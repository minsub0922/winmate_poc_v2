# 도입사례 이미지 검토 브리프

Winmate(삼성 B2B 제안서 도구)의 '유관 사례' 카드와 상세 갤러리에 쓸 실제 사진을 고르는 작업입니다.
각 사례마다 samsung.com 도입사례 원문(일부는 리포트 PDF · 영상)에서 받은 이미지를 한 장의 검토 시트(번호가 붙은 격자)로 만들어 두었습니다. 원문 페이지가 사진과 글을 한 이미지에 섞어 둔 경우가 많아, 사진 부분만 자동으로 잘라 낸 조각(role=crop)도 함께 들어 있습니다.

## 할 일

배정받은 배치 파일(`batch_N.json`)의 시트를 하나씩 Read 도구로 직접 보고, 시트마다 결과 파일을 씁니다.
배치 파일 항목: `sheet`(시트 이미지 경로) · `key`(예: case:1979) · `title`(사례 제목) · `imgs`(번호 n · id · alt(원문 대체 텍스트) · size · role).

결과 파일: `/home/claude/media/review/out/<key의 ':'를 '_'로>__<시트 파일명>.json` — 예: `case_1979__case_1979.json`

```json
{"key": "case:1979", "sheet": "case_1979.jpg", "items": {
  "1": {"k": 1, "kind": "scene", "rep": 3, "d": "쇼룸 거실 · 대화면 프로젝터와 소파"},
  "14": {"k": 0, "kind": "text", "rep": 0, "d": ""}
}}
```

시트의 **모든 번호**에 대해 항목을 하나씩 씁니다.

- `k` 1 = 쓴다, 0 = 뺀다
- `kind`
  - `scene` 설치 · 사용 현장(공간이 보이는 사진) / `people` 사람이 주인공인 장면(직원 · 고객 · 인터뷰) / `exterior` 건물 · 매장 외관 / `product` 설치된 제품이나 제품 단독 컷 / `screen` 솔루션 · 앱 화면, 사이니지 콘텐츠 화면 클로즈업 / `diagram` 구성도 · 배치도처럼 그림이 중심인 도식
  - 빼는 것: `text` 글 위주 카드 · 제목 띠 · 표 / `icon` 아이콘 · 로고 · 픽토그램 / `dup` 같은 시트에 거의 같은 사진이 이미 있음(더 크고 깨끗한 쪽을 남김) / `bad` 잘못 잘린 조각(사진이 반쯤 잘림, 대부분 빈 배경, 글이 섞여 반쯤 잘림) / `other` 이 사례와 무관(다른 사례 썸네일, 공통 배너, QR 코드, 상장 · 인증서 등)
- `rep` 대표 사진(카드 썸네일)으로 얼마나 좋은지 0~3. 3 = 이 사례를 한눈에 보여 주는 깨끗한 현장 사진(제품이 공간 안에서 쓰이는 모습, 글 오버레이 없음). 글 오버레이가 큰 목록 썸네일(role=list)은 최대 1. 사례마다 rep 3이 최소 하나는 있도록 가장 좋은 것을 고릅니다(마땅한 게 없으면 가장 나은 것에 2).
- `d` 보이는 것을 한국어로 30자 이내. 공간 · 제품 · 상황 중심, 예: "드라이브스루 주문대 옆 실외 사이니지", "관제실 비디오월 앞 상황 근무자". 사례 제목 · alt를 참고해 제품명을 쓸 수 있지만 보이지 않는 것을 지어내지 않습니다. 고객사 이름 · 사람 이름은 쓰지 않습니다. 빼는 항목은 빈 문자열.

## 기준

- 글이 조금 들어간 실제 사진(사이니지 화면 속 글, 매장 간판)은 사진으로 봅니다. 사진 위에 원문 편집 문구(큰 제목 · 설명 문단)가 크게 얹힌 것은 `text`.
- 작은 크기(200px대)라도 내용이 또렷한 사진이면 씁니다. 흐리거나 깨진 것은 `bad`.
- 제품 컷(흰 배경의 제품 사진)은 그 사례에 나온 제품이면 `product`로 씁니다.
- 영상 대표 장면(role=video) · 리포트 PDF 쪽(role=pdf · pdfpage)도 같은 기준. pdfpage는 글이 많은 쪽이면 `text`, 사진이 크게 나온 쪽이면 `scene`.
- 판단이 애매하면 쓰는 쪽(k=1)으로.

배치의 시트를 모두 끝내면 처리한 시트 수와 빠진 시트가 있는지만 짧게 보고합니다(결과 내용은 파일에 있으니 다시 적지 않음).
