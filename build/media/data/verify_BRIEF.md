# 솔루션 · 유관사례 이미지 독립 검수 브리프

Winmate(삼성 B2B 제안서 도구)에서 '솔루션'(17개)과 '유관 사례'(삼성 고객 도입사례 218건) 카드에 지금은 더미 일러스트가 보입니다.
각 항목의 연관 리소스(samsung.com 도입사례 원문 · 리포트 PDF · 영상, 솔루션 공식 페이지 · 업종 페이지)에서 모은 실제 이미지를 이미 골라 두었고,
이번 작업은 **그 결과를 처음 보는 사람으로서 다시 검수**하는 것입니다. 원문 페이지가 사진과 글을 한 장에 섞어 둔 경우가 많아 사진 부분을 자동으로 잘라 낸 조각(role=crop)이 대부분이라, 잘못 잘린 조각 · 글이 섞인 조각이 남아 있을 수 있습니다.

## 할 일

배정받은 배치 파일 `/home/claude/media/verify/batch_N.json`의 시트를 하나씩 **Read 도구로 직접 보고** 판정합니다.
배치 항목: `sheet`(시트 이미지 경로) · `key`(예: case:3080, solution:vxt) · `title` · `ctx`(사례 원문 제목 · 업종 · 제공 제품/솔루션 · 공간, 또는 솔루션 설명 · 키워드) · `imgs`[n(시트 번호) · kind · d(지금 설명) · role · size(원본 px)].
시트의 각 칸 왼쪽 위 숫자가 n입니다. **빨간 0번이 카드 썸네일(대표 사진)**입니다. 한 항목이 20장을 넘으면 시트가 _p1, _p2 …로 나뉩니다.

결과 파일: `/home/claude/media/verify/out/<시트 파일명에서 .jpg를 .json으로>` — 예: `case_3080.json`, `case_93_p2.json`

```json
{"key": "case:3080", "sheet": "case_3080.jpg",
 "v": {"1": {"v": "dup", "why": "0번과 같은 천장 LED"},
       "8": {"v": "trim", "box": [0, 0.40, 1, 1], "why": "위쪽 글 상자"}},
 "rep": null,
 "fixd": {"5": "객실 침대와 태블릿 제어 화면"}}
```

- `v`에는 **문제가 있는 번호만** 씁니다(문제없는 번호는 적지 않음 = 그대로 씀). 판정 값:
  - `wrong` 이 항목과 무관한 이미지(다른 사례 · 다른 제품군 · 공통 배너 · 다른 업종 장면이 분명할 때). ctx와 맞지 않는지 신중히 판단 — 같은 원문에서 온 매장 외관 · 사람 · 제품 컷은 관련 있음.
  - `text` 글이 주인공인 이미지(제목 · 설명 문단 · 표 · 인포그래픽 문구가 화면의 절반 가까이). 사진 속 간판 · 사이니지 화면 속 글은 문제 아님.
  - `trim` 사진은 좋은데 가장자리에 글 띠 · 다른 사진 조각 · 흰/검정 여백이 붙어 있어 잘라 내면 깨끗해지는 경우. `box`에 **남길 영역**을 원본 비율 [x0, y0, x1, y1](0~1)로 적습니다. 예: 위 40%가 글 → [0, 0.4, 1, 1].
  - `slice` 잘못 잘린 조각(사진이 반쯤 잘림, 대부분 빈 배경, 비스듬한 띠 조각 등 trim으로 못 살림).
  - `dup` 같은 항목 안에 거의 같은 이미지가 이미 있음(더 크고 깨끗한 쪽을 남기고 작은/지저분한 쪽을 dup). 같은 장면이라도 구도가 확실히 다르면 dup 아님.
  - `bad` 너무 흐리거나 깨짐 · 너무 작아 알아볼 수 없음.
  - `why` 짧게(한국어 20자 이내).
- `rep`: 0번(카드 썸네일)이 이 항목을 대표하기에 부적절하면(글 · 제품 단독 컷 · 너무 가늘고 긴 띠 · 문제 판정) 더 나은 번호를 숫자로, 괜찮으면 `null`. 좋은 대표 = 이 사례/솔루션을 한눈에 보여 주는 깨끗한 현장 · 사용 장면 · 대표 화면.
- `fixd`: 지금 설명(d)이 보이는 것과 다르거나 틀렸을 때만 고친 설명(한국어 30자 이내, 보이는 것만, 고객사 · 사람 이름 없이).

## 기준

- 판정은 보수적으로: 애매하면 문제없음(적지 않음). 단 **글이 크게 섞인 조각 · 반쯤 잘린 조각은 놓치지 말 것** — 이번 검수의 핵심입니다.
- 제품 컷(흰 배경 제품 사진)은 그 사례 · 솔루션에 나온 기기면 정상입니다.
- 리포트 PDF 쪽(role=pdfpage)은 글이 많으면 text.
- 시트를 반드시 직접 보고 판단합니다. 시트 하나도 건너뛰지 않습니다(문제가 없으면 `"v": {}`로 파일을 씁니다).

배치를 다 끝내면 처리한 시트 수, 판정별 개수, 빠진 시트가 있는지만 짧게 보고합니다.
