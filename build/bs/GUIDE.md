# Best Scenario 사진 중심 전환 — 작업 가이드 (채우기 담당용)

Winmate v2(삼성 B2B 제안서 작업대)의 Best Scenario 덱(bs01~bs20)을 **사진 중심 레이아웃으로 바꾸고, 바꾼 장의 글 · 사진을 모두 채우는** 작업입니다.
사용자 요구: “레이아웃을 사진을 사용하는 것 위주로 바꿔. 사진 요소가 있는데 사진이 없거나 표지가 없으면 다 채워. 가능한 samsung.com/business 사진으로.”

작업 폴더: `/home/claude/wm` (모든 명령은 여기서). **src/ · data/ · dist/ 파일은 고치지 마세요.** 쓰는 곳은 아래 두 곳뿐입니다.
- `build/bs/out/<bsNN>.json` — 결과(바꾼 장의 값)
- `build/bs/out/<bsNN>.notes.md` — 짧은 메모(결정 · 새로 가져온 사진 · 남은 문제)
- 새 사진을 가져오면 `build/bs/newimg/` (도구가 씀)

## 1. 받은 것
- 브리프: `build/bs/briefs/<bsNN>.md` — 시나리오 요약, 장 목록(그대로 / 바꿈 → 새 레이아웃 / 리드가 처리), 바꿀 장마다
  ① 원래 레이아웃의 칸과 **채운 값**(‘—’는 안 채움 = 원래 레이아웃의 예시 글이 그대로 보였다는 뜻) ② 새 레이아웃의 칸 목록(예시 글 · 크기 · 글자 크기 · 줄 · 한 줄 글자 수 대략 · 사진 칸).
- 장 그림(지금 모습): `build/bs/shots0/<bsNN>-<kk>.jpg` (원래 레이아웃 · 채운 값)
- 새 레이아웃 예시 그림: `build/bs/gal/<f>.jpg` (없으면 `node build/bs/gallery.mjs build/bs/gal <f>`)
- 칸 정보 다시 보기: `node build/bs/slots.mjs <f>`
- 사진 라이브러리: `build/bs/lib/catalog.md` (id · addr · 내용 · 크기 · 출처) + 미리보기 `build/bs/lib/sheets/g??-?.jpg` (사진 위 #id)

## 2. 결과 형식 — `build/bs/out/<bsNN>.json`
브리프에서 “바꿈”인 장만, 장 번호(0부터, 문자열 키)마다:
```json
{
  "3": {
    "f": "L_PH_MI_FB_B",
    "t": { "0": "02 · MARKET INTELLIGENCE", "1": "A 커피의 수익은 …", "5": { "html": "첫 줄<br/>둘째 줄" } },
    "img": { "0": { "src": "img/ph/fb-cafe-counter.jpg", "name": "카페 카운터 위 메뉴보드", "keep": true, "pos": "50% 40%" },
             "2": { "src": "img/bs/p-qm55c.png", "name": "QM55C", "keep": true, "fit": "contain" } },
    "r": [["T 은행", "A 커피"]]
  }
}
```
- `t`: 글 칸 번호 → 글(문자열) 또는 `{ "html": "…<br/>…" }`(줄바꿈 · `<b>` 정도만).
- `img`: 사진 칸 번호 → `{ src, name, keep, pos?, fit? }`. **사진 레이아웃(L_PH_* · L_C*)에서는 항상 `"keep": true`** (칸의 틀 · 배지 · 캡션은 두고 사진만 바꿈). 제품 컷은 `"fit": "contain"`.
- `r`: 편집 칸이 아닌 **고정 글**에 든 예시 고객 이름 · 자리표시를 바꿀 때 `[[원래, 바꿀]]`.
- 그대로인 장 · “리드가 처리” 장은 쓰지 않습니다.

## 3. 글 채우기 원칙
1. **새 레이아웃의 모든 글 칸을 이 시나리오 내용으로** 채웁니다. 새 레이아웃의 예시 글은 다른 예시 고객(A 커피 · T 은행 · C 빌딩 …)용이라 그대로 두면 틀립니다. 구조 글(‘01’, ‘근거’, ‘고객사 로고’, ‘CONFIDENTIAL · n’)처럼 어느 덱에나 맞는 글만 그대로 둡니다. CONFIDENTIAL · n 은 앱이 쪽 번호로 바꾸니 두면 됩니다.
2. **내용은 원래 장에서 옮깁니다.** 원래 장의 채운 값 + (안 채운 칸은) 원래 레이아웃 예시 글이 그 장의 실제 내용입니다. 숫자 · 제품 · 일정 · 이름은 그대로 옮기고, 새 레이아웃이 칸을 더 요구하면 같은 덱의 다른 장 값(브리프 · shots0 그림)에서 일관되게 가져옵니다. 덱 안에서 같은 지표는 같은 숫자.
3. 새로 숫자가 필요하면 덱의 사실과 맞게 보수적으로. 시장 · 통계는 출처를 “삼성전자 추정(2026)” 또는 “고객사 자료”로만(외부 기관 이름 금지). 제품 · 솔루션은 카탈로그 이름 그대로(브리프의 제품 · 솔루션 목록). 사례는 브리프의 유관 사례(실제 이름) 또는 이미 덱에 쓰인 사례만.
4. 고객 이름은 브리프 제목의 이름 그대로(예: “A 커피”). 다른 예시 고객 이름 · `[00]` · `[고객사]` 같은 자리표시가 화면 어디에도 남으면 안 됩니다(고정 글은 `r`).
5. 길이: 칸의 ‘줄 · 한 줄 글자’를 지킵니다. ‘한 줄 고정’ 칸은 한 줄 글자 수 안으로. 제목은 한 줄(대략 30~36자 이내). 넘침은 검사가 잡아 줍니다.
6. 문체: 기존 채운 값처럼 짧은 명사구 · ‘·’ 구분 · “~합니다/~입니다” 제목. 느낌표 · 과장 · “혁신적” 같은 말 금지. 영어는 제품 · 솔루션 이름만.

## 4. 사진 채우기 원칙
1. **모든 사진 칸이 이 장 내용에 맞는 사진**이어야 합니다. 새 레이아웃의 기본 사진이 이 시나리오 업종 · 장면에 맞으면 그대로 둬도 되지만(그 칸은 img 생략), 다른 업종 사진 · 엉뚱한 장면이면 바꿉니다.
2. **samsung.com 사진 먼저** (catalog.md 의 출처 samsung.com: img/ph · img/fill/*.json#k · 제품 컷 img/bs/p-*). Unsplash(img/bs/bsNN-*) · stock(img/cover) 사진은 맞는 samsung.com 사진이 없을 때만. 원래 장에서 쓰던 Unsplash 사진도 samsung.com 사진으로 바꿀 수 있으면 바꿉니다.
3. 라이브러리에 맞는 사진이 없으면 samsung.com 에서 새로 가져옵니다(덱당 10장 이내):
   - 후보 보기: `python3 build/bs/caseimgs.py <samsung.com 페이지> <이름표>` → 목록 + `build/bs/tmp/cand-<이름표>.jpg` (Read 로 보기)
   - 페이지 찾기: `data/catalog.json` 의 cases(도입사례 218건, url · 업종 · 제품), samsung.com/sec/business 업종 · 제품 페이지
   - 가져오기: `python3 build/bs/addphoto.py <images.samsung.com 주소> <이름> "<내용>" <출처 페이지> [--crop x0,y0,x1,y1]` → `img/bsn/<이름>.jpg` 로 씀. 이름 앞에 시나리오 번호(예: `bs13-golf-bay`).
   - 사진 속 글 · 로고가 큰 홍보 배너, 사람 얼굴이 크게 잘리는 컷은 피하고 필요하면 --crop.
4. **한 덱 안에서 같은 사진을 두 번 쓰지 않습니다**(제품 컷 · 워드마크는 예외). 검사가 ‘같은 사진’으로 알려 줍니다 — 바꾸지 않은 장(원래 값)의 사진과 겹쳐도 바꿉니다.
5. 사진 칸 크기에 맞는 비율 · 해상도(검사의 ‘해상도 부족’ 경고). 얼굴 · 제품이 잘리면 `pos` 로 맞춥니다(예: "50% 30%").
6. 표지(L_C01 · L_C02 · L_C08)는 그 덱을 대표하는 현장 사진 — samsung.com 업종 · 도입사례 사진으로.

## 5. 검사 — 끝내기 전에 반드시
```
node build/bs/check.mjs <bsNN> --shots
```
- `✗` 오류(글 넘침 · 칸 밖 · 겹침 · 빈 사진 칸 · 자리표시 · 다른 고객 이름 · 아직 안 바꿈)는 **0개**가 될 때까지 고칩니다. 원래 값 장(바꾸지 않는 장)의 오류는 무시해도 됩니다.
- `·` 확인 항목(예시 글 그대로 · 해상도)은 하나씩 보고 맞으면 둡니다. `↻ 같은 사진`은 고칩니다.
- 그다음 `build/bs/check/<bsNN>-sheet-*.jpg` 를 Read 로 **눈으로 확인**: 사진이 장 내용과 맞는지, 글이 사진 위에서 읽히는지, 잘림 · 어색한 줄바꿈 · 빈 곳이 없는지. 한 장만 다시 볼 때 `--only 3,7`.
- 큰 그림이 필요하면 `build/bs/check/<bsNN>/<kk>.jpg` (1280×720).

## 6. 끝나면
- `build/bs/out/<bsNN>.notes.md`: 바꾼 장 수, 새로 가져온 사진(이름 · 출처 페이지), 원래 계획과 다르게 한 것, 남은 문제.
- 마지막 응답: 시나리오별 오류 0 확인 결과와 메모 요약(짧게).
