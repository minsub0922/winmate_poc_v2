# 삼성 DB 전체 갱신

목표는 원본 자료부터 화면·검색·추천이 쓰는 데이터까지 같은 시점의 검증된 내용으로 갱신하는 것이다. 크롤러 실행 성공만으로 완료하지 않는다.

먼저 [공통 데이터 계약](../../references/winmate-contracts.md)을 읽고, [수집·삭제·반영 절차](references/refresh-workflow.md)에 따라 작업한다. 경로는 저장소 루트 기준이다.

## 1. 전체 대상을 먼저 확정한다

- 현재 삼성 공식 탐색 메뉴·분류·목록 페이지와 카탈로그 목록을 직접 조회한다. 기존 `site_lists.txt`, `EXTRA`, `catalogs.json`은 출발점이며 최신 전체 목록의 증거가 아니다.
- 제품군, SKU, 필터, 사양, PDP 특장점·면책, 이미지, 카탈로그 권·쪽·추출 제품, 솔루션, 업종 페이지, 고객 도입사례(PDF·영상 포함), 연결 이미지 라이브러리의 갱신 대상을 빠짐없이 목록화한다.
- 기존 소스와 새로 발견한 소스의 합집합을 `source-inventory.json`으로 남긴다. 각 대상에 기존/현재 URL·ID, 수집 방식, 기존/현재 개수, 수집 시각, 캐시 유효성, 성공/불완전/이동/폐지/범위 제외 및 근거를 기록한다.
- 대상 목록을 만든 뒤 항목별로 진행한다. 사용자가 범위를 정하지 않았다면 위 전체 범위를 기본으로 삼는다. 자료 부족으로 일부가 보류되면 전체 최신화 완료라고 보고하지 않는다.

## 2. 원본을 보존하고 새 스냅샷을 수집한다

- 기존 DB·원본·사진 주소표·앱 JSON·출처 대장의 해시와 사본을 확보한다. staging 디렉터리에서 수집·빌드하고 활성 DB에 바로 쓰지 않는다.
- 페이지네이션, 목록 총수, 옵션 수, 카탈로그 전체 쪽, 오류 기록을 대조한다. 빈 응답·차단·타임아웃·파서 실패는 삭제 근거가 아니다.
- 기존 캐시가 있으면 생략하는 스크립트를 점검한다. 변경된 카탈로그·사진·페이지는 원본 해시/재검증 시각으로 새 수집을 입증한다.
- 사실과 검색용 색인을 구분한다. 사양·성능·모델·효과 수치를 추측으로 보완하지 않는다. 새 이미지의 정확한 제품 대응과 출처를 확인한다.

## 3. 모든 변경과 삭제 영향을 대조한다

- 기존/신규 엔터티를 안정 ID로 비교해 추가·내용 변경·URL 이동·병합·추천 제외·물리 삭제 후보·미확인으로 나눈다. 수정일만 다른 행은 내용 변경과 구분한다.
- 삭제 후보 전부에 공식 근거와 하위 행·이미지·레이아웃·시나리오·페르소나·저장 문서 참조 영향을 붙인다. 사이트 목록에서 빠졌어도 다른 공식 소스에 남는지 확인한다.
- `change-plan.json` 및 사람이 읽을 수 있는 삭제 영향표를 만든다. 이미 승인된 갱신 범위 안의 근거 있는 변경은 진행하되, 참조를 잃는 물리 삭제나 아직 승인되지 않은 파괴적 변경은 이 구체적인 표를 제시한 뒤 필요한 결정만 받는다. 재확인만을 위한 별도 승인 단계를 만들지 않는다.
- 과거 자료·판매 종료·사이트 이동을 구분한다. 현행 추천에서 제외하는 것과 과거 문서를 그릴 데이터를 없애는 것은 다르다. 보존/alias/마이그레이션이 구현되지 않았는데 있다고 가정하지 않는다.

## 4. 같은 릴리스로 반영하고 검증한다

- 원본 DB → 앱 목록·상세·사진·이미지 검색 → `app/data` → runtime SQLite → Agent KB를 함께 반영한다. 상세 절차의 스크립트별 입출력을 확인한다.
- 기존 ID·묶음 주소를 유지하거나 모든 소비자를 이관한다. 사라진 이미지 슬롯을 다른 제품 사진으로 재사용하지 않는다.
- 건수 변화는 변경 계획과 일치해야 한다. 고정 기대 건수는 근거 있는 새 계약으로 함께 갱신하며 검사를 우회하지 않는다.
- DB integrity/FK·의미 참조, 모든 pack 주소, UI/API/KB의 동일 제품, 검색·추천·제품 상세·이미지 삽입·기존 제안서 렌더를 검사한다. 실패 시 활성 상태를 보존/복구한다.

## 완료 결과

수집 기준 시각, 대상별 완전성, 추가/변경/이동/병합/제외/삭제/보류 건수, 삭제 영향 처리, 실제 반영 파일, 실행한 검사와 남은 미확인을 보고한다. 인벤토리·원본 해시·변경표·검증 결과·복구 경로를 작업 산출물로 남긴다.
