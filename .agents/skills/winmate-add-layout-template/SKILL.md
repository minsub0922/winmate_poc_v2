# Winmate PPT 레이아웃 추가

[공통 데이터 계약](../../references/winmate-contracts.md)과 [제작·통합 계약](references/layout-contract.md)을 먼저 읽는다. 결과는 편집 가능한 라이브러리 템플릿이며, 이미지 한 장이나 독립 PPTX만 만들어 끝내지 않는다.

## 요구사항과 디자인 기준

1. 장의 목적, 대상 업종·청중, PARTS 유형, 전달할 메시지, 제품/솔루션 수, 글·사진·표·KPI의 양, 필수 정보, 원본 PPT/PDF 유무를 정리한다. 미지정된 세부 디자인은 기존 장표에서 합리적으로 결정한다.
2. 현재 활성 레이아웃에서 내용과 밀도가 가까운 3~5개를 찾고 메타와 실제 HTML을 함께 읽어 1280×720로 렌더한다. 폰트·색·마진·제목·본문·꼬리말·사진 처리·정보 계층을 비교해 기준을 기록한다.
3. 원본 명세 재현이면 해당 표준 덱의 규칙을 우선한다. 일반 추가면 가장 가까운 Winmate 계열을 따른다. UI 토큰을 장표의 인라인 디자인과 혼동하지 않는다. 기존 구조가 요구를 충족하면 재사용/변형하고 차이가 필요한 부분만 새로 만든다.

## 제작

- 충돌 없는 새 `f`를 부여한다. 기존 `f`·칸 번호의 의미를 바꾸지 않는다. 변경된 구조를 기존 템플릿에 덮어써 저장 제안서의 overrides를 깨뜨리지 않는다.
- 편집 글은 `data-tb`, 교체 그림은 `data-img`와 기존 이미지 메타를 사용한다. 칸 번호는 각각 중복 없이 안정적으로 유지한다.
- 제품 컷은 흰 배경과 `contain`, 장면은 용도에 맞는 crop을 쓴다. 모든 사진의 모델·업종·장면·해상도·출처를 확인한다. AI 이미지는 실제 삼성 제품 사진·실제 도입사례로 표시하지 않는다.
- 예시는 재사용 가능한 입력 길이를 보여 주도록 작성한다. 가상 수치·고객은 예시임을 표시하며 공식 사실처럼 출처를 붙이지 않는다.
- HTML과 함께 메타를 만든다. 제목뿐 아니라 `when`, `p/p2`, `req`, `prods/sols`, `ik/ih`, `nT/nI`, `ph/phs`, `txt`, `pv/pf`가 실제 칸·내용과 맞아야 검색·추천·AI 채우기가 작동한다.

## 통합

- 앱의 정본 모듈/`app/data`에 추가한다. 과거 `build/photo`·`build/v25` 스크립트는 디자인·생성 로직의 근거로 읽되 출력 경로를 확인하지 않고 실행하지 않는다.
- `ALL_LAYOUTS`, `LAYOUTS`, `L`, `layoutHtml()`에 의도대로 들어가고 라이브러리·필터·검색·추천에서 접근 가능한지 확인한다. 추가만 할 때 기존 템플릿을 retired 처리하지 않는다.
- 새 사진/pack을 앱이 실제 제공하는 위치에 넣는다. `reference/live` 심볼릭 링크를 통해 보존 자료에 쓰지 않는다.
- 프런트 빌드와 Agent KB를 갱신하고 의도된 건수 변화에 맞게 기대값·계약 테스트를 갱신한다.

## 검증과 전달

1280×720 원본 크기와 앱 축소 보기에서 렌더해 모든 글·그림·장식을 확인한다. 긴 한국어 입력으로 넘침·겹침·잘림을 고치고, 이미지 로드 완료 뒤 확인한다. 실제 `applyOverrides`로 글 수정·사진 교체·`keep`를 확인하고, 편집 가능한 PPTX로 내보내 재가져오기까지 검사한다.

최종 결과에 새 `f`, 쓰임새·필수 입력, 따르는 디자인 견본, 통합 파일, 미리보기와 검사 결과를 포함한다. 사용할 수 없는 원본/이미지나 미검증 내보내기가 있으면 명시한다.
