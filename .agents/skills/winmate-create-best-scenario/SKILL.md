# Best Scenario 생성

[공통 데이터 계약](../../references/winmate-contracts.md)과 [시나리오 생성 계약](references/scenario-contract.md)을 먼저 읽는다. 결과는 목록용 소개 글뿐 아니라 실제 채워진 덱·Storyboard·활용 가능한 제안서다.

## 1. 표준 여부부터 판별한다

| 모드 | 생성 기준 |
|---|---|
| 표준제안서 | 사용자가 지정한 공식 양식·PPT/PDF·명세의 장 순서, 문구, 구조, 제품/공간, 주석·면책을 보존한다. `req: 'std'`, `std: true`를 함께 설정한다. |
| 일반 Best Scenario | 고객의 상황·의사결정 기준·시간·결정 요청을 기준으로 요구 유형과 전략을 고르고, 기존 활성 레이아웃을 조합한다. `std`를 붙이지 않는다. |

표준 원본에서 고객 입력칸만 채운 것은 표준 모드다. 원본의 장 구성·순서·공식 문구를 바꾼 맞춤본은 기본적으로 일반 모드로 분류하고 기준 덱과 변경 대응표를 기록한다. 사용자가 새 표준 판본으로 지정한 경우 그 지정과 원본을 근거로 표준 등록한다. 두 모드 모두 유효한 `strategy/ending`, `audience:{lead,others:[]}`, `criteria` 등 런타임 필수 필드를 생략하지 않는다.

표준을 요청했는데 원본이 없으면 현재 등록된 특정 표준 덱을 명시적으로 기준으로 삼을 수 있는지 확인한다. 기존 양식을 확인할 수 없으면 맞춤 구성안을 만들되 공식 표준 원본을 재현했다고 표시하지 않는다. 원본이 필요한 의존 작업만 보류하고 독립적인 요구 정리는 진행한다.

## 2. 내용과 덱을 설계한다

- 고객 상황·발언, 청중, 평가 기준, 핵심 주장, 논리, 차별점, 단계별 목표, 최종 `ask`, 다음 행동, 준비 자료, 제품·솔루션·사례, KPI와 반론 대응을 같은 사실표에서 작성한다.
- 일반 모드는 `REQ_TYPES`, `STRATEGIES`, `ENDINGS`, `STAGES`와 `PARTS`의 실제 키를 사용한다. 장수는 시간과 내용에 맞추고 표지·본문·결정 요청의 연결을 확인한다.
- 표준 모드는 원본 쪽 ↔ 레이아웃 ↔ 칸 번호 대응표를 만든다. 과거에 이미 등록된 사진 대체본도 확인한다. 임의 요약·순서 변경·주석 삭제로 표준을 바꾸지 않는다. 고객 맞춤 범위와 원본 유지 범위를 구분해 기록한다.
- 맞는 레이아웃이 없으면 [레이아웃 추가 스킬](../winmate-add-layout-template/SKILL.md)을 읽어 그 계약으로 추가한다. 슬롯 구조가 다른 템플릿으로 `f`만 바꾸지 않는다.

## 3. 연결된 데이터를 함께 만든다

- `scenarios.js`: 고유 id와 전체 시나리오 정의·flow.
- `scenario_fills.js`: 고객명과 평탄화한 flow 순서 그대로 장별 `{f,t,img,r?}`.
- `scenario_story.js`: 청중별 요구·가중치·메모와 flow 단계 이름에 대응하는 PARTS 유형·내용.
- 이미지·출처·필요한 배경 테마: 실제 앱에 제공되는 경로와 전체 장 수·배경 map.
- `scenario_storyboard.js`의 변환을 그대로 사용한다. 표지는 숨은 deck part에 두고 본문 버블과 분리한다. 본문 파트의 기존 2장 이상 구성 관례를 우선하되, 짧은 제안 요구에 맞는 예외는 이유를 남긴다.

## 4. 채움과 검증

- 전 장의 의미 있는 텍스트/이미지를 확인해 다른 고객 이름·자리표시·부적합한 기본 사진을 제거한다. 표준 양식의 구조 문구·면책은 유지한다.
- 사진 칸은 원칙적으로 `keep: true`, 제품 컷은 흰 배경·`contain`을 사용한다. 실제 모델 대응·출처·자르기·해상도를 확인하고 같은 장면의 불필요한 반복을 줄인다.
- 가상 고객의 수치·목표는 가정으로 표시한다. 과거 가이드의 '삼성전자 추정' 문구를 근거 없는 숫자의 출처로 사용하지 않는다. 덱 전체의 고객·제품·수량·KPI·일정·합계를 대조한다.
- 모든 `FILLS[id][k].f`와 해당 장의 `flow`를 대조한다. 불일치는 `fillOf`가 조용히 빈 값으로 만들므로 오류로 취급한다.
- 전체 덱을 렌더해 넘침·잘림·오류 사진을 고친다. 목록/필터·상세 Storyboard·전체 보기·활용하기 복사·수정·재열기·PPTX 내보내기/복원을 검증한다. 표준은 원본 장별 비교도 수행한다.
- 현재 앱·Agent KB에 함께 반영하고 시뮬레이션 preset이 해석하는 청중·criteria·objections·ask·refs까지 확인한다. 기존 관리자 샘플·저장 제안서는 덮어쓰지 않는다.

## 완료 결과

시나리오 ID·표준/일반 모드·기준 원본, 고객/요구 유형/전략/결말, 장 수와 단계 흐름, 추가 템플릿, 이미지 출처·가정, 실제 통합 파일, 전체 덱 미리보기와 검증 결과를 전달한다.
