# Winmate 공간 조감도 품질 개선

목표는 실제 앱의 안정된 첫 화면과 근거를 추적할 수 있는 제품·가구 형상이다. 외곽 치수 검사만으로 사진과 같은 형상이라고 결론 내리지 않는다. [구현·검증 계약](references/fidelity-contract.md)은 해당 작업의 코드와 명령을 찾을 때 읽는다.

## 화면을 먼저 관찰한다

- 첫 진입·새로고침에서 API를 지연시켜 로딩 중 화면과 완료 화면을 확인한다. 헤더의 x/y/width/height를 여러 프레임에서 측정하고, 데스크톱과 좁은 모바일에서 비교한다. 완료 후 스크린샷 한 장으로 blink가 해결됐다고 판단하지 않는다.
- 헤더를 라이브러리 로딩 여부와 무관한 동일한 DOM 위치에 유지한다. 로딩·오류 UI는 헤더 아래에 두고 준비되지 않은 동작만 비활성화한다. 스크롤바 출현에 의한 가로 이동도 확인한다.
- 느린 히스토리 요청이 제품 라이브러리 표시를 불필요하게 막지 않게 한다. 기존 스튜디오·저장·프롬프트·레이아웃 편집 작업은 보존한다.

## 제품 정체성과 근거를 맞춘다

- 현재 카탈로그와 상세 스펙, 제품 ID에 연결된 원본 이미지·갤러리의 정면/후면/상단 라벨을 함께 읽는다. 전체 자산을 대상으로 누락·잘못된 분류·범용 레시피 공유를 집계한다.
- 제품 분류에 내부 ID를 사용하지 않는다. `ec_360_*`의 `360`은 카탈로그 번호다. 이름·모델을 우선하고 제품군은 보조 근거로 쓴다. `벽걸이 브라켓`이 붙은 사이니지를 에어컨으로, `식기세척기`를 세척 서비스로, `NVMe SSD`가 포함된 노트북을 부품으로 분류하지 않는다.
- W/H/D를 미터 단위 x/y/z로 정규화한다. 섹션과 행 제목을 함께 읽어 W/D/H, H/W/D, 세로/가로/두께도 구분한다. 포장·타공·VESA·화면 크기를 본체 치수로 쓰지 않는다.
- 모니터 스탠드 포함/제외, 키오스크 패널/연결박스/조립체/옵션 플로어 스탠드, 이어버드 한 개/케이스처럼 치수의 대상 구성을 확인한다. 대체 규격은 원문과 선택한 구성을 보존한다. 축 순서가 없는 수치는 임의로 확정하지 않는다.
- 치수를 다른 항목에서 가져올 때는 정규화한 동일 모델 코드와 실제 측정 행이 일치해야 한다. 유사 이름이나 제품군만으로 정확한 치수를 부여하지 않는다. 새로 확인한 제조사 자료는 출처·날짜·원문·구성을 공간 자산의 근거로 남긴다.
- 자료가 없는 모델은 추정 치수·참고 이미지 없음·대표 구성이라는 상태를 유지한다. 규칙 분류와 이미지 연결만으로 제조사 CAD 또는 모델별 완전 일치라고 표시하지 않는다. 공용 가구는 제조사 제품과 구분된 설계 자산이다.

## 같은 형상을 모든 결과에 적용한다

- 1Way/2Way/4Way/360, 덕트/스탠드/실외기, 도어 수, 곡면 모니터, 버너 수, 로봇/스틱 청소기 등 눈에 보이는 구조 차이는 별도 레시피로 표현한다. 제품군 하나를 같은 상자로 축소하지 않는다.
- 정규화한 부품을 먼저 회전한 뒤 실제 x/y/z 치수를 적용한다. 실치수로 늘린 원통을 나중에 회전하면 팬이 긴 드럼처럼 돌출된다. 구·원통은 가로와 깊이가 다른 타원 스케일을 보존한다.
- 메시의 최종 외곽이 자산 치수와 맞고 바닥이 설치 높이에 놓이는지 검사한다. 문·손잡이·락커 문처럼 같은 평면에 겹친 표면의 z-fighting도 실제 렌더로 찾는다.
- 이미지의 촬영 방향과 종횡비를 확인해 맞는 면에만 텍스처를 쓴다. 인덕션 탑뷰를 수직 전면에 붙이지 않는다. 화면 콘텐츠의 주색을 제품 베젤 색상으로 오인하지 않으며 스펙의 색상을 우선한다.
- 제품별 썸네일 키는 레시피뿐 아니라 치수·색상·이미지·형상 변환을 포함한다. 실제 편집 렌더러로 생성하고 작은 제품도 프레임을 채우게 한다. 새 이미지가 준비된 뒤 PNG·GLB를 캡처한다.
- 2D는 같은 부품 회전·치수 변환을 투영한다. 원형 가구에 사각 외곽 채움을 덧씌우지 않는다. 배치·충돌·선택·내보내기 치수가 서로 달라지지 않게 한다.
- 기존 자산 ID와 저장된 `assetRevision`을 보존한다. 새 라이브러리는 새 해시로 저장하고 예전 버전 파일을 덮어쓰지 않는다. 옛 장면에는 당시 렌더링 규칙을 적용한다.

## 검토하고 마무리한다

실제 이미지와 생성된 오브젝트를 나란히 둔 전체 검토표를 만들고, 서로 다른 레시피와 가구도 별도로 렌더해 본다. 잘못된 축·하위 형상·설치 구성·표면을 수정한 뒤 필요한 미리보기를 다시 생성한다. 수학적 외곽 검사, 전체 기본 장면의 배치 검사, 지연 로딩 UI, PNG·GLB 검사를 변경 범위에 맞게 실행한다.

시험 계정·히스토리는 별도 DB와 포트를 사용한다. 실행 중인 다른 작업의 서버·계정·수정 파일을 덮어쓰지 않는다. 같은 워크스페이스에서 자산 수가 달라졌다면 현재 전체 라이브러리로 검토를 다시 맞춘다.

최종 전달에는 수정 결과, 검증 결과, 검토표와 스킬 경로, 남은 근거 부족을 구분해서 적는다. 확인하지 못한 제품까지 정확히 재현했다고 단정하지 않는다.

읽기 전용 검토 요청이면 생성기·계정·서버를 실행하지 않는다. 먼저 검사 코드의 쓰기 동작을 읽고 쓰기 없는 계산·검사만 실행하며, 기존 UI 근거와 직접 재현한 결과를 구분한다. 보고서는 요청된 임시 경로에만 쓴다.

검토 시작·종료의 `sourceHash`, 주요 코드 SHA-256과 실행 시각을 기록한다. 자산 수가 같아도 해시가 달라지면 관련 검토를 다시 맞춘다. 합격은 외곽, 하위 부품 비율, 제품/이미지 모델, 열림/닫힘 상태, 설치 구성, 관측 방향, 재질, 실제 캡처 각각의 범위로 구분한다. 패널과 스탠드 포함 조립체를 비교하거나 열린 사진과 닫힌 본체를 비교한 채 사진 일치로 승인하지 않는다.

이미지·재질·투영 규칙을 바꿨다면 렌더링 버전과 썸네일 키도 갱신한다. 선택·편집 후의 모든 캡처 진입점도 해당 장면 세대의 이미지 준비를 기다려야 한다. 규칙 분류 회귀에는 `엑스커버`를 커버 액세서리로, `히트펌프`를 드레인 펌프로, 팔레트 치수를 소모품 본체 치수로 오인하지 않는 사례도 포함한다.

화면 제품은 전체 외곽 외에도 실측 패널·베젤·곡률을 맞춘다. 사이니지 55형 항목에 75형 사양을 연결하거나, M8에 M7 사진을 빌리거나, 스탠드 포함 높이를 패널 높이로 쓰지 않는다. 제조사 사진의 흰 여백·거치대·설치 공간을 화면으로 늘리지 않는다. 필요하면 제품 실루엣의 패널 사각형을 찾아 정면 보정하고, 근거와 네 꼭짓점을 보관해 실제 패널 면에 적용한다. 설치 사진은 검토한 화면 영역만 잘라 쓰며 원본 전체를 제품 표면으로 매핑하지 않는다. 확인된 사진이 없으면 물리 제품에 가짜 SAMSUNG 화면을 만들어 넣지 않는다.

이미지 검증에는 정면 렌더와 적용한 원본 사진의 같은 위치를 비교하는 검사를 포함한다. LED 격자처럼 촘촘한 텍스처는 동일 투영 크기로 맞추고 작은 영역 평균으로 비교해 안티앨리어싱 차이와 잘못된 이미지를 구분한다. 수치 검사는 원본·변경 전·변경 후의 실제 렌더 검토와 함께 판단한다. 치수 표시는 소수 mm를 반올림해 다른 값으로 보이지 않게 한다.

오브젝트 목록의 스크롤 페이지 처리는 실제 스크롤 컨테이너를 observer root로 사용한다. 검색·분류를 바꾸면 첫 페이지와 스크롤 위치를 함께 초기화하고, 추가 페이지·필터 변경 중 선택한 항목은 유지한다. 버튼을 없앴다는 사실만으로 완료하지 말고 데스크톱·모바일에서 다음 페이지와 마지막 페이지까지 검사한다.

구형 장면의 라이브러리와 최신 목록이 섞이지 않게 한다. 최신 제품 목록을 보여 주되 과거 배치의 치수를 바꿀 때는 새 자산 버전으로 검증하고 실행 취소도 원래 라이브러리를 복원해야 한다. 같은 크기의 가구·제품 좌표는 움직이지 않는다. 새 실측 크기가 충돌하면 조용히 저장하지 말고 배치 조정이 필요함을 표시한다.

제품 상세 JSON을 수정했다면 UI용 SQLite와 Agent KB까지 같은 모델 사양으로 갱신한다. `prepare_data.py`의 입력 지문이 바뀌었는지 확인하며, DB 파일이 존재한다는 이유로 옛 75형 데이터를 계속 쓰지 않게 한다. 원본 SQLite는 수정하지 않고 앱의 검토 데이터와 투영 DB·검토 원장·KB를 일치시킨다.

패널 모서리 반경은 화면 폭의 비율로 늘리지 않고 물리 단위로 정의한다. 기본 베젤이나 곡률을 추정한 항목은 `displaySpec`의 근거 수준을 남기며 확인 치수와 섞지 않는다. 사진 대조 통과는 해당 사진이 올바르게 적용됐다는 증거다. 별도로 모델 코드·세대·사이즈 일치를 확인해야 한다. 목록 카드의 포인터 선택 시 focus 미리보기가 클릭을 가로채지 않게 하고, 키보드 미리보기는 `:focus-visible`로 유지한다.
