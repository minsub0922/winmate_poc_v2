# 09 — 고객 요구사항 히스토리 버튼과 Hover 상세

확인일: 2026-10-20 KST.

## 변경

- 고객 요구사항에 공통 HistoryReuse 진입점을 연결했다. 제품·솔루션 매칭과 같은 전폭·최소 60px 높이·두 줄 안내 버튼을 사용한다.
- 요구사항의 선택 미리보기를 기본 정보, 자유형식 원문, 키맨별 요구와 비중, 제작자 의견, 첨부파일 이름·크기·메모로 구분했다. 긴 원문을 자르지 않고 스크롤로 읽는다. @태그는 읽기 가능한 카탈로그 이름으로 표시한다.
- 히스토리 항목에 마우스를 약 200ms 올리면 독립적인 상세 카드가 열린다. 카드 안으로 포인터를 옮기고 긴 내용을 스크롤할 수 있다. 요구사항과 제품·솔루션 매칭 팝업에 같은 Hover 동작을 적용했다.
- Hover는 선택 상태나 저장소를 바꾸지 않는다. 클릭한 내역만 실제 불러오기 대상이 된다. 다른 항목의 Hover 상세를 읽어도 기존 선택과 불러올 대상은 유지된다.
- Esc는 Hover 상세부터 닫는다. 목록 스크롤·검색 변경·화면 크기 변경·팝업 닫기 때 오래된 상세를 정리한다. 키보드 포커스로도 상세를 확인할 수 있고, 상세 닫기 후 포커스 복귀로 카드가 다시 열리지 않게 했다.
- 터치 기기는 기존 클릭 선택과 본문 미리보기를 사용한다. Hover가 필수 조작이 되지 않게 했다.

기존 불러오기 동작은 유지했다. 요구사항·제작자 의견·첨부 메타데이터를 복사하고 키맨과 첨부 ID를 새로 만들며, 원본 히스토리는 보존한다. 모델 호출과 RFP 추출 로직은 수정하지 않았다.

## 검증

| 환경 | 요구사항 | Hover | 결과 |
|---|---:|---:|---|
| 고정한 소스의 검증용 웹 빌드 | 12/12 | 15/15 | 27/27 통과 |
| 실제 Cloudflare 주소의 주요 흐름 | 4/4 | 6/6 | 10/10 통과 |

요구사항 버튼 높이 일치, 모든 정보 구역, 키맨과 가중치, @태그, 파일 메타데이터, 긴 원문, 선택·취소 시 무변경, 정확한 복사와 ID 재생성, 빈 상태, 900/390px, Hover 열기·항목 전환·선택 보존·카드 내부 이동과 스크롤·마우스 이탈·클릭·Esc·키보드 닫기·검색·목록 스크롤·키보드 포커스·터치·제품 이미지 회귀·화면 크기 변경을 검사했다. 총 37개 검사가 통과했다.

검사마다 격리 브라우저와 합성 제안서를 사용했다. 모델과 서버 공유 저장 요청은 이 UI 검사에서 차단했다. 실제 관리자 Chrome에서는 상세 미리보기만 열고 다른 히스토리를 불러오지는 않았다. 콘솔 오류는 없었다.

## 배포·실행

검증한 웹 assets를 먼저 배치하고 index를 원자적으로 교체했다. 기존 assets는 유지했고 API와 Cloudflare 터널은 재시작하지 않았다. 다른 기능의 작업 중 수정은 되돌리지 않으며 이번 커밋에서는 제외한다. 원본 `src/`, `dist/`, `poc/`, `proddb/`도 수정하지 않았다.

```sh
WINMATE_REQ_HISTORY_WEB=http://127.0.0.1:5194 WINMATE_TEST_PASSWORD='현재 비밀번호' node app/tests/requirements-history.mjs
WINMATE_REQ_HISTORY_WEB=https://배포주소 WINMATE_REQ_HISTORY_SUITE=smoke WINMATE_TEST_PASSWORD='현재 비밀번호' node app/tests/requirements-history.mjs
```

첫 명령은 실행 중인 검증용 웹 빌드에 전체 검사를 수행한다. 두 번째는 외부 주소의 주요 흐름을 확인한다. 검사 후 임시 preview 서버만 종료하며 앱과 외부 접속은 유지한다.
