# 07 — Storyboard 레이아웃 선택 해제

확인일: 2026-10-20 KST.

## 변경

- 상세 팝업의 `선택 해제`는 대상 이름과 삭제 범위를 보여 주는 확인 팝업을 연다. 확인한 뒤에만 해제하고 상세 팝업을 닫는다.
- Storyboard 레이아웃 카드에 마우스를 올리면 오른쪽 위 X가 나타난다. X는 같은 확인 팝업을 열며 상세 팝업을 동시에 열거나 카드를 드래그하지 않는다.
- 키보드 포커스와 터치 기기에서도 X에 접근할 수 있다. 찜 버튼은 X 왼쪽에 배치해 겹치지 않게 했다.
- 취소·Esc·닫기·배경 클릭은 기록을 바꾸지 않는다. 초기 포커스는 취소에 두고 Tab은 확인 팝업 안에서 순환한다. 확인 중 화살표 키가 아래 상세 장표를 넘기지 않게 했다.
- 공통 저장소 함수가 선택한 UID 한 건만 제거한다. 같은 템플릿의 다른 복사본과 파트 내용은 유지한다. 기존 키·저장 형식을 그대로 쓴다.
- 보기 전용 Best Scenario에는 X를 제공하지 않는다. AI·렌더링·PPTX 변환 코드는 이번 변경에 포함하지 않았다.

## 검증

| 범위 | 상세 팝업 | Storyboard 카드 | 결과 |
|---|---:|---:|---|
| 이번 커밋 대상 소스의 격리 사본 | 12 | 12 | 24/24 통과 |
| 실제 Cloudflare 배포 주소 | 12 | 12 | 24/24 통과, 재검 포함 |

확인 전 무변경, 취소·Esc·닫기·배경 취소, 특정 복사본만 삭제, 마지막 장표 제거 후 파트 보존, 새로고침 후 저장 유지, 안전한 초기 포커스, Tab 순환, 아래 장표의 키보드 탐색 차단, X 표시·위치·찜과의 간격, 일반 카드 열기, 터치 조작, 보기 전용을 검사했다. 1500px 기본 화면, 900px 취소 동작, 390px 터치 화면을 포함한다.

초기 테스트 하네스의 외부 호스트 차단과 React 테스트 마운트 방식을 수정했다. 포커스 검사도 팝업의 초기 취소 포커스가 잡힌 뒤 진행하도록 명시했다. 작업 폴더의 병행 공유 기능 수정이 임시 미완료 import를 만들었으므로 Git index에서 이번 변경만 포함한 소스 사본과 필요한 정적 데이터를 추출해 최종 소스 검사를 실행했다. 병행 변경은 되돌리지 않았다.

외부 검사 중 한 차례 앱 파일 로드 실패로 검사 화면에 진입하지 못했다. 같은 시간대에 배포 정적 파일 이름이 다른 빌드로 교체되고 있었다. 재실행에서는 정상 진입하고 해당 동작이 통과했다. 실패한 시도의 내용과 재검 결과는 최종 JSON의 `previous_attempt`에 보존했다. 최초 일괄 실행만으로 모두 통과했다고 취급하지 않는다.

실제 사용자 Chrome에서는 확인 팝업을 열고 취소해 18장인 샘플 제안서를 그대로 유지했다. 삭제 검사는 격리 브라우저의 합성 제안서에서만 실행했다. 모델 호출은 테스트에서 차단했으며 Gemini 호출 변경은 없다.

## 배포와 남은 사항

기존 앱·Cloudflare 터널을 유지하고 웹 빌드에 반영했다. 열린 앱은 새로고침하면 변경을 받는다. 이 기능의 남은 차이나 결정 사항은 없다.

작업 중 별도로 추가된 공유 기능은 현재 외부 화면에서 `연결 확인 필요 · Not Found`를 표시한다. 이는 별도 변경의 프런트/실행 중 API가 아직 연결되지 않은 상태이며 이번 커밋에는 공유 코드나 서버 재시작을 포함하지 않았다. 이번 선택 해제 동작은 해당 안내가 있는 현재 외부 화면에서도 검증했다. 원본 `src/`, `dist/`, `poc/`, `proddb/`는 수정하지 않았다.

검사 실행:

```sh
# 로그인한 로컬 API를 사용해 소스 검사 (Vite 테스트 서버는 자동 실행·종료)
WINMATE_TEST_PASSWORD='현재 비밀번호' node app/tests/layout-removal.mjs
# 실행 중인 빌드본/외부 배포 주소 검사
WINMATE_REMOVE_WEB='https://배포주소' WINMATE_TEST_PASSWORD='현재 비밀번호' node app/tests/layout-removal.mjs
```

개별 재검은 `WINMATE_REMOVE_FILTER`에 검사 이름의 일부를 지정한다. 검사마다 사용자 브라우저와 분리한 저장소를 사용한다. 진행 중인 다른 소스 편집이 있으면 확정한 사본에서 실행한다.
