# 08 — 제품·솔루션 매칭 히스토리 미리보기

확인일: 2026-10-20 KST.

## 반영

- `이전 히스토리에서 불러오기`를 최소 60px 높이의 전폭 버튼으로 키우고 설명을 두 줄로 배치했다.
- 팝업은 넓은 작업 영역으로 만들었다. 왼쪽 히스토리 목록과 오른쪽 미리보기는 각각 스크롤하며, 검색과 하단 불러오기 버튼은 계속 접근할 수 있다.
- 특정 히스토리를 고르면 제품·솔루션·유관사례를 항목별 이미지 카드로 표시한다. 기본 이미지 영역은 200×176px이며, 이미지는 잘리지 않게 contain으로 표시한다.
- 제품: 이름, 모델, 분류, 사양, 적용 공간, 업종. 솔루션: 이름, 분류, 전체 설명, 함께 쓰는 제품, 업종. 사례: 고객명, 내용, 업종, 고객 유형, 날짜, 공간, 도입 제품, 제공 구성, 고객 요구·성과와 원문 링크를 데이터에 있는 범위에서 표시한다. 줄 수나 항목 수로 생략하지 않는다.
- 사진은 기존 Thumb과 제품/미디어 묶음 로더를 사용한다. 800px 이하에서는 카드를 세로로 쌓고, 긴 메타데이터도 줄바꿈한다. DB에 없는 참조 ID는 사라지지 않고 정보 없음 상태와 ID를 보여 준다.
- 미리보기 선택·스크롤·취소는 제안서를 변경하지 않는다. 실제 불러오기는 기존 context 복사 방식을 유지한다.

기존 히스토리 재사용 컴포넌트는 작업 폴더에 존재했으나 아직 Git에서 추적되지 않았다. 이번 구현은 해당 컴포넌트와 제품·솔루션 매칭의 진입점, 새 미리보기·스타일을 함께 버전 관리한다. 별도로 진행 중인 공유·DB·검토·슬라이드 수정은 포함하지 않는다.

## 검증

| 환경 | 결과 |
|---|---|
| 변경 시점 소스를 고정한 검증용 웹 빌드 | 16/16 통과 |
| 실제 Cloudflare 배포 주소 | 16/16 통과, 900px 1건 재검 포함 |
| 사용자 Chrome | 실제 히스토리 선택, 메타데이터 표시, 대표 이미지 4개 정상 로드 확인 |
| Vite 빌드 및 테스트 스크립트 구문 | 통과 |

버튼 높이, 선택 전 불러오기 비활성화, 세 종류의 메타데이터, 제품·솔루션·사례 이미지 로드와 크기, 취소 시 무변경, 정확한 context 복사와 원본 보존, 검색, 빈 분류, 누락 ID, 긴 목록 독립 스크롤, 항목 전환 시 스크롤 초기화, 900/390px 가로 넘침, 키보드 선택을 검사했다. 소스·외부 합계 32개 기능 검사가 통과했다. 모델 요청은 차단했으며 AI 응답을 대체하지 않았다.

초기 개발 서버 사본에서는 node_modules 심볼릭 링크로 React가 중복 로드돼 검사 앱이 시작되지 않았다. 배포 대상 빌드본의 preview로 바꿔 검사했다. 외부 900px 검사 한 건은 팝업 애니메이션 중 요소 교체로 스크롤 검사에 실패해, 애니메이션 완료를 기다린 뒤 재검했다. 이전 실패와 재검 결과를 JSON에 보존한다.

## 배포

검증한 고정 사본의 빌드를 사용했다. 새 assets를 먼저 복사한 뒤 index를 원자적으로 교체했고, 기존 assets를 유지해 열려 있던 페이지의 파일을 지우지 않았다. API·Cloudflare 터널은 재시작하지 않았다. 실제 관리자 화면에서는 미리보기만 열고, 기존 제안서에 내용을 불러오지는 않았다. 별도 검증 서버는 검사 후 종료한다.

검사 실행:

```sh
WINMATE_REUSE_WEB=http://127.0.0.1:5195 WINMATE_TEST_PASSWORD='현재 비밀번호' node app/tests/history-reuse.mjs
WINMATE_REUSE_WEB=https://배포주소 WINMATE_TEST_PASSWORD='현재 비밀번호' node app/tests/history-reuse.mjs
```

브라우저 저장소는 검사마다 분리한다. 개별 재검은 `WINMATE_REUSE_FILTER`로 검사 이름의 일부를 지정한다. 원본 `src/`, `dist/`, `poc/`, `proddb/`는 수정하지 않았다.
