# 06 — 관리자 샘플 히스토리와 외부 초기 로딩

확인일: 2026-10-20 KST.

## 결과

현재 외부 주소의 `admin` 계정에 다음 편집 가능한 제안서 3개를 제공한다.

1. `[샘플] F&B 프랜차이즈 · 전국 매장 디지털 메뉴보드 전환` (bs01)
2. `[샘플] 호텔 · 리조트 AI 스테이 — 표준 제안서 37장` (bs21)
3. `[샘플] 대학 캠퍼스 · 스마트 강의실 · 도서관 구축` (bs03)

이 샘플은 사용자가 이번에 요청한 기존 Best Scenario의 복사본이다. 모델 실행·점수·내보내기 이력을 지어내지 않으며 `exportedAt`은 null이다. 기존 AI 기능의 Gemini 전용 정책과 실패 처리는 그대로 유지한다. 04단계의 기본 빈 히스토리 정책에서 이번 요청에 해당하는 admin 초기 샘플만 추가했다.

인증된 bootstrap의 admin 프로필에만 샘플 정책을 넣었다. 저장소 경계에서 기존 제안서 뒤에 추가하고 동일한 안정 ID의 기록은 덮어쓰지 않는다. `winmate.v2.seedv`에 이번 버전을 기록해 삭제한 샘플이 재생성되지 않게 했다. 기록 저장에 실패하면 완료 표시도 쓰지 않는다. 원본 시나리오는 깊은 복사로 보존한다.

다른 기기·새 브라우저에서도 admin 첫 접속 시 같은 초기 샘플을 받는다. 편집 내용은 기존 localStorage/IndexedDB 방식으로 해당 브라우저에 저장하며 기기 간 동기화나 서버 제안서 저장을 새로 구현하지 않았다.

## 로그인 후 화면이 사라지는 현상

외부 주소를 새로 열었을 때 실제로 빈 root가 보였다. 콘솔 오류나 인증 실패가 아닌, React를 마운트하기 전에 bootstrap과 큰 App 모듈을 기다리는 구간이었다. 격리 Chromium에서 로그인 시작부터 앱 표시까지 11.77초가 걸렸고, App 파일 응답 완료가 11.36초 지점이었다. 기존 HTML의 root는 비어 있어 그동안 표시할 콘텐츠가 없었다.

- HTML에 즉시 표시되는 로딩 상태와 재시도 버튼을 추가했다. 파일 로드 실패와 오래 걸리는 접속도 빈 화면 대신 안내한다.
- React 렌더 예외는 복구 안내를 표시하며 저장된 기록을 지우지 않는다.
- HTTP gzip 전송을 적용했다. 앱 JS 약 9.2 MB가 실제 외부 전송에서 1,511,382 bytes로 줄었다. 확인한 파일 요청은 약 0.99초였다. 압축을 해제한 앱 데이터와 장표 로직은 같다.
- HTML과 사용자 bootstrap은 no-store로 제공해 예전 HTML이 삭제된 빌드 파일을 계속 가리키는 일을 줄였다.
- SSE와 Range 응답은 압축하지 않는 설치된 Starlette 미들웨어 동작을 검사했다. 실제 Gemini SSE도 외부에서 확인했다.

수정 후 새 브라우저의 실제 폼 로그인→앱 표시 검사 소요는 1500px 4.85초, 900px 4.36초, 390px 4.19초였다. 이 값은 이번 접속 측정이며 다른 네트워크의 보장 시간이 아니다. 이번에 재현한 초기 로딩 현상은 수정했다. 사용자 기기에서 다른 오류가 발생하는지까지 직접 확인한 것은 아니다.

## 실행 상태

앱과 기존 Cloudflare 터널은 실행 상태로 유지했다. 주소는 05단계와 같다. 기존에 열어 둔 페이지는 새로고침하면 변경을 받는다. 원본 `src/`, `dist/`, `poc/`, `proddb/`는 수정하지 않았다. 이번 샘플·초기 로딩 수정과 별도로 작업 공간에서 진행 중인 화면 편집은 되돌리거나 이번 커밋에 포함하지 않는다.
