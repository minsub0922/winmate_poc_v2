# 프롬프트 예산 — 레이아웃 흐름의 모델 호출을 짧게 · 조금씩 · 동시에

- 작성일: 2026-11-18
- 요청: “레이아웃 흐름에서 LLM 프롬프트에 무식하게 긴 경우가 있어. 이건 절대 대답 성능을 내지 못해. 모델 성능이 상당히 안좋은 환경이야. 프롬프트는 최대한 간결해야하고 한번에 필요로 하는 input, output 처리도 제한을 둬야해. 필요하면 fan out/in 패턴을 써서 해결해. 병렬 처리를 많이 활용해도돼.”
- 앱 모델: `qwen/qwen3.6-35b-a3b` — 활성 매개변수 3B인 MoE 모델. 긴 프롬프트에 약하다.
- 코드:
  - `app/api/poc/prompt_budget.py`(규칙 · 도구)
  - `app/api/poc/sheet_writer.py`(작성) · `app/api/poc/sheet_check.py`(검수)
  - `layout_fanout.py` · `part_orchestrator.py` · `layout_final.py` · `layout_flows.py`(사용자 정의 단계) · composer `pictures.py` · `market_research.py`(추리기)

## 1. 규칙 (모든 레이아웃 흐름 호출)

| | 값 | 뜻 |
|---|---|---|
| `WRITE_CELLS` | 8 | 한 번에 쓰는 칸. 더 많으면 나눈다. 한 카드(요소)의 칸은 함께 묶는다. |
| `CHECK_CELLS` | 12 | 한 번에 판단하는 칸 |
| `SOFT_CHARS` · `HARD_CHARS` | 2,400 · 3,200 | 프롬프트 목표 · 상한. 넘치면 맥락 칸(자료 · 요구 · 다른 장 목록)을 줄인다. 묻는 칸은 줄이지 않는다. |
| `WORKERS` | 6 | 한 번 나눈 호출을 동시에 보내는 수. 전체 동시 수는 제공자 설정이 정한다. |

- **보낼 것만 보낸다**: 그 장이 답할 요구, 그 장에 묶인 항목의 자료, 그 장의 흐름 지시 · 입력.
  - 같은 고객 문장이 두 요구 ID로 들어오면 한 번만 보낸다.
  - 여러 칸이 같은 메모를 가지면 메모를 한 번만 쓴다(‘칸 3 · 5 · 7: …’).
  - 기본 흐름 지시가 장 이름 · 말할 것을 되풀이하면 그 부분은 뺀다.
  - 장 목차는 목차 · 간지 · 표지 장에만 보낸다.
- **팬아웃 · 팬인**: 나눈 호출을 동시에 보내고, 답을 원래 호출의 답 모양으로 모은다. 그래서 뒤 단계(빠진 칸 · 같은 말 · 길이 · 검수)는 그대로다.
  - 일부 호출이 실패하면 그 칸만 빈다(뒤에서 다시 묻는다).
  - 모두 실패하면 예전처럼 오류를 낸다.
  - 취소는 곧바로 멈춘다.

## 2. 단계별로 바뀐 것

| 단계(stage) | 전 | 후 |
|---|---|---|
| 문구 작성 `auto_part_fill` | 파트 전체를 한 번에: 덱 메시지, 파트 근거 전부, 요구사항 요약, 장마다 입력 · 묶음 · 칸 · 메모 | 장마다 칸 8개 이하 묶음(카드 칸은 함께). 그 장의 요구 · 항목 자료 · 흐름 지시 · 입력 · 요약은 잘라서 넣는다. 다른 장은 이름만. |
| 빠진 칸 `auto_part_fill_missing` | 파트 근거 전부 + 모든 장의 모든 칸 | 장마다 빠진 칸 묶음 + 그 장의 옆 칸 |
| 길이 맞춤 `auto_part_shorten` | 넘친 칸 전부 | 10개씩 |
| 사실 · 요구 검수 `auto_part_verify` | 파트 근거 전부 + 모든 장의 모든 칸 + 규칙 20줄 | 장마다 칸 12개 이하 묶음 + 그 장이 답할 요구 · 항목 자료 + 규칙 4줄. 요구는 어느 장이든 답하면 된다(합칠 때 판단). 고친 뒤 다시 보는 검수는 고친 장만. |
| 파트 계획 `auto_part_plan` | 파트의 모든 장 + 파트 근거 + 규칙 두 화면 | 장마다 한 호출(지시 · 요구 · 항목) + 니즈 열 한 호출 + 파트 한 줄 한 호출. 모은 뒤 `clean_plan`은 그대로. |
| 파트 검토 `auto_part_review` | 파트의 모든 장 | 장마다(칸 12개씩) 다시 쓸지 · 이유 · 고칠 칸 |
| 장 다시 쓰기 `auto_sheet_redo` | 파트 근거 2,400자 + 다른 장 문구 24개 | 칸 8개씩, 그 장 항목 자료 2개 · 다른 장 문구 8개 |
| 요소 작성 `auto_unit_fill` · 모으기 `auto_frame_fill` | 덱 메시지 · 요소 자료 2,400자 | 요소 자료 600자 · 요구는 원문과 답할 것만 |
| 요소 다시 쓰기 `auto_unit_repair` | 장 전체 문구 + 피할 문구 30개 | 칸 8개씩, 그 요소의 자료 · 칸만, 피할 문구 8개 |
| 사진 고르기 · 검수 `auto_image` · `auto_image_verify` | 파트의 사진 칸 전부 | 2칸 · 3칸씩 |
| 최종 점검 `auto_final_check` · `auto_final_fix` | 장 전체(모든 칸 · 카드 · 사진) | 카드마다(칸 12개 이하 + 그 카드 사진). 고칠 칸 호출은 걸린 칸 + 같은 카드의 다른 칸만. |
| 사용자 정의 단계 `auto_flow_agent` | 장의 모든 칸 | 칸 8개씩(카드 칸은 함께), 도구 결과 3개 × 400자 |
| 시장 근거 추리기 `research:screen` | 모든 주제의 검색 결과 | 주제마다 |

## 3. 검증

**같은 입력으로 전 · 후를 쟀다.**
- 입력: 7개 실제 구성 요청 — admin 샘플(카페 · 숲 · 병원 · 오피스 · 공공 · 리테일 · 학교)의 Storyboard 요청을 잡아 둔 것.
- 하네스: `admin/runtime/prompt-budget/census.py`가 실제 합성기를 돌린다. 모델은 부르지 않는다. 그 요청에서 실제 모델이 낸 답(계획 · 검토 · 칸 문구)을 되돌려준다.
- ‘전’은 같은 하네스로 바꾸기 전 코드를 돌린 것이다. 문구 작성은 실제 기록과 같다(17회 · p90 11,934자 · 최대 12,767자).

- 레이아웃 흐름 호출은 모두 최대 2,849자(약 1.6k 토큰) 이하가 되었다.
- 호출은 45% 늘고, 보낸 글자는 27% 줄었다.
- 빠진 칸 · 다시 쓰기 호출 수는 대역 답에 따라 달라진다. 대역은 칸마다 실제 문구를 돌려주므로 빠진 칸이 적다.
- **모든 레이아웃의 예산 시험**(`app/tests/test_prompt_budget.py`):
  - 사용 중 레이아웃마다 그 장의 칸 전부로 작성 · 검수 · 최종 점검 프롬프트를 만들었다. 자료 · 요약 · 지시는 일부러 길게 넣었다.
  - 모든 묶음이 칸 8 · 12개 이하, 3,200자 이하였다. 최대는 작성 2,509자 · 검수 2,843자다.
  - 묻는 칸은 잘리지 않았다.
- 관련 시험 273개(흐름 · 최종 점검 · 요소별 작성 · 파트 orchestrator · 합성기 · Decision · 사진 · 시장 근거 · admin 흐름)가 통과했다. 바뀐 답 모양에 맞춰 고친 시험은 6개다.

## 4. 남은 것

- **실제 모델로 잰 답의 질은 아직 없다.**
  - OpenRouter 크레딧이 $25 중 $0.93 남아 있고, 운영 앱과 같은 키를 쓴다.
  - 크레딧을 채운 뒤 같은 7개 요청을 실제 모델로 돌린다(`census.py`의 Replay 대신 앱 제공자). 전 · 후 장표를 블라인드로 판정한다.
- **동시 처리 설정**:
  - 운영은 기본값(`WINMATE_LLM_CONCURRENCY` 4 · `WINMATE_LLM_RPM` 42 — 코드 상한 42)이다.
  - 호출이 늘어난 만큼 동시 수를 8~12로 올려야 나눈 호출이 실제로 함께 돈다. 제공자 한도 안에서 정할 일이다.
- **이번에 줄이지 않은 것**:
  - 덱 계획 `auto_plan`(최대 8,474자) — 레이아웃 흐름 전에 덱 전체를 짜는 단계라 이번 범위 밖이다.
  - 시장 근거 추출 · 수정 · 감사(`research:extract` 등, 문서 5개 × 4,200자) — 원문을 읽는 단계라 문단 고르기(읽을 문단만 뽑기)로 다시 짜야 줄일 수 있다.
  - 웹 앱의 장 채우기 `app:fill`(운영 기록 p90 약 17k자 · 최대 약 25k자) — 레이아웃 흐름 밖의 브라우저 경로다.
