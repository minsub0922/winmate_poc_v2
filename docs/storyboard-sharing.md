# Storyboard 재사용·공유

고객 요구사항과 제품 · 솔루션 매칭 버블의 **이전 히스토리에서 불러오기**로 과거 제안서의 동일 버블 내역을 확인하고 복사한다. 선택한 버블과 업종만 바꾸며, 현재 파트·레이아웃과 원본 히스토리는 보존한다.

Storyboard에 들어오면 서버 공유본과 `/s/<토큰>` 주소를 준비한다. 상단 **공유**는 링크를 복사하고 권한 설정을 연다. 기본값은 **읽기전용**이다. 소유자는 같은 링크를 유지하면서 **편집가능/읽기전용**을 언제든 변경한다. 서버는 매 변경 요청에서 권한을 확인하며, 열린 화면은 약 1.5초마다 새 버전과 권한을 확인한다. 바뀌지 않은 공유본은 본문을 다시 전송하지 않는다.

공유 상태를 위한 별도 상태줄은 표시하지 않는다. 연결 실패 시 **공유** 버튼을 비활성화하고 느낌표를 표시하며, 버튼에 마우스를 올리면 연결 오류 내용을 볼 수 있다. 초기 링크 생성 실패도 자동 재시도하고, 연결이 복구되면 버튼을 다시 활성화한다. 동시 수정 충돌의 선택 버튼은 기존 공유 설정 창에서 제공한다.

링크를 가진 사람은 별도 로그인 없이 참여한다. 소유자는 로그인 계정으로, 익명 참여자는 서버가 서명한 브라우저 쿠키로 식별한다. 일반 관리·AI API는 기존 로그인 보호를 유지한다. 외부 참여에는 앱 서버에 연결되는 외부 주소가 필요하다. 로컬 주소는 해당 컴퓨터에서만 접속할 수 있다.

읽기만 한 공유본은 히스토리에 추가되지 않는다. 첫 편집이 서버에 저장되면 같은 공유본을 참여자의 히스토리에 연결한다. 단순 내보내기 상태 변경은 편집으로 세지 않는다. **이 스토리보드 활용하기**는 원본과 동기화되지 않는 새 복사본을 히스토리에 추가한다. 복사본은 자신만의 소유권과 공유 주소를 갖는다. 업로드 이미지와 My 레이아웃도 공유본에 담는다.

서로 다른 필드의 변경은 합치며, 파트·레이아웃은 고유 ID로 구분해 병합한다. 같은 필드의 동시 수정은 충돌로 표시하고 사용자가 **서버 변경 사용/내 변경 반영**을 선택한다. 배열의 추가·삭제·순서 변경이 다른 편집과 겹쳐도 자동 덮어쓰기하지 않는다. 저장되지 않은 변경은 브라우저의 `winmate.v2.shared-drafts`에 보관하고 재연결 시 재전송한다. 권한이 회수되었을 때도 미저장 내용은 복사본으로 보관할 수 있다.

장표 자동 검토의 요청 ID·대기/실행 상태는 브라우저의 작업 상태이므로 공유 내용에 포함하지 않는다. 공유본의 자동 검토는 소유자 브라우저에서 실행하며, 결과 장표 내용은 다른 참여자에게 동기화한다. 열람자의 화면을 여는 것만으로 자동 검토가 실행되거나 편집 내역이 생기지 않는다.

공유본·편집 참여 기록은 `app/data/runtime/storyboards/storyboards.sqlite`, 쿠키 서명 키는 같은 폴더의 `collaboration.secret`에 저장한다. `WINMATE_STORYBOARD_DIR`로 폴더를 변경할 수 있다. 공유본 백업에는 이 폴더도 포함해야 한다. 공유본 최대 크기는 40MiB다. 히스토리 목록 자체는 각 브라우저에 보관한다. 쿠키·브라우저 데이터를 삭제하면 익명 신원과 해당 브라우저의 히스토리는 유지되지 않는다.

검증:

```sh
app/.venv/bin/python -m pytest -q app/tests/test_storyboards.py app/tests/test_auth.py app/tests/test_stage1_api.py
npm --prefix app/web run build
node app/tests/storyboard-sharing.mjs
```

브라우저 검증은 별도의 서버·계정·SQLite, 소유자·편집자·열람자 브라우저로 재사용, 링크 복사, 권한, 동기화, 충돌, 독립 복사, 업로드 이미지, My 레이아웃, 배포 빌드의 모바일 직접 접속을 검사한다. 실제 모델은 호출하지 않는다. 결과 화면은 `app/tests/output/sharing/`에 저장한다.
