## 1. 모델에 가는 글에는 제품 코드가 없다 — 표식으로 묻고 이름으로 돌려받는다

모델 경계(`Masked` = 레이아웃 흐름의 모든 `llm.json`, `MaskedDecision` = 결정 모델)에서 바꾼다:

| 원래 | 모델이 보는 것 |
|---|---|
| 고른 제품 (QM55C · QM43C · KM24C) | 제품군 + 번호 표식: `사이니지①` `사이니지②` `키오스크①` |
| 한국어로 쓴 모델 이름 (갤럭시 엑스커버7 프로 · 탭 액티브5 프로) | 같다 (고른 것은 표식, 아니면 `다른 스마트폰`) |
| 고르지 않은 제품 | `다른 {제품군}` |
| 카탈로그 계열의 모르는 코드 (QM65C) | `모델` |
| 솔루션 (MagicINFO · VXT · ST Pro · Knox …) | 분류 + 글자 표식: `사이니지 CMSⓐ` — 그 솔루션의 장(솔루션 · 여정 · 기술 장, 또는 장 이름이 그 솔루션)에서만 이름 그대로 |
| 규격 (IP65 · USB · 55") | 그대로 |

- 표식이 있으면 맨 앞에 한 줄 범례.
- 답의 표식은 덱 이름(`short`)이나 카탈로그 이름으로 되돌린다.
- 스키마 enum은 표식으로 묻고 ID로 돌려받는다.
- 결정 모델:
  - 상태와 질문의 모든 필드를 바꾼다(`decision.choice`의 `instructions` 포함 — 처음에는 `q`만 바꿔서 질문 글이 그대로 갔다. 고침).
  - 선택지 키는 표식으로 묻고 원래 키로 돌려받는다.
- 장마다의 범위: `item_mask.sheet(auto, ctx, sl)` — 쓰기 · 검수 · 최종 점검 · 파트 계획 · 재작성 · 사용자 단계가 장 단위로 연다.

검증 — 실제 composer, 7개 실요청, 답은 기록된 실모델 답을 되풀이(`admin/runtime/prompt-budget/census.py`):

| | 호출 | 제품 코드 · 한국어 모델명 | 자기 장 밖 솔루션 이름 |
|---|---|---|---|
| 표식 전 (after1 — 프롬프트 예산 적용 뒤, LLM 호출만) | 561 | 180 | 592 |
| 지금 (mask6 — LLM 487 + 결정 모델 58) | 545 | 0 | 0 |

레이아웃 흐름의 LLM 프롬프트는 모두 3,200자 이하다(최대 2,932자). 최종 점검 한 번 예: 고정 지시 + 표식 범례 + 메타데이터 + 1차 값 = 2,190자.

## 2. 레이아웃 메타데이터 — AI가 채우는 칸 · 사진과 그 관계 (구조는 쓰되 내보내지 않는다)

`layout_meta.view(f)`:

```
groups: [{label, about, key, key_by?, key_in?,
          cells: [{i, role, form, len, key?, names?, of?, same?}],
          pictures: [{slot, shows: item|scene, hint?}]}]
frame:    장 전체 칸 (제목 · 부제)
pictures: 묶음 없는 사진
flags:    묶음을 정한 근거
```

- **묶음 하나 = 항목 하나.**
  - `key` 칸이 그 항목을 정한다: 제품 · 공간 · 사례 이름, 또는 다른 칸들이 ‘칸 N …’으로 가리키는 칸.
  - 같은 묶음의 칸과 `shows: item` 사진은 그 항목을 말하고 보여 준다.
  - `about: list · matrix` 는 칸마다 다른 항목이다.
- **값:**
  - `form · len` 은 그 레이아웃 견본의 형식 · 길이다(내용은 아님).
  - `of` 는 그 칸이 말하는 칸, `same` 은 글자 그대로 되풀이하는 칸이다(‘칸 20 이름 그대로’).
- **나가지 않는 것:** 좌표 · HTML · 견본 글 · 제품 코드 · 솔루션 이름(`clean`). 단, 규격은 남긴다.

묶음을 정하는 순서 — 레이아웃 구조와 견본으로 확실히 한 뒤 구조는 버린다:

1. **요소 계획의 묶음** (`layout_elements`)
   - 한 묶음 안의 번호(‘가치 1 · 가치 2’ · ‘1장 · 2장’)로 나눈다.
   - ‘2~3개’ 같은 개수는 번호가 아니다.
   - 칸 3개 이상이 행 · 열을 함께 가리키면 표(matrix)다.
2. **‘칸 N …’ 역할 참조로 옮긴다.** 다르게 · 말고(대조)와 그대로(복사)는 참조가 아니다.
3. **n번째 제품 사진 ↔ n번째 제품 이름 칸.**
4. **계획이 빠뜨린 것**
   - **a** 같은 번호의 칸들(고정 이름 칸이 key).
   - **f** 같은 이름을 가리키는 칸들.
   - **e** 한 묶음에 같은 종류의 기준 칸이 둘 이상이면(한 줄의 두 단계):
     - 기준마다 그것만 담은 가장 큰 HTML 상자로 나눈다.
     - 나머지는 시트의 실제 상자(줄 · 열 겹침)로, 없으면 HTML 거리로 붙인다.
   - **b** 묶음 없는 사진은 문서 순서로 옆 칸들의 묶음에 붙인다.
     - 앞 · 뒤 방향은 장 전체로 정한다: 1:1 → 견본 일치 → 뒤.
     - 시트의 25% 이상인 사진(히어로 · 조감도 · 풀블리드)은 붙이지 않는다.
     - 하나만 붙으면 견본이 같은 제품을 보일 때만 붙인다.
     - 한 묶음에 사진 여럿이면 사진마다 나눈다.
   - **c** 캡션 · 제품 이름 칸이 뒤따르는 사진은 그 자체로 묶음이다.
   - **d** 한 묶음의 두 요소 사이에 낀 칸은 그 묶음이다.
5. **견본 확인:** 사진 견본이 key 견본의 제품(제품군)을 보이면 `shows: item`. 다르면 `flags`.

## 3. 최종 점검 — 고정 지시 + 메타데이터 + 1차 값

`auto_final_check`(ReAct) · `auto_final_fix` 의 지시는 레이아웃과 회차에 상관없이 같은 글(`FIXED` · `FIX_FIXED`)이다. 그 아래에 매번 넣는 것:

- 고객이 고른 것(표식)
- 이 카드 묶음의 메타데이터(`layout_meta.prompt_block`, AI 채움 칸만)
- AI가 처음 채운 값(`1차 값`: 칸 · 사진 설명 · 고정 칸)
- 코드 관찰 · 도구 결과

예전에는 들어가던 레이아웃 견본 글(다른 고객 것)은 이제 넣지 않는다. 묶음은 메타데이터 묶음으로 나누고, 한 번에 12칸 이하다.

- **코드 검사(카드):** 메타데이터 key 칸이 정한 항목과 다른 항목을 말하는 칸 · 사진을 잡는다. key가 단계 · 문제 이름이면 그 묶음의 제품 이름 칸으로 본다.
  - 이름 · 제목 칸은 견본에 숫자가 있어도(‘1차 확산’) 숫자 칸이 아니다(`role_form`).
- **결정 모델:** 같은 메타데이터 + 1차 값을 상태로 받는다.
  - ‘같은 항목인가’는 key 있는 묶음의 칸에만, 그 항목(칸 K “1차 값”)을 넣어 묻는다.
  - 다른 묶음의 칸은 ‘일을 하는가’만 묻는다.
  - 묶음 없는 칸(제목 · 부제)은 묻지 않는다(형식은 코드가 본다).

검출 벤치(`admin/runtime/layout-final`, 레이아웃 399장에 오류를 넣고 실제 결정 모델로 판정; 넣는 이름 바꾸기는 묶음 수에 따라 달라 개수 대신 비율):

| | 깨끗한 장 오탐 | 이름 바꾸기를 결정 모델이 잡음 | 코드 또는 결정 |
|---|---|---|---|
| f4 (견본 글 상태, 모든 칸에 같은 질문) | 5.8% | 43/122 (35%) | 54/122 (44%) |
| f6 (메타데이터 상태) | 12.0% | 71/161 (44%) | 83/161 (52%) |
| f6 − 묶음 없는 칸 질문 (지금) | 6.3% | 같음 (결정만 잡는 것 70 → 66) | |

마지막 줄은 f6의 답에서 묶음 없는 칸의 질문을 뺀 계산이다(다시 돌리지 않음).

결정 호출 크기는 질문마다 선택지 설명이 붙는 결정 API 형식 때문에 크다(최대 19k자, 그중 질문 13.5k). 바뀌기 전부터 그랬고, LLM 프롬프트 상한(3,200자) 대상이 아니다.

## 4. admin — 레이아웃 관리 상세 머리 ‘메타데이터 n’

- 버튼 자리: 활용 예시 · 칸 설계 · 입력 옆.
- 누르면 팝업:
  - 묶음마다 이름 · 종류 · key(코드 · 고정 · 다른 묶음)
  - 칸(역할 · key · 이름 종류 · → 가리키는 칸 · = 같은 말 · 형식 · 길이)
  - 사진(항목 · 장면, 설명)
  - 장 전체 · 묶음 근거
- Esc 나 바깥을 누르면 팝업만 닫힌다.
- 설명 문장은 넣지 않았다(표식 · 짧은 라벨만).
- 시험: `admin/tests/layout-flow-ui.mjs`(버튼 · 팝업 · API · 코드 없음 · Esc).
