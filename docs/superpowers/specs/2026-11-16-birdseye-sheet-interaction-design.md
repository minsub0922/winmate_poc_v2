# 조감도 시트 — 3D 조작 · 중앙형 전환

## 의도
조감도가 들어간 시트를 그림 한 장이 아니라 조감도 시뮬레이션처럼 다루고, 같은 내용을 두 형태(좌 조감도 + 우 설명 / 중앙 조감도 + 꺽쇠 화살표 + 설명 버블)로 오가며 보게 한다.

## 목표
- 대상 시트: `L_SPATIAL_3D` · `L_SPATIAL_2D`(공간·제품 연결), `L_VS_BIRD_S3~S6` · `L_VS_BIRD_B7~B10`(표준 제안서 조감도 · 범례).
- 시트 팝업 우상단에 전환 버튼. 편집 팝업에서는 선택이 시트에 저장되고(`ov.spatialMode = 'center'`), PPT · 썸네일 · 뷰어에 그대로 반영된다. 읽기 전용 팝업에서는 저장 없이 보기만 바뀐다.
- 조감도 칸은 3D로 살아 있다. 편집 팝업: 회전 · 오브젝트 선택 · 이동, 끝나면 시트에 저장. 읽기 전용 팝업: 회전만(저장 없음).
- 회전하는 동안 번호 핀과 화살표가 공간을 따라간다.
- 표준 제안서 조감도(미리 만들어진 시트)도 전환 · 회전이 된다.

## 하지 않는 것
- 「내 조감도 레이아웃」(`L_MY_*`)은 이미 중앙형 편집기가 있으므로 그대로 둔다.
- `L_BE01~03`(장면이 없는 도식)은 대상이 아니다.
- 2D 배치도(`L_SPATIAL_2D`)는 전환만 되고 3D 조작은 없다.
- 표준 건물 조감도(`L_VS_BIRD_B*`, 8종)는 건물 전용 렌더러라 전환만 되고 회전은 없다.
- 시트에서 옮긴 오브젝트는 그 시트의 사본(`ov.spatial`)에만 남는다. 원본 조감도 히스토리는 바꾸지 않는다.

## 접근
1. **(채택) 공용 렌더 경로 + 팝업 위 3D 덧씌움.** `applyOverrides`가 `ov.spatialMode`를 보고 같은 DOM을 중앙형으로 재배치한다(글 칸 번호는 그대로라 편집 · 근거 · PPT가 모두 따라온다). 3D는 `Slide`의 innerHTML 밖, 팝업 무대 위에 얹는다(`Slide`는 값이 바뀔 때마다 innerHTML을 다시 쓰므로 안에 캔버스를 둘 수 없다).
2. 중앙형을 별도 레이아웃 id로 만들고 `f`를 바꾸기 — 칸 번호 매핑 · 근거 이전이 필요하고 읽기 전용 화면에서는 `f`를 바꿀 수 없다.
3. 「내 조감도 레이아웃」으로 변환 — 사용자 템플릿이 시트마다 생기고, 표준 시트에는 쓸 수 없다.

## 설계
- `domain/spatial/birdseye-sheet.js`(순수): 대상 판별, 공간 행(번호 · 이름 칸 · 설명 칸), 공간 좌표 출처(`ov.spatial.anchors` → 표준 이미지 핀 표), 중앙형 기하(이미지 상자 · 버블 자리 · 꺽쇠 경로), DOM 적용.
- 표준 시트 데이터: `bird_render.mjs` · `bld_render.mjs`가 핀 좌표 표(`domain/templates/vertical_std_bird.json`)와 장면 파일(`public/assets/vertical-std/<vid>.scene.json`, 공간 조감도 36종)을 함께 낸다.
- `components/birdseye-live.jsx`: 3D 렌더러를 직접 올리는 덧씌움. 장면 출처는 `ov.spatial` → 조감도 히스토리(`img.birdseye`) → 표준 장면 파일.
- 팝업: `detail.jsx`(편집) · `tplkit.jsx`(읽기 전용)에 버튼과 덧씌움.

## 만드는 사람에게 맡기는 것
버블 크기 · 자리, 화살표 모양, 3D가 뜨기 전 표시, 저장 시점(조작이 멎은 뒤).
