# 조감도 통합 · 명령형 스튜디오 — 설계

2026-11-15 · 상태: 사용자 승인 대기

## 1. 왜 바꾸나

- 건물 조감도와 공간 조감도가 사이드바 항목, 목록, 히스토리, 시작 방식이 모두 따로다. 같은 "조감도" 일이 둘로 갈라져 있다.
- 공간 스튜디오는 왼쪽 입력 카드에 조건을 적고 "조감도 만들기"로 다시 만드는 방식이다. 사용자는 **시뮬레이터를 문장과 마우스로 직접 조작**하길 원한다.
- PPT 레이아웃 만들기(레이아웃 추출 · Layout 히스토리)는 조감도 탭의 일이 아니라 Storyboard의 일이다.

## 2. 사용자가 정한 것

아래는 사용자가 직접 말한 요구다. 설계가 이것과 어긋나면 설계가 틀린 것이다.

1. 건물 · 공간 조감도를 **하나의 탭**으로 합친다. **히스토리도 나누지 않는다.**
2. **Layout 히스토리는 없앤다.** PPT 레이아웃을 만드는 기능은 **Storyboard에 위임**한다.
3. 조감도 탭의 "업종별 템플릿" 버튼을 없앤다. **스튜디오를 시작할 때 팝업**으로 건물인지 공간인지, 내 Storyboard의 요구사항 · DSS 기반으로 시작하는지, 업종 템플릿을 쓸지 등을 확인하고 스튜디오로 넘어간다.
4. 스튜디오의 **왼쪽 카드를 없애고 시뮬레이터만** 둔다. 시뮬레이터 아래에 **텍스트 입력창**이 있고, **@로 공간 · 제품 · 오브젝트를 모두 태깅**해 명령한다. 명령은 **실제로 시뮬레이터를 조작**한다.
   - 예: `@거실 에 @사람 2명 복사해` · `@소파 오른쪽으로 옮겨` · `@세탁기 3개 추가해`
5. 오브젝트는 **이동 · 복사 · 회전**할 수 있어야 한다.
6. 명령 해석은 **LLM(또는 Decision 분기)** 을 쓴다.
7. **건물에서는 프롬프트 입력 자체를 막는다.** 건물은 **이미 만든 공간이나 템플릿 공간을 자유롭게 구성하고 합칠 수 있게** 한다.

## 3. 목표 · 비목표 · 실패로 볼 것

**목표**
- 사이드바 "조감도" 하나, 목록 하나, 히스토리 하나, 시작 팝업 하나.
- 공간 스튜디오 = 시뮬레이터 + 그 아래 명령 입력창. 왼쪽 카드가 하던 일(공간 추가 · 삭제, 제품 넣기)은 시작 팝업과 명령, 오브젝트 서랍으로 한다.
- 명령 한 번에 여러 조작(문장 여러 개)을 처리하고, 결과가 곧바로 장면에 반영되며 실행 취소로 되돌릴 수 있다.
- 건물 스튜디오에서 내가 만든 공간 조감도와 템플릿 공간을 크기 제한 없이 층으로 쌓는다.
- Storyboard의 조감도 장에서 조감도를 골라 그 자리에서 장표(레이아웃)를 만든다.

**비목표 (이번에 하지 않음)**
- 건물의 층 안 오브젝트(가구 · 사람 · 제품) 편집. 건물 명령 입력.
- 건물을 PPT 레이아웃으로 만들기.
- 저장 데이터 형식 변경이나 일괄 이전. 기존 조감도 · 건물 · 저장 레이아웃 · 제안서는 그대로 열려야 한다.

**실패로 볼 것**
- 명령을 넣었는데 설명만 나오고 장면이 바뀌지 않는다.
- 왼쪽 카드를 없앤 뒤 공간을 추가 · 삭제하거나 제품을 넣을 방법이 없다.
- 이미 제안서에 들어 있는 조감도 장표나 기존 히스토리가 깨진다.
- 같은 작업 폴더를 쓰는 다른 세션의 미커밋 변경을 덮어쓴다.

## 5. 설계

### 5.1 탭과 경로
- 사이드바는 "조감도" 한 항목(2D · 3D · BETA). 누르면 통합 목록(`{name:'spatial'}`).
- 스튜디오 경로는 그대로 둔다: 공간 `{name:'spatial', id}`, 건물 `{name:'building', id}`. 기존 링크 · 새로 고침 복원이 깨지지 않는다.
- `{name:'building'}`(id 없음)은 통합 목록으로 보낸다. 두 스튜디오 모두 "뒤로 가기"는 통합 목록으로 간다.
- 사이드바 항목은 두 경로 모두에서 현재 위치로 표시한다.

### 5.2 통합 목록
- 머리말 "조감도", 주 버튼 **"조감도 스튜디오 시작"** 하나 → 시작 팝업(5.3).
- "업종별 템플릿 활용하기" 버튼, 히스토리가 비었을 때의 업종 템플릿 줄, "Layout 히스토리" 구역, 저장 레이아웃 전체 보기 창을 없앤다.
- **"조감도 히스토리" 한 구역**에 공간 조감도와 건물을 최근 수정순으로 섞어 보여 준다. 카드에 종류 표시(공간 · 건물)를 붙인다. 구역을 종류별로 나누지 않고 필터도 두지 않는다.
- 카드를 누르면 그 종류의 스튜디오로, 삭제는 종류에 맞는 삭제를 부른다. 건물 카드의 썸네일 · 요약(층 수 등)은 건물 모듈의 것을 쓴다.
- 페이지 나누기는 유지한다(한 쪽 8개). 건물은 로컬 전체를 읽고, 공간은 서버에서 그 쪽에 필요한 8개 묶음만 읽어 합친다(건물 수만큼만 앞쪽을 더 읽는다 — 구현 중 고침: 처음에는 앞에서부터 한 번에 최대 48개씩 읽었으나 뒤쪽일수록 장면 전체를 다시 받았다).
- 건물 모듈의 자체 목록 화면은 앱 안에서 더 쓰지 않는다. 대신 모듈이 목록 · 썸네일 · 삭제 · 변경 알림을 밖으로 내보내 통합 목록이 쓴다.

### 5.3 시작 팝업
한 창에서 순서대로 고른다.

1. **종류**: 공간 / 건물
2. **출발점**
   - 공간: 빈 스튜디오 · 내 Storyboard에서 · 업종 템플릿
   - 건물: 직접 구성(빈 건물) · 내 Storyboard에서 · 건물 템플릿
3. **고르기**(출발점에 따라): 제안서 목록, 또는 템플릿 갤러리(지금의 업종 템플릿 창 · 건물 템플릿 고르기 창의 내용을 이 안으로 옮긴다)
4. 스튜디오로 이동

**빈 스튜디오 (공간)**
- 장면은 업종 없이는 만들 수 없다(가구 · 사람 역할 · 스타일이 업종을 따른다). 그래서 빈 스튜디오를 고르면 **업종을 고르는 단계**가 하나 더 있다(필수). 스타일은 그 업종에서 가장 많이 쓰는 것으로 정한다.
- 시작한 뒤 업종을 바꾸는 기능은 두지 않는다(스타일은 명령으로 바꿀 수 있다). 업종을 바꾸려면 새로 시작한다.

**내 Storyboard에서 (공간)**
- 편집 권한이 있는 내 제안서 목록을 보여 준다(고객 · 제목, 요구사항 한 줄, 연결된 DSS 수, 공간 구성 여부).
- 공간 구성이 완료된 제안서: Storyboard가 조감도를 만들 때 쓰는 것과 **같은 함수(`startBirdseye`)** 로 만든다. 즉 이렇게 만든 조감도는 **그 제안서의 조감도로 등록**된다(`spacePlan.birdseye`). 그 구성으로 만든 최신 조감도가 이미 있으면(done이고 stale이 아님) 새로 만들지 않고 그것을 연다.
  - 등록되므로 Storyboard에서 조감도를 만들었을 때와 똑같이, 그 제안서의 비어 있는 조감도 장이 자동으로 채워진다(`mapBirdseyeLayouts`). 시작 팝업에서 이 사실을 한 줄로 알린다.
- 공간 구성이 없는 제안서: 그 자리에서 추론한다(업종 추론 → 공간 후보 중 첫 후보 → 제품 배치). 진행 상태를 보여 주고, 결과는 제안서의 공간 구성으로 저장한다. 연결된 제품 · 솔루션이 없으면 이유를 말하고 막는다.

**내 Storyboard에서 (건물)**
- 위와 같은 방법으로 공간 구성을 얻은 뒤 **공간 하나를 한 층**으로 하는 건물을 만든다(아래부터 구성 순서, 최대 6층). 각 층은 그 공간만 담은 장면을 만들어 5.8의 "내 공간을 층으로" 방식으로 넣는다. 외벽은 그 업종 건물 템플릿의 것을 쓰고 없으면 기본.

**직접 구성 (건물)**: 빈 층 하나짜리 건물로 스튜디오를 연다. 층은 스튜디오에서 채운다(5.8).

### 5.4 공간 스튜디오 화면
- 왼쪽 `SpatialStudioForm`을 없앤다. 화면은 위에서부터: 도구줄(2D · 3D 전환, 실행 취소 · 다시 실행, 이름, 요약, "제품 · 가구 오브젝트" 서랍 버튼) → 시뮬레이터 → 공간 띠(전체 맵 · 공간별) → 명령 입력창.
- "레이아웃 추출" 버튼과 레이아웃 편집 창을 스튜디오에서 없앤다(5.9로 이동).
- 입력 폼 데이터(`form`)는 화면 없이 내부 상태로 남긴다. 장면과 함께 저장되고, 조작할 때마다 지금처럼 장면과 맞춘다(`mergeSpatialEditForm`). 저장 형식은 바꾸지 않는다.
- 빈 스튜디오(공간이 하나도 없음)에서도 명령 입력창은 켜져 있다. 첫 공간은 명령(`@회의실 추가해`)으로 만든다. 빈 화면에는 예시 명령을 안내한다.
- "입력 내용이 변경되었어요 · 조감도 만들기" 흐름은 없어진다. 모든 변경은 곧바로 장면에 반영된다.
- **예전 기록을 열 때**(입력 폼과 장면이 어긋난 기록):
  - 장면은 없고 입력 폼에 공간이 적혀 있는 초안 → 열 때 그 폼으로 장면을 한 번 만든다(적어 둔 입력을 잃지 않게). 폼이 불완전해 만들 수 없으면 빈 스튜디오로 연다.
  - 장면이 있고 폼에 반영 안 된 변경이 남은 기록 → 장면이 기준이다. 폼은 장면에서 다시 뽑는다.
- **Storyboard 위 팝업으로도 동작해야 한다.** 2026-11-15에 사용자가 다른 세션에 "Storyboard에서 만든 3D 조감도를 누르면 스튜디오를 팝업으로" 띄우게 했다(`components/spatial-studio-popup.jsx`, `SpatialPage`의 `popup` 속성, `ProposalPage.jsx` · `match-area.jsx`). 이 동작은 그대로 유지한다: 팝업일 때는 "뒤로 가기" 대신 "닫기", 통합 목록으로 이동하지 않는다. 이 문서의 스튜디오 변경(왼쪽 카드 제거, 명령 입력, 마우스 · 키보드 조작)은 팝업 안에서도 같게 적용된다.

### 5.5 @ 태깅
@를 치면 세 묶음이 한 목록에 나온다. 글자를 더 치면 좁혀진다.

| 묶음 | 항목 | 태그 종류 |
|---|---|---|
| 공간 | 장면에 있는 공간 | `room` |
| 공간 | 새로 추가할 공간 종류(`SPACE_TYPES`) — "새로 추가" 표시 | `space` |
| 제품 | 카탈로그 제품(삼성 제품) — "새로 추가" 표시 | `asset` |
| 오브젝트 | 배치된 오브젝트(제품 · 가구 · 사람 연출) | `object` |
| 오브젝트 | 카탈로그 가구 · 사람 연출 — "새로 추가" 표시 | `asset` |

- 지금 보고 있는 공간의 항목을 먼저 보여 준다.
- 태그에 마우스를 올리면 지금처럼 위치 강조 · 상세가 보인다. 공간 태그는 그 공간을 강조한다.
- 시뮬레이터에서 오브젝트나 공간 이름표를 고르면 "@ 프롬프트에 넣기"로 태그를 넣을 수 있다.

**사람은 "사람 연출" 단위다.** 카탈로그의 사람 164종은 모두 사람과 딸린 소품 · 가구가 한 묶음인 오브젝트다(예: "회의 참석자 2명 · 착석 토론", "회사원 · 머그컵 휴식"). 사람만 따로 있는 오브젝트는 없다.
- @에서 "사람"이나 역할(학생 · 직원 · 손님 …)로 찾으면 사람 연출이 나온다. 배치된 사람 연출은 `object`, 새로 넣을 것은 `asset`.
- 가구에 자동으로 앉혀진 사람(`object.people[]`)은 따로 고르거나 태그할 수 없다. 그 가구를 태그하면 사람도 함께 복제 · 이동된다.
- 복제는 원본에 얹힌 것(책상 위 제품)과 딸린 사람을 함께 가져간다.
- 묶음에서 사람만 떼어 조작하는 것은 이번 범위가 아니다.

### 5.6 명령 해석과 조작

**흐름**: 문장 + 태그 + 장면 상태 + 지금 보는 공간 + 카메라 방향 → 서버 → 조작 목록 → 클라이언트가 장면 복사본에 차례로 적용 → 전부 성공하면 한 번에 반영(실행 취소 한 단계). 하나라도 실패하면 장면은 그대로 두고 이유를 보여 준다. 배치 충돌로 실패하면 지금처럼 이유를 붙여 한 번 다시 묻는다. 삭제가 들어 있으면 지금처럼 확인을 받는다.

**조작 종류** (서버 응답과 `applySpatialEdit`가 같은 모양을 쓴다)

| 조작 | 내용 |
|---|---|
| `add` | 자산을 공간에 N개(1~30) 추가. 자리는 자동 안전 배치 |
| `copy` | 배치된 오브젝트를 N개 복제. 대상 공간을 주면 그 공간에, 없으면 원본과 같은 공간에. 회전 · 설치 방식은 원본을 따른다 |
| `move` | 절대 좌표, 또는 방향(왼쪽 · 오른쪽 · 앞 · 뒤)과 거리(m). 다른 공간으로 옮기기(대상 공간 지정)도 포함 |
| `rotate` | 상대 각도(예: 오른쪽으로 90°) 또는 절대 각도 |
| `remove` | 오브젝트 삭제(얹힌 것 · 딸린 것 함께) |
| `style` | 공간 스타일 변경 |
| `room_add` | 공간 종류(와 이름)로 새 공간 추가. 기존 공간과 그 안의 배치는 그대로 둔다 |
| `room_remove` | 공간과 그 안의 오브젝트 삭제 |
| `room_update` | 공간 이름 · 용도 설명 바꾸기 (왼쪽 카드에서 하던 일) |

**방향 해석**: "오른쪽 · 왼쪽 · 앞 · 뒤"는 **지금 화면에서 보이는 방향**이다. 서버는 방향과 거리만 답하고, 클라이언트가 카메라 방향으로 지도 좌표 이동량을 계산한다(2D 평면도에서는 화면 = 지도). 거리를 말하지 않으면 1m. 벽 · 다른 오브젝트에 막히면 닿기 직전까지만 옮기고 그렇게 했다고 알린다.

**대상을 말하지 않았을 때**: 공간 태그가 없으면 지금 보고 있는 공간, 전체 맵을 보고 있으면 용도가 맞는 공간을 모델이 고른다. 고를 수 없으면 조작 없이 되묻는다(임의로 정하지 않는다).

**LLM · Decision 분기**
- 새 작업 이름 `spatial.command`를 `DECISION_TASKS`에 더한다. 두 경로 모두 위 조작 목록을 낸다.
- LLM 경로: 지금의 `/api/spatial/edit`를 넓힌다(조작 종류 · 태그 종류 · 방향 답 추가). 문장 여러 개도 한 번에 처리한다.
- Decision 경로(키가 있고 작업이 켜져 있을 때)는 **"요청이 하나이고, 대상이 모두 @로 태그된 명령"만** 맡는다. 이런 명령은 대상 후보가 태그와 장면의 공간으로 좁혀져 있어 유형 질문으로 풀린다.
  - 문장을 코드로 쪼개거나 숫자를 정규식으로 읽지 않는다(규칙 대체 없음 원칙). 문장 전체를 state로 주고 묻는다: 요청이 둘 이상인가(noul) → 조작 종류(choice) → 태그 중 무엇이 조작 대상이고 무엇이 목적지인가(choice) → 대상 공간(choice, 장면의 공간 + "말하지 않음") → 개수(choice 1~30) → 방향(choice) → 거리 · 각도(choice, 정해진 단계 + "말하지 않음").
  - LLM 경로로 넘기는 경우: 요청이 둘 이상, 태그 없는 대상(카탈로그에서 찾아야 함), 공간 추가 · 삭제 · 이름 바꾸기 · 스타일, 선택지로 표현 못 하는 값, 확신도가 기준보다 낮음.
- 결과 문구("거실에 사람 연출 2개를 복제했어요")는 적용된 조작 목록에서 코드가 만든다(두 경로 공통). 모델의 문장은 조작 없이 되물을 때만 쓴다.
- 응답에 어느 경로가 답했는지(`source`)를 담는다. 키 · 모델 설정은 지금의 `.env` 규칙을 그대로 따른다.

**사용자 예시의 기대 결과**
- `@거실 에 @사람 2명 복사해` → `copy`(태그한 사람 연출, 2개, 대상 = 거실). 사람 태그가 카탈로그 자산이면 `add` 2개.
- `@소파 오른쪽으로 옮겨` → `move`(그 소파, 오른쪽, 1m).
- `@세탁기 3개 추가해` → `add`(세탁기, 3개, 보고 있는 공간 또는 용도가 맞는 공간).

### 5.7 마우스 · 키보드 조작 (공간 스튜디오)
- 이동: 지금처럼 끌어서(2D · 3D).
- 선택한 오브젝트의 말풍선에 **회전**(왼쪽 · 오른쪽 15°, 90°)과 **복제** 버튼을 더한다. 복제는 같은 공간의 빈 자리에 놓는다.
- 단축키: `R` 90° 회전, `Ctrl/⌘+D` 복제, `Delete` 삭제, 화살표 5cm 이동(Shift 50cm). 오브젝트를 고른 상태에서만 동작하고, 입력창이나 다른 입력 칸에 글자를 치는 중에는 동작하지 않는다. 팝업으로 열렸을 때도 같고, 뒤에 깔린 Storyboard에는 영향을 주지 않는다.
- 모두 실행 취소 대상이고, 충돌하면 지금처럼 이유를 보여 주고 적용하지 않는다.

### 5.8 건물 스튜디오
- **명령 입력창을 두지 않는다.**
- 층을 채우는 고르기 창에 **"내 조감도"** 묶음을 더한다(내 공간 조감도 히스토리). 기존 "템플릿 공간"(구운 층)과 나란히 고른다. 여러 개를 한 번에 골라 여러 층으로 쌓을 수 있다.
- **크기 제한을 없앤다.** 어떤 공간이든 어떤 층에든 넣을 수 있고, 그 층의 크기는 넣은 공간의 크기를 따른다. 층 추가 · 복제 · 순서 바꾸기 · 삭제 · 외벽 · 이름은 지금 그대로.
- **내 공간을 층으로 넣는 방법**: 앱이 공간 조감도 장면을 건물의 층 기록 형식으로 바꿔(`build_building_bake.mjs`의 `bakeScene`과 같은 규칙) 건물 모듈에 등록하고, **그 층 기록을 건물 기록 안에 함께 저장**한다. 그래서 원본 조감도를 지우거나 고쳐도 건물은 그대로이고, HTML 추출 파일에도 들어간다. 원본을 고친 뒤 건물에 반영하려면 그 층에 다시 넣는다.
- 건물 모듈은 독립 모듈인 채로 둔다. 앱과의 연결은 지금의 저장 훅처럼 좁은 접점으로만 한다(층 기록 등록, 내 조감도 목록 제공, 목록 · 썸네일 · 삭제 내보내기, 시작 방식 지정).

### 5.9 Storyboard로 넘기는 것 (PPT 레이아웃)
- 공간 스튜디오와 조감도 목록에서 레이아웃 추출 · Layout 히스토리를 없앤다.
- Storyboard의 조감도 장 상세(`detail.jsx`)에서 조감도를 고르는 창이 **조감도 히스토리**(공간)와 업종 템플릿을 보여 준다. 조감도를 고르면 그 자리에서 레이아웃 편집 창(`SpatialLayoutEditor`)이 열리고, 저장하면 그 장에 적용된다.
- 저장 방식은 지금과 같다(내 템플릿 `L_MY_…`, kind `spatial`, 장은 `spatialLayout`으로 참조). 그래서 이미 만든 장표 · 저장 레이아웃은 그대로 동작한다.
- 예전에 추출해 둔 레이아웃은 같은 창의 "저장한 레이아웃" 묶음에서 계속 고를 수 있다.
- 공간 구성 → 조감도 → 조감도 장 자동 채우기(`mapBirdseyeLayouts`)는 그대로 둔다.

### 5.10 호환
- 기존 공간 히스토리 · 건물 · 저장 레이아웃 · 제안서 데이터는 손대지 않고 그대로 읽는다.
- `/api/spatial/edit`의 기존 요청 · 응답 모양은 계속 받는다(새 필드는 선택).
- 건물 기록에 더하는 필드(내 공간 층 기록)는 없어도 되는 필드다. 예전 건물은 그대로 열린다.

### 5.11 확인 방법
- 순수 함수(조작 적용 · 방향 계산 · 층 기록 변환 · 통합 목록 병합)는 Node 테스트.
- 서버 명령 해석은 pytest(가짜 LLM · 가짜 Decision으로 두 경로가 같은 조작 목록을 내는지, 잘못된 응답을 거르는지).
- 화면은 격리 서버 + 시스템 Chrome UI 테스트: 통합 목록, 시작 팝업의 여섯 갈래, 공간 스튜디오 명령(사용자 예시 세 문장 포함), 마우스 · 키보드 조작, 건물 자유 구성, Storyboard 조감도 장.
- 실제 모델(OpenRouter · TypeSafe 키가 `.env`에 있음)로 사용자 예시 세 문장을 두 경로 모두 한 번씩 돌려 본다.
- 이번 변경으로 전제가 사라지는 기존 테스트(스튜디오 입력 폼, 업종별 템플릿 버튼, Layout 히스토리, 저장 레이아웃, 건물 목록 등)는 새 화면에 맞게 고치거나 지운다. 무엇을 지웠는지 결과 보고에 적는다.

- 2026-11-15 현재 다른 세션들이 같은 영역을 고치고 있다: `SpatialStudioPage.jsx` · `spatial-studio-popup.jsx` · `spatial.css` · `ProposalPage.jsx` · `match-area.jsx`(스튜디오 팝업), `storyboard.jsx` · `layout-compose.*`(레이아웃 자동 구성). 이 파일들은 새 파일로 나눌 수 있는 것은 나누고, 고칠 때는 필요한 줄만 고친다. 통째로 다시 쓰지 않는다.
- 커밋 · 푸시는 사용자가 요청할 때만 한다.
- 8788 서버와 `app/web/dist`는 건드리지 않는다. 확인은 격리 인스턴스(별도 포트 · 별도 DB 경로)로 한다.

## 7. 내가 정한 것 (사용자 확인이 필요한 판단)

사용자가 말하지 않아 내가 정했다. 틀리면 고친다.

1. 히스토리는 필터 없이 한 목록, 카드에 종류 표시만.
2. 기존 저장 레이아웃 · 장표는 지우지 않고 계속 동작하게 둔다. Storyboard 창에서 계속 고를 수 있다.
3. 레이아웃 편집 창은 없애지 않고 Storyboard의 조감도 장으로 옮긴다.
4. Storyboard 기반 시작에서 공간 구성이 없으면 그 자리에서 자동 추론(첫 후보)한다.
5. Storyboard 기반 건물은 "공간 하나 = 한 층".
6. 왼쪽 카드가 없어지므로 공간 추가 · 삭제도 명령으로 한다.
7. "오른쪽 · 왼쪽"은 화면 기준, 거리를 말하지 않으면 1m.
8. 마우스 조작은 말풍선 버튼(회전 · 복제)과 단축키로 더한다.
9. 건물에서는 명령 입력창을 아예 보이지 않게 한다.
10. 건물에 넣은 내 공간은 넣는 순간의 사본이다(원본을 고쳐도 건물은 그대로).
11. "합친다"는 여러 공간을 층으로 쌓아 한 건물로 만드는 것으로 봤다. 한 층 안에 여러 조감도를 나란히 붙이는 것은 넣지 않았다.
12. Decision 경로는 "요청 하나 + 대상이 모두 태그된 명령"만 맡고, 나머지와 확신도가 낮은 것은 LLM 경로로 넘긴다.
13. 사람은 "사람 연출"(사람 + 딸린 소품) 묶음 단위로 태깅 · 복제 · 이동한다. 가구에 앉혀진 사람만 떼어 조작하는 것은 넣지 않았다.
14. 빈 스튜디오는 시작 팝업에서 업종을 고른다. 시작한 뒤 업종 변경은 없다.
15. Storyboard 기반으로 만든 조감도는 그 제안서의 조감도로 등록된다. 그래서 그 제안서의 빈 조감도 장이 자동으로 채워진다.
16. 공간 이름 · 용도 바꾸기도 명령으로 한다.
17. 예전 초안(장면 없이 입력만 있는 것)은 열 때 그 입력으로 장면을 만든다. 장면이 있는 기록은 장면을 기준으로 한다.
18. 스튜디오는 Storyboard 위 팝업(오늘 다른 세션에서 추가된 동작)에서도 같게 동작한다.

## 8. 만드는 사람에게 맡기는 것
- 파일 나누기, 컴포넌트 · 함수 이름, CSS.
- 시작 팝업의 단계 표현(한 화면에 펼칠지, 단계로 넘길지).
- Decision 경로의 질문 문구와 확신도 기준(실제 모델로 맞춘다).
- 통합 목록의 페이지 병합 구현.
- 작업 순서. 다만 각 단계가 끝날 때 앱이 동작하는 상태여야 한다.

- 통합 목록에는 예전 목록의 보기 전용 「제품 · 가구 오브젝트」 버튼을 그대로 둔다. 목록은 첫 읽기가 끝난 뒤에 카드를 그리고, 스튜디오에 다녀와도 보던 쪽으로 돌아온다.
- 시작 팝업의 템플릿 갤러리는 기본 썸네일(2D · 3D) 선택을 계정마다 기억한다(예전 창과 같은 키).
- 태그 목록에서 배치된 제품은 「제품」 묶음의 맨 앞에 나온다(배치된 가구 · 사람은 「오브젝트」).
- 스튜디오 「레이아웃 추출」을 거치던 UI 테스트 두 개는 지우고, Storyboard 쪽 테스트가 편집 · 닫기 확인 · 이어 고치기를 본다.
