# 검토 평가 기준 v3 — 2026-10-20

이 문서는 이전 점수 방식의 기록이다. 현재의 정밀 채점 방식은 `review-criteria-v4.md`를 따른다.

사용자가 지정한 네 카테고리와 각 여섯 항목으로 현재 검토 기준을 교체했다. 항목 이름과 순서를 그대로 사용한다. 별도 배점이 없어 영역은 각 25%, 영역 안의 여섯 항목은 동일 중요도 1로 둔다. 적용·채점되지 않은 영역은 종합 점수에서 제외하고 남은 가중치를 다시 나눈다. 점수 체계는 실제 AI의 1·2·3점을 0·50·100으로 변환하는 기존 방식을 유지한다.

| 카테고리 | 기준 ID | 상세 항목 |
| --- | --- | --- |
| 고객·사업기회 이해도 | CU1–CU6 | 고객 정보의 정확성 / 현장·업종 과제의 구체성 / 고객의 사업 목표와 제안 목적의 연결 / 의사결정자별 관심사 반영 / 고객 요구사항 반영의 충실도 / 고객의 시장·산업 환경 분석의 적절성 |
| 제안 제품/솔루션/서비스 실행성 | PR1–PR6 | 제안 제품·솔루션의 용도 적합성 / 제품명·사양·구성의 정확성 / 제품-솔루션-서비스 간 연계의 완결성 / 적용 공간·운영 환경과의 적합성 / 도입 범위·전제조건의 명확성 / 당사 실행 일정·역할·위험 대응의 구체성 |
| 스토리라인·경쟁력 | VS1–VS6 | 핵심 가치 제안의 명확성과 논리성 / 기대효과의 정량성과 계산 타당성 / 고객 투자 대비 효과의 설득력 / 경쟁 대안 대비 차별성(Why Samsung) / 유관 사례·실증 결과데이터와의 관련성 / 도입 후 운영·확장 가치의 제시 |
| 완성도 | DQ1–DQ6 | 수치·단위·계산의 정확성 / 근거 데이터의 최신성과 출처 명시 / 템플릿 잔여물, 오타, 용어통일성 / 기밀이나 고지 정확성 / 레이아웃·시각자료·정보량의 가독성 / 문장·용어·시각 스타일의 디자인 일관성 |

`app/web/src/domain/review/schema.json`을 UI·API·Agent KB의 공통 기준으로 사용한다. 각 항목에 확인할 점, 1·2·3점 앵커, 중복 평가를 방지하는 담당 범위를 명시했다. 시장·산업의 분석 적절성은 CU6, 날짜와 출처는 DQ2, 효과 산식의 가정은 VS2, 산술·단위 오류는 DQ1에서 평가한다. 템플릿·오타·명칭 표기 통일은 DQ3, 문체·설명 수준·시각 체계는 DQ6으로 구분한다. 확인할 수 없는 화면·사실·법적 의무는 추정하지 않는다.

홈 느낌표 버튼은 네 카테고리와 24개 전체 항목을 제공한다. 상세는 여섯 축의 스파이더 차트 네 개를 사용하며, 14px 항목명과 차트 바깥의 hover 설명을 유지한다. 긴 항목명이 위아래에서 잘리지 않도록 실제 줄 수에 맞는 여백을 확보했다. 모바일 요약 점수는 2×2로 표시한다.

기존 v1 7영역·54항목, v2 5영역·26항목의 이름·배점·점수는 당시 기준으로 보존한다. `schema-v2.json`과 `criteria-v1.js`는 해당 기록용 참조다. 재평가할 때만 이전 버전을 명시해 선택 항목을 현재 기준으로 대응시킨다. ID가 같아도 뜻이 바뀐 CU2·PR3·DQ1 등의 이전 선택을 새 의미로 잘못 해석하지 않는다. 시뮬레이션의 기존 기준은 별도 참조를 유지한다.

## 개선한 연결 예시

기존 카페·호텔·대학 원본 레이아웃에 각각 네 장을 보강했다. 고객 목표와 의사결정자, 당사 일정·역할·위험 대응, 파일럿 투자·민감도, 근거·고지·검증 범위를 다룬다. 가상 고객·시장 자료·금융 가정임을 장표에 명시하고, 실제 조사·확정 견적·보장 실적으로 표시하지 않는다. 기본 Best Scenario 라이브러리와 수집 자료는 수정하지 않는다.

| 원본 시나리오 | 개선 장표 수 | 새 검토 ID | 실제 AI 종합 점수 |
| --- | ---: | --- | ---: |
| bs01 카페 | 22 | r_linked_example_bs01_v3 | 100 |
| bs21 호텔 | 41 | r_linked_example_bs21_v3 | 94 |
| bs03 대학 | 19 | r_linked_example_bs03_v3 | 96 |

각 예시의 전체 본문·도형 측정값과 실제 화면 네 장으로 24개 기준 모두를 실제 서버 모델에 재평가했다. 점수를 수동 변경하지 않았다. 세 건 모두 모델 호출 네 건이 성공했고 대체·실패는 없었다. 예시 점수는 가상 제안서에 대한 모델의 평가이며 실재 고객의 사업 검증 결과는 아니다. 원본 ID·결과·모델 이력·화면 해시는 `migration/evidence/linked-review-examples.json`에 있다. v2 모델 결과와 화면도 참조 자료로 보존했다.

관리자 브라우저의 seed marker를 `admin-linked-review-examples-3`으로 올려 수정하지 않은 v1/v2 기본 검토만 새 예시로 교체한다. 수정한 검토 또는 수정한 연결 원본은 기존 평가와 함께 보존한다. 기존 제안서 원본·개인 기록도 유지하며, 새 예시는 별도의 원본 ID에 연결한다. 완료 후 삭제한 예시를 새로고침으로 되살리지 않는다. 다른 계정에는 예시를 넣지 않고, 열람·교체 시 모델을 다시 호출하지 않는다.

`make test`, `node app/tests/review-report.mjs`, `node app/tests/linked-review-examples.mjs`, `npm --prefix app/web run build`를 사용한다.
