# 제품·반복 영역 개수에 맞춘 PPT 레이아웃 개선

2026-10-20. `레이아웃 수정`의 우측 속성 패널에서 1~8개를 지정하고 `레이아웃 개선하기`를 누른다. AI 개선안과 원본을 비교한 뒤 `개선안 적용`한다. 적용은 되돌리기/다시 하기를 지원하며 저장 시 새 My 템플릿으로 보관한다. 기존 My 템플릿을 다시 개선해도 새 `f`를 사용하므로 이미 저장된 장의 칸 번호와 overrides를 바꾸지 않는다.

앞쪽 기존 제품을 유지하고, 줄어든 개수만큼 뒤 제품을 제외한다. 늘어난 제품은 이미지·모델명·사양·설치 위치 입력 칸으로 제공한다. 알려지지 않은 제품이나 사양을 생성하지 않는다. 제품 수가 많은 경우에는 분류 태그와 모델명을 한 줄로 묶는 등 원래 사진/제품 컷 구조를 유지하면서 세로 공간을 확보한다. 제목의 개수 표현과 더 이상 유효하지 않은 수량 합계도 조정한다.

## 구현과 품질 제약

- `app/web/src/services/layout-reflow.js`: 실제 1280×720 DOM과 사진으로 원본 반복 그룹을 분석한다. 실제 Gemini API가 영역·공통 스타일·개별 좌표를 설계하고 측정 피드백으로 보완한다. 마지막으로 별도 AI 구성 검토를 수행한다. API 오류나 검증 실패를 임의의 성공 결과로 대체하지 않는다.
- 기존 제품 문구는 원본 ID로 참조한다. 렌더러가 원래 글자 크기·색·위치에서 제목/분류/사양/용도/수량 계층을 읽어 문구를 보존한다. API가 원문을 다시 생성할 필요가 없도록 설계를 간소화했다.
- 사진 ID·제품 식별 정보·원본 사진과 제품 컷을 유지한다. 인셋(PIP), 파란 수량 배지, 회색 카드 패널, 원본 비율의 가로/세로 제품 컷, 공용 설치 사진과 남은 위치 핀을 보존한다. 축소 시 불필요해진 위치 핀을 제거한다.
- 비교표에서 3개 이상 공유하는 사양 라벨이 있으면 새 제품에도 같은 비교 행을 빈 값으로 제공한다. 알려진 파란 강조색, 행 구분선과 세 열의 기준선을 유지한다.
- 정확한 개수, 동일 제품 카드의 균일한 크기, 고립된 작은 마지막 행 방지, 카드 경계/겹침, 본문·이미지 겹침, 글자 넘침, 이미지 최소 크기, 제목 18px/본문 13px 이상, 반복 영역 점유율 72% 이상을 검사한다. 새 사진의 크롭은 원본 가시 영역의 75% 이상을 보존해야 한다. 검사를 통과하지 못하면 원본을 유지한다.
- `layout-reflow.jsx`: 진행·취소·오류 표시, 전후 비교, 원본 변경 감지. 편집 배율 변경을 정규화하며 설계 중 문서가 바뀌면 이전 개선안을 적용하지 않는다.
- `mytpl.jsx`: 편집 이력, 새 My 저장, 제품/이미지/빈 칸 메타데이터 연결. 저장 후 재접속해도 구조와 콘텐츠를 복원한다.

My 템플릿은 개인 저장소에 동적으로 등록한다. 고정 라이브러리의 원본 `f`, 카탈로그 건수, 정본 자료 및 Agent KB 항목 수는 변경하지 않는다. 정본 `app/data/static`의 심볼릭 링크를 통한 쓰기는 하지 않았다.

## 실제 API 실험

테스트 서버는 현재 앱의 실제 provider 설정을 사용한다. 인증·공유 저장소는 임시 디렉터리의 합성 테스트 계정으로 격리하며 실제 사용자 계정/히스토리를 수정하지 않는다. 성공 모델 응답을 가짜로 주입하지 않았으며 실제 모델명과 사용량은 실행 보고서에 남긴다.

원본 디자인 견본은 `L_PH_P3_A`(3개 사진+제품 컷), `L_PH_P5_A`(5개·수량 배지), `L_PH_P2_C`(2개 비교), `L_P3B`(공용 공간 사진+3개 제품 목록)이다. 1280×720 PNG, 모델 설계 JSON, 최종 HTML을 `app/tests/output/layout-refine/`에 저장한다. 실행 중 실패한 실험도 각 시점의 `live-report-*.json`에 보존한다.

긴 한국어 설명을 원본에 넣어 꼬리말까지 넘치게 한 뒤에도 실제 API로 3개→4개를 재설계해, 전체 문구 보존과 넘침/크롭 검사를 통과했다.

초기 실험에서는 추가 입력 칸/의도적 제품 축소를 오류로 판단하는 평가, 잘리는 6개 가로 사진, 사라진 수량 배지·회색 패널, 인셋 비례, 비교표 신규 열의 사양 행 누락과 강조색 손실, 복잡한 API 응답의 지연을 발견했다. 평가 목적을 정정하고 원문 참조 렌더링, 원본 패널·배지 보존, native 사진 비율 검사, 3행 가로 카드, 간소화된 좌표 응답으로 보완했다. 일부 provider HTTP 500/502 응답도 실제 관측했으며 원본을 유지한 후 재실행했다.

독립 이미지 평가는 실제 원본/결과 PNG 두 장을 Gemini vision 모델에 전달한다. 읽기·피사체 식별·잘림·스타일·정렬·균형 여섯 항목, 정확한 보이는 개수, 중대한 결함 없음과 적합 판정을 요구한다. 초기에 동일 원본 점수가 호출마다 7~9로 변해 점수 차이 0.5만으로 합불을 정하는 방식은 사용하지 않는다. 원본/결과 점수는 참고값으로 그대로 기록하고 구체적인 결함과 여섯 항목을 판단 근거로 삼는다. 첫 6개 변형의 실제 크롭 결함은 Gemini와 Claude Opus 교차 검토 모두에서 확인하고 수정했다.

최종 실험 집계는 같은 폴더의 `final-evaluation.json`을 참조한다. 모델의 구성 점수와 실제 이미지 평가 점수는 서로 다른 지표다.

## 최종 검증 결과

- 실제 API로 원본 4종의 변형 12개를 생성하고 최종 PNG의 해시와 평가 대상을 대조했다. 목표 1~8개를 모두 포함한다.
- 12개 모두 영역·겹침·넘침·사진 크롭 검사를 통과했다. 반복 영역 점유율은 76.7~100%다.
- 11개는 Gemini의 여섯 시각 항목을 모두 통과했다. 7개 배치의 Gemini 평가는 카드 크기가 다르고 사진이 늘어났다고 판단했지만, 실제 DOM은 모든 카드가 276×244이며 cover/contain을 사용했다. 원래 거절 결과를 그대로 보존하고 직접 픽셀 검토와 별도 Claude Opus 검토로 교차 판정했다. Claude는 여섯 항목을 모두 통과, 중대 결함 없음으로 평가했다. 사진 세부와 제품 컷이 작아지고 행 간격이 좁아지는 점은 남은 경미한 제약으로 기록했다.
- 원문을 길게 바꿔 기존 장에서 넘치던 한국어 설명도 실제 API 3개→4개 실험에서 전체 보존·넘침/크롭 검사를 통과했다(영역 활용 93.8%).
- 실제 UI의 비교→적용→undo/redo→My 저장→reload→재개선 시 별도 My 복사를 통과했다. 기존 템플릿과 원래 My HTML/칸 번호는 유지됐다.
- 최종 12장 PPTX 내보내기/재가져오기를 통과했다. 텍스트 346개와 사진 65개가 독립 편집 요소로 남고, 텍스트 교체·이미지 keep·사진 식별 정보·실제 교체 이미지 임베딩도 검증했다.

## 재현

실제 API 사용과 과금이 발생한다.

```sh
node app/tests/layout-reflow.mjs L_PH_P5_A:6 L_PH_P3_A:6 L_P3B:2 L_PH_P3_A:1 L_PH_P3_A:8 L_PH_P3_A:2 L_PH_P3_A:4 L_PH_P5_A:2 L_PH_P5_A:4 L_PH_P2_C:3 --ui --export
node app/tests/layout-reflow.mjs L_PH_P3_A:5 L_PH_P3_A:7
app/.venv/bin/python -B app/tests/layout-reflow-vision.py L_PH_P3_A:1 L_PH_P3_A:2 L_PH_P3_A:4 L_PH_P3_A:5 L_PH_P3_A:6 L_PH_P3_A:7 L_PH_P3_A:8 L_PH_P5_A:2 L_PH_P5_A:4 L_PH_P5_A:6 L_PH_P2_C:3 L_P3B:2
node app/tests/layout-reflow.mjs --export
node app/tests/layout-reflow.mjs --long
app/.venv/bin/python -B app/tests/layout-reflow-report.py
node app/tests/layout-editor.mjs
npm --prefix app/web run build
```

`--refresh`는 저장된 실제 모델의 좌표·스타일 설계를 최신 원문 참조 렌더러로 다시 그린다. 모델 응답을 꾸며내거나 실패한 모델 요청을 대체하지 않으며, 이전 PNG/JSON은 iterations에 보존한다. 제품 컷 비율 보정 후 이 방식으로 12개 변형을 다시 렌더하고 측정·이미지 평가·PPTX를 재검증했다.

`--ui`는 실제 버튼 → API → 비교 → 적용 → undo/redo → My 저장 → reload → My 재개선 시 별도 `f` 저장을 검증한다. `--export`는 실제 성공 결과들을 편집 가능한 PPTX로 내보내 재가져오고, 텍스트/사진 요소·칸 수정·이미지 keep 및 식별 정보·교체 사진 임베딩을 확인한다. 최종 내보내기 결과는 `count-reflow-editable.pptx`, `pptx-roundtrip.json/png`이다. 기존 편집 회귀 검사의 API 격리는 별도이며 개수 개선의 성공 증거로 사용하지 않는다.
