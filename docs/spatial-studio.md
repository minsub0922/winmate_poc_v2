# 공간 조감도 스튜디오

새 스튜디오는 `POST /api/spatial/drafts`로 빈 초안을 만든 뒤 `/spatial/{id}`에서 열린다. 진입 버튼은 목록 페이지에만 표시하며 편집 페이지에서는 제거한다. 시작할 때 업종·공간 목록은 비어 있고 캔버스에는 아무 장면도 생성하지 않는다. 업종 선택은 분류 입력이며, **업종 템플릿**은 이미 구성된 조감도와 공간·제품 입력을 함께 연다. 템플릿 카드와 같은 공간 경계·제품·가구 좌표를 즉시 2D/3D로 표시하고 저장한다.

공간별로 이름·용도·제품·수량을 입력하고 선택적으로 실제 가로·세로·좌석 수를 지정한다. 생성기는 입력된 공간과 삼성 제품만 사용하고 추가 가구와 동선을 자동 구성한다. 입력 폼은 ID별로 계정에 자동 저장되며 빈 초안도 새로고침으로 복구된다. 기존 조감도에서 입력만 바꾼 경우에는 이전 렌더를 유지하고 재생성을 안내한다. 기존 히스토리·관리자 예시는 저장된 장면을 바로 표시하며 필요한 입력 폼은 장면 데이터에서 가져온다. 기존 장면이 있으면 공간·제품 수와 면적을 표시한다. 히스토리를 요청하는 동안에는 로딩 표시만 보여 주며 건수·빈 목록 안내는 성공 응답 후에 표시한다. 실패는 별도 오류·다시 불러오기로 안내하고, 늦게 도착한 이전 응답은 최신 목록을 덮어쓰지 않는다. 과거에 장면 없이 입력만 저장된 템플릿 히스토리는 연결된 기본 장면을 한 번 복원해 저장하고 준비 상태·미리보기를 갱신한다. 복원은 사용자별로 처리하며 입력 변경, 문서 ID·수정 버전·시간을 보존한다. 이미 저장된 장면과 `assetRevision`은 덮어쓰지 않는다.

추가 검증은 `node app/tests/spatial-studio-form.mjs`와 `node app/tests/spatial-studio-flow-ui.mjs`이다. 후자는 `WINMATE_API_PORT=8977`, 별도 `WINMATE_AUTH_DIR`·`WINMATE_SPATIAL_DB`로 실행한 `app/tests/fixtures/spatial/server.py`를 사용한다. 브라우저에서는 ID 경로·빈 시작·공간별 제품/수량 입력·명시적 생성·입력 자동 저장·업종 템플릿·모바일·뒤로 가기를 검사한다.

가구 배치는 앞 방향(`frontAxis`)과 사용 관계(`facing`)를 함께 저장한다. 의자는 연결된 책상·회의 테이블·무대·환자 침상을, 소파는 낮은 대화 테이블을, 모니터는 실제 착석 위치를 바라본다. 회전 양수 90°는 평면도의 +Z 앞 방향을 -X로 돌린다는 규칙을 SVG와 Three.js에서 공통으로 사용한다.

업무석의 행 간격은 의자 뒤 이동 공간을 포함해 2.25m로 잡으며, 장식물·바닥 제품을 배치할 때 의자 뒤 0.7m를 비워 둔다. 카페 의자·아일랜드 스툴·방문객 의자·소파는 가구의 실제 크기에 맞춘 간격을 사용한다. 이 수치는 앱의 배치 디자인 정책이며 건축 법규 적합성 판정이 아니다.

스튜디오의 **자연스럽게 정리**는 방향, 가구 간 거리, 의자 뒤 여유를 검사·보정한다. 책상이나 테이블을 옮기거나 회전하면 연결된 의자와 모니터가 같이 따라온다. 과거 버전 장면을 열면 당시 오브젝트 버전으로 배치를 보정하고 원본을 실행 취소에 남긴다. 수정 사항은 사용자가 저장할 때 히스토리에 반영된다. 기본 맵 680개와 생성된 방향·간격 관계를 전수 검사한다. 검사 명령은 `node app/tests/spatial-naturalness.mjs`이며, UI 검사는 별도 8795 포트의 시험 서버에서 `node app/tests/spatial-naturalness-ui.mjs`로 실행한다.

사이드바의 **공간 조감도** 또는 `/spatial`에서 사용한다. 기존 라이브러리의 `tl-head` 제목·상단 구조와 같은 헤더를 사용한다. `/spatial/{historyId}`는 로그인한 계정의 저장 장면을 연다.

기본 화면은 헤더 → 큰 **조감도 스튜디오** 버튼 → **공간맵 라이브러리** → **조감도 히스토리** 순서다. 공간맵은 홈에서 대표 3개를 먼저 보여주고 **전체 보기**로 검색·업종·범위·크기 필터를 갖춘 전체 목록 팝업을 연다. 전체 보기 팝업의 **기본 썸네일 2D / 3D** 선택은 목록 전체와 이후 검색·추가 표시 항목에 적용되며 계정별 브라우저 설정에 보관한다. 개별 카드의 보기 전환도 유지한다. 3D 썸네일은 화면에 들어온 카드부터 렌더링한다. 카드 전체나 이미지는 클릭으로 이동하지 않는다. 각 카드의 **2D / 3D** 버튼이 실제 평면도와 조감도 썸네일을 전환하며, 사진 오른쪽 아래의 파란 **입력에 활용** 버튼 → **스튜디오로 이동할까요?** 확인 팝업 → **스튜디오로 이동** 순서로 입력을 시작한다. 취소하면 스튜디오를 생성하거나 기존 입력을 바꾸지 않으며, 전체 보기 팝업의 필터도 유지한다. 기존 스튜디오에서 선택하면 현재 조감도와 입력이 선택한 템플릿으로 바뀐다는 안내를 표시한다. 3D 미리보기는 같은 장면·렌더러로 생성해 캐시하고 순차 렌더링한다.

목록 화면에는 공간 조감도 헤더를 유지하고, 스튜디오에서는 헤더 왼쪽을 **뒤로 가기**로 바꾼다. 오른쪽 **제품 · 가구 오브젝트**는 펼침 화살표 없이 강조한 버튼이며, 누르면 오른쪽에서 화면 전체 높이의 패널을 연다. 목록 화면에서는 조회·상세 보기만 가능하다. 현재 스튜디오에서는 제품·가구를 여러 개 선택하고 검색·필터를 바꿔도 선택을 유지한다. 하단에서 대상 공간과 **선택한 N개 추가**를 누르면 입력과 생성된 장면에 함께 추가·저장한다. 추가 실패 시 기존 입력·장면은 바꾸지 않으며 선택을 유지해 다시 시도할 수 있다. 제품 사진·상세 호버와 모델 선택을 지원한다.

오브젝트는 모델 번호를 제외한 제품명과 형상 레시피가 같은 항목을 카드 하나로 묶는다. 원래 자산 ID·모델별 치수·장면 참조는 보존하며 검색은 전체 제품명·모델·연관 모델 번호에 적용한다. 검색 결과를 선택하면 일치한 제품을 배치한다. 모든 오브젝트 카드 썸네일은 같은 렌더러로 미리 만든 형상 이미지(`public/assets/spatial-objects/`)다. 히스토리 썸네일 파일을 받지 못하면 저장된 장면의 2D 평면도를 표시한다. `build:spatial-previews`는 관리자 예시와 오브젝트 썸네일을 함께 갱신한다.

조감도 위의 저장·더 보기·공간 이름 컨트롤은 표시하지 않는다. 입력은 자동 저장하며, 레이아웃 편집은 팝업의 **저장하기**를 눌렀을 때 공간 조감도 홈의 **Layout 히스토리**에 반영한다. 저장·닫기·취소 화면에 저장 위치 안내문을 표시하지 않고, 저장에 성공했을 때만 **Layout 히스토리에 저장됐어요.** 토스트를 표시한다. **뒤로 가기**로 조감도 목록에 돌아갈 때도 장면 변경을 저장한다. 저장 장면의 직접 URL은 편집 화면을 연다.

스튜디오 제목 아래의 공간 수·제품 수·면적은 왼쪽에 정렬하고 오른쪽에 큰 **Layout 추출** 버튼을 표시한다. 추출 초기화 버튼은 표시하지 않는다. 버튼은 1280×720 레이아웃 편집 팝업을 연다. 레이아웃 영역 내부 중앙 상단의 **+ 설명 상자 추가**로 둥근 설명 영역을 만들고, **공간 이름 배치** 모드에서 맵의 공간명을 눌러 이름 오브젝트를 추가한다. **원형 포인팅**으로 다시 전환할 수 있으며 기본값은 원형 포인팅이다. 일반 텍스트 추가 버튼은 표시하지 않으며 기존 텍스트 오브젝트는 호환한다.

연결 대상 **공간 / 제품 / 가구** 세 버튼은 레이아웃 우측 상단에 있고 기본 선택은 공간이다. **원형 포인팅 / 공간 이름 배치**는 공간이 선택된 경우에만 그 버튼들 바로 아래에 표시하며 제품·가구를 선택하면 숨긴다. 모드 버튼과 설명 상자 추가는 팝업 상단 툴바에 표시하지 않으며, 레이아웃 SVG나 저장 결과에 편집용 버튼을 포함하지 않는다. 기본적으로 공간·제품·가구는 작은 원형 포인팅으로 표시한다. 별도의 공간 이름 배치 모드에서는 공간명을 표시하고, 클릭해 배치해도 원래 라벨의 박스·글자 크기를 유지한다. 모드 전환이나 기존 이름 선택으로 배치한 요소의 크기를 바꾸지 않는다. 설명 상자를 선택하고 맵에서 여러 대상을 직접 눌러 연결한다. 연결 검색·체크 목록·연결 칩·선택 삭제 버튼은 표시하지 않는다. 영역은 드래그로 이동하고 오른쪽 아래 손잡이로 크기를 바꾼다. 마우스 오른쪽 클릭의 삭제 메뉴와 Delete 키를 지원하며 영구 삭제·연결 해제는 공용 확인 동작을 따른다.

오른쪽의 **조감도 각도**에서 회전 각도·위에서 보는 각도·확대를 바꾸면 이미지·포인팅·연결선 끝점이 실시간으로 갱신된다. 설명 상자는 배치 위치를 유지하고 공간명 오브젝트는 연결된 공간과 함께 투영 위치를 따라간다. 2D/3D 전환도 지원한다. 조감도 외부의 회색 배경과 그림자용 큰 바닥을 제거하고 투명 PNG와 흰 레이아웃 표면을 사용한다. 원래 제품·가구의 좌표와 자산 버전은 바꾸지 않는다.

레이아웃 저장본은 개인 My 템플릿의 `my.spatialLayout`에 `renderVersion: 2`, 원본 장면 `sourceScene`, 카메라·투영 좌표·설명 영역을 보관하고 이미지는 별도 IndexedDB 참조를 쓴다. 과거 `scene.presentation.layout`은 읽기 호환만 유지한다. 원본 장면에서는 `presentation`을 제외해 레이아웃이 중첩되지 않게 한다. 각도 조정 중 프레임 갱신은 실행 취소 항목을 늘리지 않으며 조정 완료 시 이전 시점을 남긴다. **레이아웃 SVG 다운로드**는 최신 각도의 이미지·텍스트·도형·꺾은선·공간명을 내보내고 편집 컨트롤을 제외한다. 팝업 편집은 조감도 장면과 분리한 임시 상태다. **저장하기**는 최신 프레임을 확정하고 조감도 이미지·독립 텍스트 칸·둥근 상자·연결선을 개인 My 템플릿 저장소에 저장한다. 닫기·닫기 아이콘·Escape·팝업 바깥 클릭은 서버 히스토리를 저장하지 않는다. 저장하지 않은 변경이 있으면 **계속 편집 / 저장하지 않고 닫기** 팝업에서 확인하며, 취소하면 편집을 유지한다. 저장본과 변경이 없으면 바로 닫는다. 저장 장면을 다시 열어도 팝업은 자동으로 열리지 않으며 **Layout 추출**로 같은 조감도의 마지막 My 저장본을 불러와 편집을 이어간다. 개인 저장본은 `L_MY_` ID, `data-tb`·`data-img` 슬롯으로 등록하고 이미지는 IndexedDB `wmimg` 참조로 보관한다. 동일한 슬롯 구조의 수정은 같은 개인 템플릿을 갱신하며, 영역 추가·삭제처럼 슬롯 구조가 바뀌면 새 ID를 만들어 이전 장표 참조를 보존한다.

각도 조정의 **원래 각도로** 버튼은 추출 당시의 회전·위에서 보는 각도·확대와 카메라 프레이밍을 함께 복원한다. `initialCamera`를 개인 저장본에 보존하므로 각도를 수정해 저장한 뒤 다시 열어도 같은 원본 시점으로 돌아간다. 원본 시점 정보가 없는 예전 저장본은 처음 열었을 때의 시점을 기준으로 한다. 복원은 실행 취소·다시 실행이 가능하고 설명 상자·연결 대상을 유지하며 공간 이름과 연결선의 투영 좌표를 다시 맞춘다. 2D 보기나 3D 준비 중에는 버튼을 비활성화한다.

레이아웃 검증은 `node app/tests/spatial-layout.mjs`로 실행한다. 브라우저 검증은 8817 포트의 독립 시험 서버(시험 전용 인증·DB)를 띄운 뒤 `node app/tests/spatial-layout-ui.mjs`로 실행한다. 3D/2D 추출, 복수 공간·제품 연결, 이동·크기 조절, 실행 취소/다시 실행, SVG, 저장·재열기, 모바일을 검사한다.

## 준비된 자산

사람과 가구·도구를 묶은 정적 연출 **144종 / 9개 분류 / 37개 직종·역할**을 추가했다. `people-scenes.js`는 인체 자세·복장 표지와 의자·책상·교탁·비전원 칠판·침상·카트 등을 실제 미터 좌표로 조합하며, 생성기가 묶음의 정확한 외곽을 계산한다. 의사·환자 문진/진찰/회진, 교탁 앞 교사, 높고 낮은 위치 판서, 필기/독서/손들기 학생, 카페·호텔·매장·현장·공공 등의 직종을 구분한다. 의상은 `people-costumes.js`에서 직종별로 관리한다. 진료복·스크럽·재킷·가디건·포켓 앞치마·작업복·반사 조끼와 안경·보호 안경·명찰·스카프·청진기·공구 벨트·직종별 모자를 실제 부품으로 조합한다. 피부톤 5가지와 머리 형태 6가지를 복장과 별도로 바꾸며 실제 인물 자료는 사용하지 않는다. 사서·약사·연구원·치과 의료진·제빵사·미술 강사·정원 관리사·정비사를 포함한다.

식사·급식·조식·음료·간식·주문·소파 독서·기지개·그림 지도·분갈이·물주기 등 64종을 더했다. 식사에는 밥·반찬·그릇·식판과 숟가락·젓가락을 입으로 드는 동작이 함께 있다. 자세만 바꾸지 않고 공간의 용도를 보여주는 소품과 가구를 함께 구성한다.

오브젝트 목록의 **사람 · 직종 연출** 필터에서 직종·행동·업종·공간·복장·액세서리로 찾는다. 카드에 마우스를 올리면 연출 썸네일과 각 인물의 복장·액세서리 상세를 확인한다. 기존 공용 가구·소품 219종과 별도로 집계하며, 모든 사람 연출에 가구가 포함된다. `people:` ID와 전용 레시피를 쓰고 한 묶음을 함께 배치·이동·회전·삭제한다. 선택한 연출은 공간 입력과 저장 장면에 남아 재생성에서도 유지된다. 삼성 제품은 별도로 선택하며 묶음 내부에는 전기 가전·디스플레이를 넣지 않는다. GLB에는 직종·의상·액세서리·구성 메타데이터도 저장한다.

디테일 소품 73종을 더해 공개 공용 목록은 **219종 / 11개 분류**다. 추가 항목은 러그·바닥 매트 18종, 컵·식기·테이블 소품 24종, 책·문구·데스크 소품 14종, 패브릭·생활 장식 17종이다. `detail-objects.js`는 형상·설계 치수·업종·설명·배치 면을 정의하고 `detail-placement.js`는 배치와 받침 검증을 맡는다.

러그는 가구 아래에 놓을 수 있으며 자동 배치에서는 기존 러그와 같은 높이에 겹치지 않는 위치를 고른다. 컵·식기는 테이블·트레이 등 허용된 받침 위에 놓고, 상판이 없으면 바닥에 대신 놓지 않고 필요한 가구를 안내한다. 소파·침상의 쿠션은 중심 좌판/침상 형상에서 계산한 높이를 사용한다. 테이블 → 트레이 → 컵의 다단 받침은 이동·회전·삭제에서 함께 처리한다. 얇은 문구·접시도 서로 겹치지 않도록 작은 소품에 맞춘 수직 허용 오차와 간격을 사용하며, 저장 API가 같은 받침·높이·영역·충돌 조건을 검사한다.

`node app/tests/spatial-details.mjs`와 별도 8805 포트의 시험 서버에서 `node app/tests/spatial-details-ui.mjs`로 배치·저장·재열기·PNG·GLB를 확인한다. 검토표는 `app/tests/output/spatial-details/index.html`, 목록·썸네일의 대응 버전은 같은 폴더의 `audit.json`에 기록한다. 신규 소품은 삼성 제품이 아닌 자체 설계 형상이다.

공용 가구는 새 형상 118종을 추가한 **공개 목록 146종**이다. 의자·좌석, 벤치·연결 좌석, 소파·라운지, 책상·테이블, 수납·진열·운반, 침대·휴식 가구, 공간 구획·비품의 7개 분류를 제공한다. 모든 신규 가구는 제조사 제품이 아닌 자체 설계한 비전동 개념 형상이며, 업종·공간·설명을 검색할 수 있다. `furniture-catalog.js`에 용도, 업종, 검색어, 형상 레시피를 함께 관리한다. 오브젝트에서 **공용 가구 → 가구 종류**로 좁혀 찾는다.

예를 들어 미팅룸의 슬레드 체어, 카페의 곡목 체어, 학교의 학생 의자, 의료 공간의 방문객 의자를 구분한다. 새로 생성하는 공간에서는 일부 좌석을 업종에 맞춰 선택하되 경계·충돌·출입 동선을 만족하지 못하면 기본 가구를 사용한다. 가구 ID와 삼성 제품 ID는 별개이며 새 항목은 삼성 제품과 명칭·전기 기기 품목이 겹치지 않는다. 기존 플로어 램프·펜던트 조명·디스플레이 전용 스탠드 3개는 공용 목록에서 제외하고, 과거 장면과 내부 받침 참조를 위해 자산 자체는 남긴다. 자산 전체는 149종이며 저장 장면의 불변 버전 파일은 보존한다.

가구 전수 검사는 `node app/tests/spatial-furniture.mjs`, 브라우저 검사는 별도 8797 포트의 시험 서버와 `node app/tests/spatial-furniture-ui.mjs`를 사용한다. 새 가구별 실제 추가·저장·SVG·썸네일, 업종별 자동 선택, 삼성 중복 제외, 검색·종류 필터·모바일을 확인한다.

2026-10-20 기준 16개 업종, 공간맵 683개(전체 101 / 개별 582), 기존 공간·제품 장표 재구성 278개, 삼성 카탈로그 오브젝트 1,068개, 공용 가구 146종이다. 기본 맵은 소형·표준·확장 변형을 포함한다. 업종별 공간 이름·역할·제품 문구는 기존 공간 맵 제작 데이터에서 가져와 `app/data/spatial/industry-sources.json`에 보존했다. 공통 장표의 업종을 추론한 경우 `source.industryInferred`로 표시한다. 원본의 명시적 `prods`를 빠짐없이 연결하는 검사가 있다.

모든 형상은 재사용 가능한 기하 레시피와 미터 단위 크기로 미리 정의되어 있다. 삼성 제조사 CAD를 제공하는 기능은 아니다. 원본 사진에는 실측 좌표가 없으므로 기존 사례는 공간 명칭·제품 구성을 보존한 **개념 배치 재구성**이다. 사진과 동일한 실측 복원으로 표시하지 않는다.

## 기본 공간 크기와 6개 구성

표준 템플릿 공간은 10.5 × 9m에서 **9.45 × 8.1m**로 가로·세로를 10%, 면적을 19% 줄였다. 제품·가구·사람 자산의 실제 치수는 유지한다. `template-composition.js`의 버전이 있는 새 템플릿에 적용하며, 기존 저장 장면과 과거 라이브러리는 당시 크기로 열린다. 공간 일부만 선택해도 공간 하나의 실제 크기는 유지한다.

기본 목록은 전체 맵이며 16개 업종의 대표 맵은 모두 **6개 공간 / 3 × 2**다. 관련 기능을 한 공간으로 묶고 원본 공간·제품 참조는 `includedSpaces`에 보존한다. 공유오피스는 프로젝트 룸을 추가해 6개로 구성한다. 다른 전체 맵도 2·4·6개로 정리하고, 4개는 2 × 2로 배치한다. 개별 공간은 사용자가 필터에서 명시적으로 선택할 수 있다. 직접 입력한 공간 수를 임의로 늘리거나 줄이지 않는다.

게시된 최신 버전은 `assets/spatial-current.json`이 가리킨다. 화면은 `/api/spatial/library/{sourceHash}`로 불변 데이터에 연결하므로, 실행 중인 API의 기본 라이브러리가 이전 상태여도 새로고침 후 새 크기와 구성을 표시한다. 이전 저장 장면은 원래 `assetRevision`으로 불러온다.

`node app/tests/spatial-density.mjs`는 전체 장면의 짝수 구성·경계·동선·불변 자산 치수·원본 제품 참조를 검사한다. `node app/tests/spatial-density-ui.mjs`는 별도 8826/5326 포트·계정·DB에서 기본 6개, 실제 2D/3D, 저장·재열기·모바일·PNG/GLB·이전 7개 장면 보존을 검사한다. `SPATIAL_DENSITY_REVIEW_PORT=5226 node app/scripts/review_spatial_density.mjs`의 검토표는 `app/tests/output/spatial-density/index.html`에 있다.

## 업종 템플릿의 사람 자동 배치

공간 용도와 실제 배치 여유에 따라 사람을 자동 배치한다. 집계는 템플릿 구성·크기에 따라 달라지며 최신 생성 결과와 검토 보고서에서 확인한다. 기존 의자·책상·소파·카운터·단상·의료 침상을 활용하며 가구·삼성 제품의 수량·좌표를 바꾸지 않는다. 교실의 교사·학생, 식당의 식사·음료 이용객, 병실·진료 공간의 환자·의료진, 접수의 직원·이용객, 작업장의 작업자·검사 담당자 등을 공간 이름과 업종에 맞춘다. 설비·냉장 보관·외벽 등의 공간과 경계·출입문·다른 사람·제품에 걸리는 배치는 생략한다.

`people-layout.js`가 가구의 `people`에 동결된 사람 자산·개별 배우 참조와 상대 좌표를 저장한다. `people-placement-geometry.js`는 같은 복장·자세를 SVG·Three.js·PNG·GLB·PPT에 전달한다. 식기는 실제 식탁의 상판에 연결한다. 가구 이동·회전에는 사람이 함께 따라가며, 작업 대상 삭제 시 남은 사람 참조를 정리한다. 새 스튜디오 입력의 재생성에서도 적용하고, 수동으로 고른 사람+가구 연출이 있는 공간에는 자동 연출을 덧붙이지 않는다. `peopleLayoutVersion`이 없는 과거 라이브러리와 저장 장면은 그대로 유지한다.

검사는 `node app/tests/spatial-people-layout.mjs`, 별도 계정·DB·8825/5325 포트를 사용하는 `node app/tests/spatial-people-layout-ui.mjs`로 실행한다. `SPATIAL_PEOPLE_REVIEW_PORT=5225 node app/scripts/review_spatial_people_layout.mjs`는 `app/tests/output/spatial-people-layout/index.html`과 업종별·공간별 실제 렌더, 코드 SHA·시작/종료 버전·배치 집계를 만든다.

## 생성·편집·재현

- Three.js(MIT)의 실제 메시·재질·조명·그림자로 3D를 그리고, 같은 장면 JSON을 SVG 2D로 그린다. 이미지 생성 API, 유료 CAD 서비스, 외부 3D 자산 다운로드는 사용하지 않는다.
- 스타일, 공간 범위, 가로·세로를 선택해 즉시 조합하거나 기존 실제 LLM 공급자에 요구사항을 보내 구조화 계획을 받는다. 모델 실패를 규칙 응답으로 성공 처리하지 않는다.
- LLM 계획은 등록된 공간·제품·가구 ID, 좌석 수, 제품 목표 수량, 선택적 공간 내부 좌표를 사용한다. 업무석 1~60석, 회의실 2~14석을 지원하며, 수용할 면적이 부족하면 오류를 표시한다. 30석 업무 공간 + 8석 미팅룸의 실제 생성 검사를 포함한다.
- 공간 경계, 수직 높이, 출입문 여유, 가구·제품 충돌을 브라우저와 저장 API 양쪽에서 검사한다. 거치 가구가 없는 모바일 기기·모니터·전자칠판에는 미리 만든 테이블·스탠드를 함께 배치한다. 가구를 옮기거나 회전하면 받침 위 제품도 같이 움직인다.
- 조감도 아래에는 맵 선택과 프롬프트 입력창을 표시한다. 캔버스 상단에는 보기 전환과 실행 취소·다시 실행만 표시한다. 레이아웃은 별도 팝업에서 편집한다.
- 2D·3D에서 제품·가구를 드래그하면 연결된 가구·제품도 이동 모습을 함께 표시하고, 놓을 때 5cm 단위 좌표와 경계·충돌을 검사한다. 잘못된 위치는 원래 배치를 유지한다. 3D 빈 공간 드래그는 카메라를 회전한다. 오브젝트 선택 위치 옆 팝업에서 공용 제품 상세(사진·특장점·사양), 가구 크기, 공간 내 좌표와 높이를 확인하고 제거하거나 **@ 프롬프트에 넣기**를 누를 수 있다.
- 하단 프롬프트에서 `@`를 입력하면 공간·개별 번호로 구분된 기존 오브젝트와 카탈로그의 새 제품을 검색한다. 화살표와 Enter/Tab으로 참조를 선택하고 Enter로 적용, Shift+Enter로 줄바꿈한다. 제품명·모델명을 직접 입력해 새 제품 추가를 요청할 수도 있다. 실제 공급자의 `/api/spatial/edit` 응답은 현재 장면에 대한 이동·회전·제거·추가·스타일 변경 명령이며 장면 전체를 재생성하지 않는다. 전체 명령의 검증을 통과해야 한 번에 반영하고 한 번의 실행 취소로 복원한다. 실패·취소·없는 제품 확인 요청은 기존 장면과 입력을 유지한다. 별도 입력 폼의 제품 수량·스타일도 직접 편집 결과를 반영한다.
- 장면 JSON으로 복원하고, 2D SVG / 3D PNG / 3D GLB로 내보낸다. 저장 장면의 좌표·크기·레시피·카메라가 재현의 기준이다. GPU·브라우저에 따라 안티앨리어싱 픽셀은 다를 수 있다.

장면은 `assetRevision`으로 불변 오브젝트 버전을 참조한다. 빌드 시 `app/data/spatial/versions/{revision}.json`을 보관하며 같은 버전 파일은 덮어쓰지 않는다. 제품 DB 치수나 기하 레시피가 바뀌어도 과거 히스토리·JSON은 당시 버전의 자산으로 열린다. 이 버전 디렉터리는 배포·백업에서 보존한다.

`app/data/runtime/spatial.sqlite`에 계정별로 저장한다. 저장 API는 계정 경계를 확인하고 수정 버전 충돌은 409로 반환한다. 운영·시험 DB 경로는 `WINMATE_SPATIAL_DB`로 분리한다. 관리자 계정에는 공유오피스, 카페, 호텔, 리테일, 교육, 의료, 금융, 주거, 제조, 개별 미팅룸의 예시 10개를 저장한다. 수정·삭제한 예시는 초기화하지 않는다. 아직 수정하지 않은 예시만 새 기하 데이터로 갱신한다.

## PPT 연결

`L_SPATIAL_2D`, `L_SPATIAL_3D`가 활성 라이브러리와 Agent KB에 등록된다. 디자인은 기존 `L_PH_SS_OF_A`·공간별 제품 계열의 64px 여백, Noto Sans KR, Samsung blue, 1280×720 장표와 `L_SOL_03`의 공간 콜아웃 구조를 따른다. 텍스트 슬롯 17개와 조감도 슬롯 1개를 유지한다.

공간이 6개보다 많으면 콜아웃을 다음 장으로 이어서 모든 공간을 연결한다. 화면과 PPT가 같은 투영 좌표와 이미지 `contain` 변환을 사용한다. 2D의 공간·제품·가구 구성 요소와 연결선은 PowerPoint 도형이며, 3D 렌더 그림과 주변 글·연결선은 각각 독립 요소다. PPTX의 `ppt/embeddings/winmate-spatial.json`에는 사용한 장면·참조 자산·카메라가 들어간다. 글자와 제품 ID를 임의로 바꾸는 AI 채움으로 공간 좌표를 다시 쓰지 않는다. 기존 표준 장표의 저장 데이터는 변경하지 않는다.

PPT 글꼴은 기존 내보내기와 마찬가지로 Noto Sans KR을 지정한다. 받는 PC에 해당 글꼴이 없으면 PowerPoint/LibreOffice가 대체 글꼴을 사용한다.

## 공간 리스트와 삭제 확인

공간별 입력 카드는 번호·여백·헤더와 균일한 테두리로 구분한다. 별도의 왼쪽 컬러 바나 공간별 색상은 사용하지 않는다. 용도 목록의 **직접 입력**으로 목록에 없는 쓰임을 입력하며, `customPurpose`를 초안·장면에 보존하고 장면의 `purpose`에도 반영한다. 내부 `kind`는 재사용 가구 배치 분류로 유지한다. 크기·좌석 수 입력 컨트롤은 표시하지 않고 기존 저장 장면의 치수는 보존한다.

배치 제품 행 왼쪽에는 같은 오브젝트 형상 썸네일을 표시한다. **제품 선택**은 해당 공간 카드 오른쪽에 고정 팝업을 열며, 선택 즉시 입력에 추가하고 팝업을 유지한다. 작은 화면에서는 화면 안에 맞춘다. 선택한 제품을 다시 누르거나 제품·공간의 삭제 버튼을 누르면 먼저 확인 팝업을 표시한다.

공간 카드에서 `@제품명` 또는 `@모델명`을 입력하면 제품 검색 목록이 열린다. 방향키로 선택하고 Enter/Tab 또는 클릭으로 해당 공간에 추가한다. 같은 제품을 다시 선택하면 기존 수량을 유지한다. 검색 문자열 대신 제품 ID·수량만 저장하며, 실제 조감도는 **조감도 만들기**로 생성한다.

선택한 제품 이름·썸네일에 hover 또는 키보드 포커스를 주면 공통 제품 상세 카드 상단에서 해당 모델의 조감도 오브젝트와 카탈로그 원본 이미지를 비교한다. **크게 보기**나 제품 클릭은 동일한 공통 상세 화면을 연다. 생성 후 편집 프롬프트의 선택된 `@` 참조와 오브젝트 카탈로그도 같은 비교를 사용한다. 원본 이미지가 없으면 누락 상태를 표시하고, 제품군 대표 이미지는 그 범위를 함께 표시한다. 모델은 다시 생성하지 않고 버전별 오브젝트 썸네일과 연결된 원본 이미지를 사용한다.

편집 프롬프트의 `@` 참조는 입력문 안에서 이미지·이름·공간/개체 번호가 있는 버블로 표시한다. 실제 DOM 버블의 개체 ID를 기존 `@[label]`·`mentions` 요청으로 직렬화하며, 지운 버블이나 직접 붙여 넣은 문자열에서 개체 ID를 추론하지 않는다. 버블 hover·키보드 포커스는 상세 카드와 정확한 2D/3D 개체 하이라이트를 함께 표시한다. 같은 모델 여러 대는 개별 ID로 구분한다. 카탈로그 참조와 공간별 제품 버블은 해당 공간의 같은 자산을 강조한다. 집중한 공간 밖의 개체는 일시적으로 전체 맵에 표시하고 hover 종료 시 기존 공간 보기를 복원한다.

태깅은 편집 선택 상태를 설정하지 않으며 조감도 위 팝업을 열지 않는다. 직접 클릭해 연 오브젝트 상세에서 **@ 프롬프트에 넣기**를 누르면 버블을 넣고 상세 팝업을 닫는다. 하이라이트는 저장 장면·PNG/PPT 캡처·GLB에 포함하지 않는 임시 표시이고 3D 장면을 다시 만들지 않는다. 공용 가구는 설계 오브젝트 미리보기와 크기를 보여 준다. `node app/tests/spatial-mention-bubbles-ui.mjs`는 별도 8996 인증 fixture와 5296 Vite에서 버블·개체 ID·실제 3D 픽셀 변화·정상/실패 전송·삭제·공간 복원·모바일을 검사한다. 캡처는 `app/tests/output/spatial-mention-bubbles/`에 저장한다.

`node app/tests/spatial-product-mentions.mjs`는 검색·중복·ID 보존·실제 생성 결과를 검사한다. 별도 8979 포트에 인증 fixture 서버를 실행한 뒤 `node app/tests/spatial-product-mentions-ui.mjs`로 키보드/마우스 추가, 이미지 로드·모델 일치, 공통 상세, 저장·복원, 편집 프롬프트와 모바일을 검사한다. 산출물은 `app/tests/output/spatial-product-mentions/`이다.

공통 `confirmDelete` / `DeleteButton`은 공간·제품·가구·설명 영역·프롬프트 삭제와 다른 화면의 템플릿·편집 요소·배경·첨부·연결·평가·시뮬레이션 기록·프로필·찜 제거에 적용한다. 기존 제안서·조감도 히스토리 및 장표 삭제 확인은 유지한다. 취소·Escape·바깥 클릭은 삭제하지 않으며, 승인 전에는 데이터를 바꾸지 않는다.

UI 검사는 별도 8992 포트 인증 서버에서 `node app/tests/spatial-room-input-ui.mjs`로 실행한다. 산출물은 `app/tests/output/spatial-room-input/`이다.

## 이미지·스펙 정합성과 초기 로딩

3D는 `services/spatial-renderer.js`에서 지연 로드한다. 웹 빌드는 `emptyOutDir: false`로 이전 배포의 해시가 붙은 JS/CSS 파일과 그 의존 파일을 함께 보존한다. 열어 둔 탭이 배포 뒤 처음 3D로 전환해도 그 탭이 시작한 버전의 모듈을 받는다. 운영 중 `dist`를 비우거나 이전 파일명을 최신 파일의 별칭으로 바꾸지 않는다. HTML은 기존 `Cache-Control: no-store`로 최신 진입 파일을 제공한다.

파일 누락·네트워크로 모듈 로드가 실패하면 한국어 안내와 **최신 화면으로 새로고침**을 표시한다. 2D로 전환하면 3D 오류를 지우며, WebGL·모델 실행 오류는 파일 배포 오류와 구분한다. 현재 문서 ID와 공간·제품 입력은 기존 서버 저장 및 문서별 브라우저 복원을 사용한다. PNG 캡처도 같은 로더를 사용한다.

`node app/tests/spatial-module-loading-ui.mjs`는 운영 계정과 분리된 인증 서버에서 실제 production 빌드 전부터 열어 둔 2D 탭을 유지한다. 재빌드 후 이전 JS/CSS의 파일·HTTP SHA-256 일치와 실제 3D 렌더를 검사한다. 새 화면에는 3D 모듈 404를 주입해 한국어 복구·모바일·문서 ID 및 변경한 제품 수량의 복원을 검증한다. 보고서와 캡처는 `app/tests/output/spatial-module-loading/`에 저장한다.

헤더는 라이브러리 응답 전부터 같은 위치에 유지하며, 스크롤바 공간을 예약한다. 라이브러리와 히스토리를 독립 로드한다. 지연 응답을 포함한 데스크톱·모바일 검증은 `node app/tests/spatial-fidelity-ui.mjs`로 실행하고 `output/spatial-fidelity/ui-report.json`에 코드·라이브러리 해시, 프레임별 좌표, 이동량과 GLB 재가져오기 결과를 남긴다.

제품 분류는 이름·모델·제품군을 사용하며 카탈로그 ID의 숫자를 제품 특성으로 읽지 않는다. 치수는 섹션/행 제목을 함께 읽어 축 순서와 단위를 정규화하고 포장·팔레트·화면·타공 규격을 제외한다. 동일 모델의 측정 행을 공유할 때는 원래 제품 ID와 근거를 남긴다. 별도로 확인한 제조사 자료는 `app/data/spatial/product-evidence.json`에서 관리한다.

원본 제품 이미지는 모델별 `referenceImage`, 촬영 방향과 적용 면은 `appearance`에 연결한다. 정면·상단 사진은 방향과 종횡비가 맞는 면에만 적용하며, 모니터는 스탠드를 제외한 화면 영역에 적용한다. 스펙 색상을 우선하며 화면 콘텐츠 색을 본체 색상으로 사용하지 않는다. 제조사 사진의 권리는 원저작자에게 있으며 자체 기하 레시피의 CC0 표기와 구분한다.

메시는 정규화 좌표에서 회전한 뒤 실치수로 스케일한다. `geometryTransform`은 바닥과 외곽을 맞추고 2D도 동일한 변환을 투영한다. 썸네일은 레시피·치수·색상·원본 이미지·형상 버전으로 구분한다. 구 버전 히스토리는 당시 자산과 렌더링 규칙을 보존한다.

스탠드 포함 세트에서 패널 치수만 확인되면 패널 크기를 `componentDimensions`로 따로 보존하고 전체 조립체는 설계 추정치로 표시한다. 패널의 가로/높이/깊이 비율을 조립체 안에서도 유지한다. 노트북은 닫힌 본체 형상이며 참고 사진의 열린 상태와 구분한다. 현재 전체 근거·누락·추정·구성 범위는 `node app/scripts/review_spatial_fidelity.mjs`가 만드는 `output/spatial-fidelity/audit.json`과 이미지/오브젝트 대조표 `review.html`에서 확인한다. 측정 행이 있다는 사실만으로 모델별 외형의 완전 일치를 뜻하지 않는다.

재사용 스킬: `.agents/skills/winmate-improve-spatial-fidelity/SKILL.md`.

스튜디오 UI는 앱 공통 `--accent`(밝은 테마 Samsung blue), `--surface`, `--surface-2`, `--ink`, `--muted`, `--line` 토큰을 사용한다. 자체 연두색 배경과 장식용 왼쪽 테두리를 두지 않으며, 선택·포커스는 앱 공통 블루 상태를 따른다. 사진·조감도 자체의 재질 색상과 UI 배경은 별도다. 밝은·어두운 테마에서 같은 토큰 체계를 사용한다.

추가 선택 가구는 `form.rooms[].furniture`에 자산 ID와 수량으로 저장한다. 아직 장면이 없는 스튜디오에서도 입력에 추가할 수 있으며 조감도 만들기에서 기본 가구와 함께 배치한다. 직접 추가된 가구의 `studioFurniture` 참조를 보존해 실행 취소·다시 실행과 재열기 때 입력 수량이 맞도록 한다. 선택 패널 검증은 독립 시험 서버(8994 포트)에서 `node app/tests/spatial-selection.mjs`와 `node app/tests/spatial-object-drawer-ui.mjs`로 수행한다.

조감도 홈·편집기·별도 portal 팝업은 동일한 블루 포인트를 사용한다. 공용 상세의 제품 배지·핵심 사양 칩·선택 모델·연결 표시·강조 태그도 공통 `--accent` / `--accent-soft`를 사용한다. SVG의 공간명·제품 번호·선택 강조·치수 주석은 블루·중성색으로 통일하고, 실제 식물·가구·제품의 재질 색상은 보존한다.

업종 템플릿의 홈·전체 목록 동작 이름은 **활용하기**로 통일한다. 생성된 개인 조감도 히스토리의 각 카드에는 **2D / 3D** 전환 버튼을 표시하며, 전환은 카드 미리보기만 바꾼다. 2D는 저장된 장면의 평면도, 3D는 해당 장면의 렌더를 사용한다. 없는 3D 썸네일은 화면에 들어온 카드부터 순차 생성하고, 손상된 썸네일도 실제 3D로 다시 렌더한다. 과거 장면은 저장 당시 오브젝트 버전을 읽는다. 생성 전 초안은 작성 중 표시를 제공한다. 히스토리는 썸네일을 눌러 열며 별도의 계속 입력하기·조감도 열기 버튼은 표시하지 않는다. 홈의 업종 템플릿 목록은 히스토리 조회가 성공하고 항목이 0개일 때만 전체 16개 업종의 표준 전체 맵을 표시한다. 로딩·오류·기존 히스토리에서는 이 목록을 표시하지 않으며, 스튜디오 만들기 오른쪽의 썸네일 포함 **업종별 템플릿 활용하기** 버튼에서 템플릿 팝업을 바로 연다. 히스토리는 데스크톱에서 4열로 표시하며, 좁은 화면에서는 2열·1열로 줄어든다.


업종 템플릿 팝업은 `template-catalog.js`가 생성한 `library.templateCatalog`를 사용한다. 실제 장면의 물리 제품 ID·수량과 공간·가구·제품 좌표를 비교하고, 제목·원본 장표 ID·크기만 바뀐 중복은 하나로 묶는다. 같은 업종에서 별도로 표시하는 항목은 제품 구성과 배치 서명이 모두 달라야 한다. 소형·표준·확장은 한 항목의 크기 선택으로 연결하며, 원본 680개 템플릿 ID와 저장 장면 참조는 보존한다. 현재 표시 항목은 199개이고, 전체 업종 목록은 16개 업종의 대표를 먼저 보여 준 뒤 각 업종의 다른 구성을 순서대로 표시한다. 카드에는 실제 포함 제품의 이름을 함께 표시한다.

팝업 목록은 18개씩 표시하며, 팝업 본문의 스크롤 끝에 접근하면 `IntersectionObserver`로 다음 18개를 자동 추가한다. 더 보기 버튼은 두지 않는다. 업종·범위·크기·검색어를 바꾸면 표시 범위와 본문 스크롤을 초기화하고, 마지막 항목에서는 추가 표시를 멈춘다. 기본 2D/3D 전환은 현재 표시 범위를 유지한다.

검증은 `npm --prefix app/web run test:spatial:catalog`로 실행한다. 실제 장면을 바탕으로 중복·전체 업종·크기 선택을 검사하고, 독립 서버에서 스크롤 전체 로딩·필터 초기화·빈 결과·실제 3D·저장된 제품과 좌표·모바일을 확인한다. 결과와 캡처는 `app/tests/output/spatial-template-catalog/`에 저장한다.

## 히스토리 페이지 로딩

히스토리는 `/api/spatial/history?page=1&page_size=8`로 현재 페이지 8개만 가져오고 렌더링한다. API는 `items`, `total`, `page`, `page_size`, `total_pages`를 반환하며 계정 경계·삭제 여부와 최신 수정순(같은 시각은 ID 역순)을 유지한다. SQLite 인덱스와 LIMIT/OFFSET으로 전체 장면 JSON을 디코딩하지 않는다. 레거시 템플릿 초안 복원도 조회한 페이지에 한정한다. 인수 없는 API 조회의 기본 크기는 12개이고 최대 48개이며, 웹 화면은 항상 8개를 요청한다.

이전·다음과 페이지 번호로 이동한다. 다음 페이지를 받는 동안 기존 카드와 전체 개수는 유지하고, 응답이 도착하면 해당 페이지만 교체한다. 늦거나 취소된 요청은 최신 목록을 덮어쓰지 않는다. 실패하면 기존 목록을 유지한 채 요청했던 페이지를 다시 불러올 수 있다. 마지막 페이지의 마지막 항목을 삭제하면 서버가 이전 유효 페이지로 보정한다.

검증: `app/.venv/bin/python -B -m unittest app.tests.test_spatial_pagination -v`, 별도 9006 포트 인증 서버에서 `node app/tests/spatial-pagination-ui.mjs`. 검증 범위·요청 크기·헤더 위치·시작/종료 해시는 `app/tests/output/spatial-pagination/`에 남긴다.

My Layout 저장 검증은 독립 8997 API / 5297 Vite에서 `node app/tests/spatial-my-layout.mjs` 및 `node app/tests/spatial-layout-my-ui.mjs`로 실행한다. 닫기 확인·취소·버리기, 히스토리 PUT 403을 가정한 개인 저장, 저장본 재열기, My 목록 표시, 편집 슬롯과 PPTX의 텍스트·도형·이미지를 검사한다.

홈 템플릿 버튼 제목은 넓은 화면에서 한 줄로 표시하고, 아래에 “업종에 맞는 공간 구성으로 시작하세요.” 설명을 둔다. 520px 이하에서는 제목을 자연스럽게 줄바꿈하고 설명은 숨긴다.


조감도 홈은 조감도 히스토리 위에 **Layout 히스토리**를 표시한다. My Layout에서 `my.kind === spatial`인 저장본을 최신 수정순으로 최대 4개까지 보여 주고, 전체 보기 팝업은 모든 저장본과 이름·업종·설명 검색을 제공한다. 썸네일은 저장한 1280×720 장표 HTML과 이미지·설명·연결선을 그대로 렌더링한다. 카드 선택은 홈에서 레이아웃 편집기를 열며, 전체 보기에서 열었다면 닫은 뒤 전체 목록으로 돌아온다.

홈 편집은 저장본의 `sourceScene`과 `assetRevision`을 사용하고, 저장 시 원래 `spatialHistoryId`와 템플릿 ID를 유지한다. 원본 히스토리가 삭제되어도 장면 스냅샷이 있는 저장본은 독립적으로 각도·설명을 수정할 수 있다. 이미지·설명 저장 후 목록·썸네일·수정순이 즉시 갱신되며, 저장하지 않은 변경에는 기존 닫기 확인을 적용한다. 슬롯 구조가 달라질 때의 새 My Layout 생성 규칙은 기존 저장 계약을 따른다.

검증은 `npm --prefix app/web run test:spatial:saved-layouts`로 실행한다. 빈 상태·최신 4개 제한·전체 목록·검색·구 버전 자산·삭제된 원본·같은 저장본 갱신·새 추출본 반영·재로딩·변경 버리기·모바일을 독립 서버에서 검사하며 결과는 `app/tests/output/spatial-saved-layouts/`에 남긴다.


Storyboard의 레이아웃 상세에서는 조감도 영역을 클릭하거나 **조감도 레이아웃 선택**을 눌러 저장한 추출 레이아웃을 고른다. `aerial` 이미지 칸, `L_SPATIAL_2D/3D`, 조감도 My Layout 및 조감도 명시 마커가 있는 레이아웃에만 제공한다. 일반 사진 칸은 기존 이미지 선택기를 유지한다. 선택기는 현재 업종·연결 제품·2D/3D 보기에 가까운 저장본을 먼저 보여 주고 이름·설명·업종 검색과 업종 필터를 제공한다.

저장본이 없으면 빈 상태를 안내하고 전체 16개 업종의 대표 템플릿을 보여 준다. 템플릿은 2D/3D 미리보기의 현재 보기로 실제 조감도와 편집 가능한 공간명을 생성해 My Layout에 저장한 뒤 적용한다. 선택한 추출본은 기존 Storyboard 장표의 UID와 순서를 유지하면서 장표 전체에 적용하므로 설명·연결선·이미지의 상대 위치를 보존한다. 이전 장표의 텍스트·이미지 오버라이드와 근거는 제거하고, 적용한 저장본의 출처를 기록한다.

사용자가 선택한 조감도는 `spatialLayout` 참조와 `retained` 상태로 유지하며 자동 맥락 채움이 저장본을 다시 쓰지 않는다. Storyboard에서 텍스트를 계속 편집할 수 있고, 새로고침과 PPTX 내보내기에서도 개별 텍스트·연결선 도형·조감도 이미지가 유지된다. 검증은 `npm --prefix app/web run test:spatial:storyboard`로 실행하며, 결과·캡처·확인용 PPTX는 `app/tests/output/spatial-storyboard/`에 저장한다. 공간 UI 시험 fixture는 인증·장면·My Layout DB를 별도로 사용한다.


화면 제품은 `spatial_display_geometry.py`에서 패널·베젤·스탠드·곡률을 나눠 물리 단위로 구성하고, `spatial_display_photo.mjs`에서 원본 사진의 제품 면을 정면 보정해 적용한다. 55형/75형, M8/M7처럼 다른 모델 정보가 연결되지 않게 상세 스펙과 제품 이미지도 같은 모델로 맞춘다. 베젤·구성품 크기가 추정인 경우 근거 수준을 별도로 남긴다. 모서리는 화면 폭 비율이 아닌 물리 단위를 사용하며, 제품 치수 표시는 소수 mm를 유지한다.

오브젝트 목록은 실제 팝업 스크롤 영역을 기준으로 40개씩 자동 추가한다. 검색·분류를 변경하면 첫 페이지와 맨 위로 돌아가며 선택 항목은 유지한다. 과거 조감도는 **제품 형상 업데이트**로 새 자산을 적용하고, 실행 취소 시 이전 라이브러리도 복원한다. 동일 크기 오브젝트의 좌표는 보존하며, 새 실측 크기에 충돌이 생기면 재배치가 필요함을 표시한다.

제품 사양을 고친 뒤에는 입력 SHA-256이 바뀌면 투영 SQLite도 자동 재생성한다. 원본 DB를 수정하지 않고 앱 상세, 실행 DB의 검토 데이터, Agent KB를 동기화한다. 검증은 `test_product_projection_refresh.py`, `test_product_specs.py`와 `spatial-signage-pagination-ui.mjs`를 사용하며 원본·수정 전·수정 후 비교는 `output/spatial-signage-review/review.html`에 저장한다.

### 레이아웃 추출: 선택 대상별 AI 설명과 실시간 각도

추출 버튼과 팝업 제목은 `레이아웃 추출`이다. 연결 대상은 공간·제품만 제공한다. 대상을 선택하면 중앙 버튼이 `{이름} 설명 추가`로 바뀌며 sparkle 아이콘과 AI 표시를 사용한다. 선택만으로 빈 설명 상자를 만들지 않는다. 설명 추가는 `/api/spatial/layout-description`에 저장본의 원본 장면과 정확한 targetId를 보내 실제 LLM 설명을 받는다. 공간은 실제 삼성 제품 목록·모델·수량, 제품은 설치 공간·등록 모델·주요 사양·특징과 오브젝트 치수를 함께 표시한다. 다른 모델의 제품군 사양표는 모델의 정확한 사양으로 쓰지 않는다. 가구나 미등록 참조는 거부하며 모델 오류를 규칙 문구로 대체하지 않는다. 오류와 진행 상태는 공통 팝업으로만 표시한다.

설명 상자는 내용 길이에 맞춰 자동 배치·연결하고, 긴 목록은 여러 상자로 나누어 누락과 잘림을 방지한다. 기존 설명을 선택한 상태에서는 Shift+클릭으로 공간·제품을 추가 연결할 수 있다. 사용자는 생성 후에도 내용·크기·위치를 편집할 수 있다. 저장 토스트는 `Layout 히스토리에 저장됐어요.`를 유지한다.

오른쪽 각도 슬라이더는 input 이벤트를 프레임별로 처리한다. 조작 중에는 PNG 인코딩 대신 WebGL 결과를 편집 전용 캔버스에 복사하며 공간명과 연결선 투영도 동시에 갱신한다. 포인터를 놓으면 최종 PNG와 카메라를 저장하고 하나의 실행 취소 단위를 만든다. 편집 전용 캔버스는 SVG·PPTX에 포함하지 않는다. 원래 각도 복원·실행 취소·저장 후 재열기도 유지한다.

검증: `app.tests.test_spatial_descriptions`, `app.tests.test_spatial`, `spatial-layout.mjs`, `spatial-my-layout.mjs`, `spatial-layout-ui.mjs`, `spatial-layout-my-ui.mjs`, 웹 빌드. 실제 LLM 공간·제품 응답은 `output/spatial-layout-description-20261020/live-ai.json`, 브라우저·내보내기 결과는 `app/tests/output/spatial-layout/`와 `app/tests/output/spatial-layout-my/`에 남긴다. 각 브라우저 시험은 별도 API·인증·장면·레이아웃 DB를 사용한다.
