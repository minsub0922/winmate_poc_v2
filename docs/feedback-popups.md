# 작업 오류·진행 알림

`FeedbackPopup`과 `NotificationHost`가 오류·진행·완료 메시지를 공통으로 표시한다. 팝업은 body의 fixed 레이어에만 렌더링되며 본문 높이를 바꾸지 않는다. 너비는 최대 360px이고 모바일 화면 안에 맞춘다. 오류는 닫을 때까지 유지하며 재시도·취소 버튼을 제공할 수 있다. 닫은 진행 팝업은 같은 작업의 업데이트로 다시 열리지 않는다. 기존 `toast()`도 이 레이어를 사용한다.

| 점검 영역 | 반영 |
| --- | --- |
| 조감도 입력·편집·히스토리·3D 로더·미리보기·카메라 | 오류·진행·완료·재생성 안내를 공통 팝업으로 이동 |
| 라이브러리·Best Scenario·레이아웃 검색 | AI 검색 오류·진행·재시도를 공통 팝업으로 이동 |
| 제안서·첨부·Storyboard·AI 채우기 | 첨부 읽기, 작업 상태, 실패, 재시도, 취소를 공통 팝업으로 이동 |
| 레이아웃 프롬프트·고객 맥락 채우기·요약 | 오류·진행을 팝업으로 이동하고 저장된 장표는 유지 |
| 제안서 검토·리포트 미리보기 | 실행 단계·실패·중단·미리보기 오류를 팝업으로 이동 |
| 시뮬레이션·추천 답변·스킬 | 대화/총평/추천 오류와 진행, 실행 로그를 팝업으로 이동; 실제 답변·분석 결과는 결과 화면에 유지 |
| 제안서 히스토리·공유 복원·앱 초기화 | 복원·초기화 오류와 재시도를 팝업으로 이동 |
| 로그인·공유 권한/충돌·파일 가져오기/내보내기·이미지 선택·삭제 확인 | 이미 dialog/drawer/popover 안에서만 표시되므로 해당 팝업 유지 |

`AgentJobControl`의 로그·질문·재시도·취소·결과 적용 버튼도 공통 팝업 안에 있다. 문서 평가 결과의 보완점, 필수 입력값, 이미지 자리의 누락 상태처럼 작업 결과나 입력 자체를 설명하는 요소는 오류 로그와 구분한다.

## 공간 프롬프트 502

`/api/spatial/edit`의 JSON schema에 수백 개 제품·오브젝트 ID를 enum으로 넣으면 공급자가 HTTP 400으로 거부했고 API에서는 502가 됐다. 식별자 필드는 STRING으로 선언하고 전체 후보·참조를 프롬프트에 전달한다. 반환된 ID·제품·공간·수량·좌표는 서버에서 기존 장면과 동결 자산 버전 기준으로 검증한다. 등록되지 않은 ID나 잘못된 수치는 계속 거부한다. 실패를 규칙 결과로 대체하지 않는다.

## 클릭과 드래그

2D·3D 모두 포인터가 5px를 넘게 움직인 제스처는 드래그로 처리한다. 이동 후 또는 원래 위치로 돌아온 후에는 상세를 열지 않는다. 기존 상세도 드래그 중 숨기고 종료 시 선택을 해제한다. 클릭만 상세를 오브젝트 옆에 표시한다. 상세 너비는 360px, 제품 hover는 420px이며 화면 가장자리에서는 위치를 조정한다.

## 검증

`app/.venv/bin/python -B -m unittest app.tests.test_spatial_edit -v`는 schema 크기, 정확한 ID 참조, 잘못된 모델 응답 거부를 검증한다. 별도 8998 인증 fixture를 사용한 `node app/tests/feedback-popups-ui.mjs`는 실제 Gemini 편집 성공, 502 주입 시 버블 보존·본문 좌표 불변, 2D/3D 드래그와 클릭, 두 검색 화면, 시뮬레이션·작업 로그 팝업, 모바일을 검사한다. 결과는 `app/tests/output/feedback-popups/`에 저장한다.
