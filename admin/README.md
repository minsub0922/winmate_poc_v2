# Winmate Admin

별도 React 앱과 FastAPI 관리 API를 같은 서버의 `/admin/`에 연결한다. 일반 Winmate 앱은 `/`에서 그대로 제공한다. 관리자 소스·테스트·실행 설정은 이 `admin/` 디렉터리에서 버전 관리한다. DB·인증·업로드·로그·선택 의존성이 있는 `admin/runtime/`과 재생성 가능한 `admin/web/dist/`는 Git에서 제외한다.

## 실행

저장소 루트에서 실행한다. 기존 `app/.venv`와 `app/web/node_modules`가 준비되어 있어야 한다.

```sh
./admin/start.sh
```

기본 포트는 기존 앱과 같은 `8788`이다. 하나의 프로세스가 `/`와 `/admin/`을 모두 제공한다. 저장소에 포함된 `admin/.enabled`에 따라 일반 `./start.sh`도 같은 결합 서버를 실행한다. 로그인 후 다른 포트로 이동하지 않는다. 실행 중인 이전 일반 앱 서버는 재시작해야 새 경로를 제공한다. 기존 서버를 유지하며 별도로 확인할 때만 다른 포트를 지정한다.

```sh
WINMATE_API_PORT=8794 ./admin/start.sh
```

일반 앱의 `admin` 로그인 세션을 공유한다. 관리자 API는 일반 앱 인증이 꺼진 환경에서도 유효한 관리자 세션을 요구한다. 다른 계정·비로그인 접근·다른 출처의 쓰기 요청은 거절한다. 비밀번호를 바꾸거나 별도 인증 우회를 만들지 않는다.

`admin/start.sh`는 관리자 프런트만 빌드하고 PDF·이미지 판독기를 `admin/runtime/python`에 설치한다. 기존 앱의 패키지 파일과 Python 환경은 수정하지 않는다. 이미 준비된 기존 앱 데이터·웹 빌드를 사용한다. 일반 `app/start.sh`에는 `admin/.enabled`와 관리자 파일이 모두 있을 때 결합 진입점을 선택하는 조건이 있다. 이 표시 파일도 버전 관리하므로 새 체크아웃에서 일반 시작 스크립트를 실행하면 관리자 의존성과 화면을 준비하고 `/admin/`을 제공한다. 관리자 없이 실행하려면 표시 파일을 제거하거나 기존 `app.api.main:app` 진입점을 직접 사용한다.

## 화면과 기능

- **관리 개요**: 실제 자산 건수, 주요 원본 상태, AI 최신성 점검, DB 최신화, 최근 작업.
- **데이터 소스**: 삼성 B2B, e-카탈로그, 솔루션·도입사례, 이미지, 제안서·평가 자료, 공간 라이브러리, 추가 자료. URL 소스 연결, 사용 중지, 점검 주기, 원문 인용과 AI 판단 근거.
- **에셋 라이브러리**: 제품·사진·레이아웃·시나리오·카탈로그·문서·공간 에셋·정적 파일과 pack. 검색, 유형·출처·상태 필터, 페이지 탐색, 출처·해시·시각 확인, 메모·태그, 일괄 보관·복원, JSON 내보내기.
- **에셋 추가**: 파일 또는 공개 HTTPS URL을 보존하고 서버에 설정한 실제 LLM으로 구조화한다. 추출한 제품·솔루션·사례도 각각의 에셋 행으로 등록하여 유형 필터와 모델 검색에서 찾을 수 있다. 각 행에는 부모 원본과 인용 근거가 연결되며 재분석해도 ID를 이름·모델에 따라 보존한다. PDF, PPTX, DOCX, UTF-8 텍스트·Markdown·CSV·JSON·HTML, PNG·JPEG·WebP. 파일당 25MB, 한 번에 10개. 원문 합계 35만 자 이하. PDF는 쪽, PPTX는 장별 인용을 보존하며 제품명·모델과 인용을 대조한다. 스캔 PDF는 성공으로 가장하지 않고 텍스트 PDF 또는 이미지 입력을 안내한다.
- **작업 내역**: 한 개의 작업 큐, 중복 요청 병합, 진행률, 취소, 재시도, 오류, 수집 로그, 실제 반영·누락 범위. 새로고침 후에도 기록을 조회할 수 있다. 재시작된 미완료 작업은 `interrupted`로 표시한다.
- **시스템**: 원본·앱·관리자 SQLite 테이블 조회, 무결성/FK 검사, 상세 pack 연결과 Agent KB 입력 해시 검증, DB 백업, 릴리스 변경표, 이전 버전 복구, 관리 활동 이력, 선택적 자동 점검.

세부 내용과 원문·설정·버전 비교는 팝업으로 연다. 데스크톱·태블릿·모바일에서 동작하며 팝업은 Escape, 초점 순환·복원을 지원한다.

## 데이터 범위

현재 이 앱은 **관리자 격리 DB**를 갱신한다. 기존 production 제품 SQLite, 앱 JSON, Agent KB, 이미지 pack을 덮어쓰지 않는다. `/`에 표시되는 기존 Winmate 앱도 기존 데이터를 사용한다. 각 릴리스에 `sync.admin_database=true`, `production_database=false`, `production_agent_kb=false`를 기록하고 화면에도 동일하게 표시한다. 관리 DB의 자료와 전체 JSON을 내려받을 수 있다.

관리자 소스를 배포에 포함해도 이 데이터 반영 경계는 유지한다. production의 제품 목록·추천·PPTX까지 연결할 때는 별도 릴리스 파이프라인에서 앱 projection·Agent KB·이미지 pack 주소를 같은 버전으로 반영하고 기존 참조를 검증해야 한다. 이 관리자 앱은 그 통합을 완료했다고 표시하지 않는다.

최초 실행 시 현재 로컬 입력과 정본 KB를 색인한다. 개별 항목과 물리 파일을 함께 관리하므로 전체 에셋 건수는 제품 개수나 원본 파일 개수와 다르다. 자산 생성·수집 기록이 없는 자료의 날짜는 `기록 없음`으로 표시한다. 파일 수정일은 원본 수집일의 대체값으로 사용하지 않는다.

### 원본별 갱신

**Samsung Business**: 현재 탐색 메뉴와 기존 분류의 합집합을 수집한다. 원래 수집기를 작업 폴더용으로 변환하여 실행하며 원본 수집기 자체는 수정하지 않는다. 목록·필터 전체 페이지, 옵션별 사양, PDP 특장점을 수집한다. 빈 사양·차단·페이지 누락·파서 오류가 있으면 반영하지 않는다. AI가 변경과 누락 후보를 검토하고 기존 제품 ID와 관리자 메모를 유지하여 관리 DB에 반영한다. 사라진 항목은 검토 후보이며 물리 삭제하지 않는다.

**e-Catalog**: 현재 공개 목록과 기존 권의 합집합을 확인한다. `b2b:272`와 `b2c:272`처럼 경로와 Dir를 함께 식별한다. 점검 시 목록뿐 아니라 각 권의 실제 제목·전체 쪽 수·첫 쪽 해시·HTTP 개정 정보를 확인하고 이전 원문과 비교한다. 팝업에 새로 발견한 권과 개정 후보를 표시하며, 신규 발견일과 실제 업로드일을 혼동하지 않는다. 기존 ID를 새 순번으로 재할당하지 않는다. 최신화에서는 모든 쪽을 다시 조회하고 쪽별 원문에서 제품·모델·인용을 추출한다. 중복 엔터티는 동일 문서·모델·이름 기준으로 합친다. 이미지 전용 쪽, 사진 crop·PDF 개정 비교·영상은 미검토 범위로 명시한다. 텍스트 전체 수집을 전체 시각 자료 검증으로 표시하지 않는다.

**솔루션·사례**: 현재 등록된 공식 원문 URL을 각각 조회하고 구조화한다. 연결된 모든 영상·PDF·신규 목록 페이지를 수집했다고 표시하지 않는다. 추가 URL 소스는 해당 페이지의 공개 본문을 대상으로 한다.

**로컬 자료**: 기존 원본·템플릿·배경·공간 라이브러리를 재색인한다. 이미 새 원문으로 갱신한 소스와 관리자 메모·보관 상태는 이전 저장소 값으로 덮어쓰지 않는다.

### 보존과 복구

모든 갱신은 `runtime/releases/<job>-<source>/`에서 수행한다. 원문, 수집 인벤토리, 변경표, 반영 데이터, 소스별 복구본을 보존한다. SQLite 반영과 FTS 갱신·버전 기록은 하나의 `BEGIN IMMEDIATE` 트랜잭션으로 처리한다. 수집 확인 시각이나 모델 사용량만 달라진 행은 사실 내용 변경과 구분한다.

복구는 소스의 활성 릴리스에만 허용한다. 반영 이후 메모·태그·내용·상태·에셋 구성이 바뀌면 복구를 중단하여 뒤의 작업을 보존한다. 여러 소스를 갱신하다 취소한 경우 이미 완료한 소스는 유지하고 그 결과를 작업에 남긴다.

자동 점검은 기본적으로 꺼져 있다. 화면에서 켜면 소스별 주기에 맞춰 실제 AI 점검을 수행하며, DB 갱신은 직접 실행한다. AI 실패·인용 불일치·접속 실패를 규칙 기반 성공 응답으로 바꾸지 않는다.

## 경로와 설정

```text
admin/server.py        /admin API·접근 제어·기존 앱과 ASGI 합성
admin/store.py         관리 SQLite·색인·작업·활동 기록
admin/inventory.py     기존 자산 등록·진단
admin/engine.py        안전한 원문 조회·문서 판독·실제 LLM·인용 검증
admin/refresh.py       원본별 갱신·변경 계획·트랜잭션·복구
admin/collect.mjs      삼성 수집기 staging 어댑터
admin/service.py       작업 큐·진행·재시도·자동 점검
admin/web/src/         독립 React 관리자 앱
admin/runtime/         격리 DB·추가 원본·릴리스·백업·선택적 의존성
```

`WINMATE_ADMIN_DATA`로 관리자 데이터 경로를 바꿀 수 있다. Python 선택 의존성은 계속 `admin/runtime/python`에 둔다. AI는 기존 서버의 `WINMATE_LLM_PROVIDER`와 `.env` 로딩 규칙을 공유한다. 기본 사내 모델은 `INTERNAL_LLM_API_KEY`, `INTERNAL_LLM_MODEL`, `INTERNAL_LLM_BASE_URL`을 사용하며, Gemini를 선택하면 `GEMINI_API_KEY`, `GEMINI_MODEL`을 사용한다. 인증키는 브라우저·DB·로그에 저장하지 않는다. 공개 HTTPS 조회는 DNS 공인 주소 검사·검사한 IP 고정·리디렉션 재검사·용량/전체 시간 제한을 적용한다.

## 사용자 관리 · 운영 추적

`/admin/users`에서 사용자를 추가하고 `/admin/tracing`에서 운영 대시보드를 연다. 기존 기본 관리자의 비밀번호와 유효한 로그인은 유지하며, 추가 계정은 별도 운영 DB에 보관한다.

- **일괄 생성**: `sales01, sales02, sales03`처럼 쉼표 또는 줄바꿈으로 1~50개 아이디를 입력한다. 자동 생성 또는 직접 입력한 **초기 비밀번호 하나**를 전체 배치에 동일하게 배정한다. 생성 결과에서 한 번 확인·복사할 수 있으며 평문 비밀번호는 DB·행동 로그·trace에 남기지 않는다. 기존 로그인 정책과 동일하게 12자 이상을 사용한다.
- **계정 관리**: 표시 이름·메모·관리자/사용자 권한·사용 중지·비밀번호 재설정. 중지와 재설정은 기존 세션을 무효화한다. 마지막 관리자를 중지하거나 권한 해제할 수 없다. 기본 관리자와 일반 계정을 함께 재설정하는 경우에는 기본 관리자를 별도로 선택하도록 안내한다.
- **기록 격리**: 새 사용자의 localStorage와 IndexedDB를 계정별로 구분한다. 기존 기본 관리자는 원래 키를 유지하여 기존 문서·사진·My 템플릿을 보존한다. 다른 계정으로 바뀐 탭의 요청은 409로 차단하고 다시 불러온다. 비관리자는 다른 사람의 AI 작업·결과·취소 API를 이용할 수 없다.
- **전체 히스토리 보관**: 제안서·검토·시뮬레이션·브라우저 작업·서버 작업·고객 프로필·찜·My 템플릿의 저장 내용과 이전 버전을 사용자별로 보관한다. 기존 브라우저 기록은 해당 계정으로 앱/관리자를 열 때 수집한다. 오래된 브라우저의 일부 목록으로 다른 기기의 문서를 일괄 제거하지 않으며, 명시적으로 제거한 ID만 이전 기록으로 표시한다. 서버 작업 감사 이력은 클라이언트가 덮어쓸 수 없다.
- **화면 활동**: 화면 진입·이탈 시각과 체류 시간, 버튼·링크·탭·팝업·변경 동작을 수집한다. 비밀번호 입력값과 일반 폼 입력 내용·키 입력은 행동 로그로 남기지 않는다. 계정별 브라우저 outbox로 오프라인·새로고침 후 전송을 재시도하며 이벤트 ID로 중복 집계를 방지한다.
- **실패 추적**: HTTP 오류, 브라우저 오류/미처리 Promise, 백그라운드 작업 실패, 모델 실패를 사용자·화면·기능·코드·trace ID로 조회한다. 같은 trace에서 요청·작업·실제 LLM 호출의 부모 관계와 시간, 오류 메시지·stack을 팝업으로 확인한다. 로그인 실패에서 미등록 아이디는 원문을 보관하지 않고 지문으로 구분한다.
- **토큰 추적**: 실제 서버 LLM 응답의 입력·출력·추론·캐시 입력·전체 토큰을 요청별로 기록한다. 전체 토큰은 API가 보고한 값이며 부분 필드를 임의로 더하지 않는다. JSON 재시도는 각 실제 호출로, SSE 사용량은 마지막 누적 값 한 번으로 집계한다. 응답 캐시 재사용은 새 토큰 사용으로 집계하지 않는다. 실패·취소 등 사용량이 보고되지 않은 호출은 `미보고`로 표시한다.
- **대시보드**: 오늘·7/30/90일·직접 기간, 사용자·기능·모델 필터, 시간/일별 사용량 그래프, 기능별 분포, 방문 횟수와 최초/최근 시각, 활동·실패·LLM 요청 목록, 로그 JSON 내보내기를 제공한다. 시간대는 한국시간이며 기록이 없는 구간은 0으로 표시한다. 과거의 미수집 화면 활동이나 토큰을 생성하지 않는다.

운영 DB는 `admin/runtime/operations.sqlite`다. 계정 해시를 일반 에셋 JSON/테이블 탐색에 섞지 않는다. 시스템의 **DB 백업 → 사용자 · 추적 DB**로 별도 SQLite 사본을 만들 수 있다. 기본 관리자의 기존 인증 파일은 기존 `app/data/runtime/auth` 경계를 유지한다. 공통 앱의 인증·provider·작업·브라우저 저장 경계에는 선택적 연결 훅이 있으며, 실제 사용자 관리·운영 저장·대시보드는 결합 서버 `admin.server:app`에서 활성화된다. Git에서 제외한 운영 DB와 업로드·백업은 배포 환경의 영속 저장소에 별도로 보관한다. 관리자 없이 `app.api.main:app`을 직접 실행하면 기존 단일 계정과 비활성 추적 상태로 동작한다.

운영 테스트:

```sh
app/.venv/bin/python -B -m pytest admin/tests/test_admin.py admin/tests/test_operations.py app/tests/test_auth.py app/tests/test_provider_strict.py -q
WINMATE_ADMIN_TEST_URL=http://127.0.0.1:8796 WINMATE_ADMIN_LIVE=1 node admin/tests/operations-ui.mjs
```

브라우저 테스트는 별도의 `WINMATE_ADMIN_DATA`, `WINMATE_AUTH_DIR`, 사용자 저장 경로를 사용하는 격리 서버에서 실행한다. `WINMATE_ADMIN_WEB_DIST`와 `WINMATE_WEB_DIST`로 시험 빌드를 지정할 수 있다. 실제 JSON/SSE 모델 사용량과 계정 격리·오프라인 전송 결과는 `runtime/evidence/operations/`에 있다.

별도 구버전 비교 검사인 `app/tests/test_stage1_api.py`에는 현재 공개 bootstrap 정책과 검토된 제품 상세 overlay를 과거 동결본과 비교하는 기대값 차이가 있다. 해당 다섯 비교 항목은 이번 사용자·추적 검증 결과에 포함하지 않았고 앱의 현재 데이터 정책을 되돌리지 않았다.

### 에셋 관리 기존 검증

```sh
node admin/build.mjs
app/.venv/bin/python -B -m pytest admin/tests/test_admin.py -q
node admin/tests/collector.mjs
```

브라우저·실모델 검사는 production과 다른 인증·사용자 자료·관리 데이터 경로의 격리 서버에서 실행한다. `tests/ui.mjs`와 `tests/live.py`의 테스트 계정은 이 검사용 서버에만 생성하는 합성 계정이다. 실제 사용자 비밀번호를 읽거나 재설정하지 않는다. `tests/live.py`는 서버에 설정한 실제 LLM을 호출하며 사용량이 발생한다.

```sh
WINMATE_ADMIN_TEST_URL=http://127.0.0.1:8794 node admin/tests/ui.mjs
WINMATE_ADMIN_TEST_URL=http://127.0.0.1:8794 app/.venv/bin/python -B admin/tests/live.py
```

검증 결과와 화면은 `runtime/evidence/`에 보관한다. `live-results.json`은 카탈로그 목록 최신성 판단, 합성 문서 분석, 공개 페이지의 실제 갱신·관리 DB 반영, 버전 복구, DB 진단 결과이다. 삼성 전체 재수집과 모든 카탈로그 전권의 실모델 분석을 완료한 결과는 아니다.

### 에셋 이미지 · 전체 리소스

에셋 상세의 첫 화면에 대표 이미지와 관련 사진을 표시한다. **전체 리소스**에서는 이미지·장표·문서·영상·3D 파일·원본 데이터·출처 링크를 종류와 그룹, 파일명으로 찾는다. 선택한 리소스는 팝업 안에서 확대하며 원본 크기 전환, 개별 다운로드, 크기와 연결 근거, 출처 페이지 열기를 제공한다. 목록으로 돌아오면 필터와 페이지를 유지한다.

- 제품의 `img` PID, 썸네일·갤러리 pack 주소, 정확한 제품 ID로 연결된 이미지 라이브러리, 검토된 제품 상세의 첨부·카탈로그 연결을 읽는다. 비슷한 모델명을 근거로 다른 제품의 이미지를 연결하지 않는다.
- 솔루션·도입사례는 미디어 인덱스의 대표 사진·갤러리·원본 주소를 해석한다. 카탈로그는 등록된 전체 쪽과 연결된 추출 이미지·PDF 주소를 보여준다. 외부 파일을 서버가 임의로 수집하거나 접속 성공으로 표시하지 않는다.
- JSON 이미지 묶음은 실제 슬롯 번호를 보존하고, 한 장씩 디코딩·다운로드한다. 빈 슬롯·삭제된 파일은 확인 필요로 표시한다. 실제 앱의 `/img/lib`, 배경, 동결 이미지 경로 우선순위를 따른다.
- 레이아웃·시나리오의 장표 HTML, `data-fill` 사진과 CSS 배경, 시나리오 배경 풀을 연결한다. 장표 미리보기는 스크립트·탐색을 막은 sandbox에서 표시한다. 공간 에셋은 실제 썸네일·형상 근거 이미지·연결 제품·참조 장표를 표시한다.
- 업로드한 이미지·문서는 원본을 제공한다. PDF의 모든 쪽·삽입 이미지·첨부파일과 PPTX/DOCX/XLSX의 media·embeddings 항목도 각각 조회한다. TIFF 등은 보기용 형식으로 변환하고 원본 다운로드는 보존한다. 앱이 직접 미리볼 수 없는 파일은 원본 다운로드로 확인한다.

리소스 URL은 선택한 에셋의 연결 목록에서만 만들어진다. 임의 경로 요청, 사용자·인증·추적 DB, 비밀 파일과 허용 폴더 밖 symlink는 제공하지 않는다. HTML·코드 파일은 첨부 다운로드 또는 텍스트로 제공하고, SVG에는 실행을 차단하는 CSP를 적용한다. 모든 API와 원본은 기존 관리자 인증을 요구한다. 원본 DB나 동결 pack을 변경하지 않으며 구현은 `admin/`, 실행 데이터는 Git 제외된 `admin/runtime/`에 보관한다.

```sh
app/.venv/bin/python -B -m pytest admin/tests/test_resources.py -q
app/.venv/bin/python -B admin/tests/resource_fixtures.py admin/runtime/resources-e2e
WINMATE_ADMIN_TEST_URL=http://127.0.0.1:8796 node admin/tests/resources-ui.mjs
```

브라우저 검사는 위 경로를 `WINMATE_ADMIN_DATA`로 지정한 별도 서버와 합성 관리자 계정을 사용한다. 결과와 데스크톱·모바일 화면은 `runtime/evidence/resources/`에 보관한다.
