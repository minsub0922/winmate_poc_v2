# Scenario Composer — 샘플 버티컬 시나리오 기반 제안서 자동 구성

성능 제한 모델(Gemini flash-lite)로 샘플 버티컬 시나리오(프런티어 모델이 만든 완성 덱) 수준의 Storyboard를 만드는 PoC다.
모델이 흐름 · 장표 · 사진을 **창작하지 않고**, 미리 분리해 둔 케이스(샘플 버티컬 시나리오의 파트 모듈 · 장 · 사진 칸) 중에서 **판단 · 선택**만 하게 한다.

```
고객 입력 ─▶ A. 상황 판정 ─▶ B. 파트 추천 ─▶ (사람이 파트를 고르고 고침) ─▶ C. 레이아웃 ─▶ D. 문구 ─▶ E. 사진
             업종·요구유형    상황 순위 1위 샘플 버티컬 시나리오   출처 모듈(src)을 기억          모듈의 장을   장별 원문을   칸마다 '원래 덱의
             (+2순위)·전략    = 뼈대, Gemini는 뺄 파트     새 파트는 가장 가까운 모듈     이 고객에 맞게 이 고객으로   사진' 설명 → 후보 5
             ·결말(enum)      (≤2)·빌릴 파트(≤2) 판단     을 Gemini가 선택              변형           옮겨 쓰기     → Gemini 선택
                              → 파트 이름
```

| 단계 | Gemini가 하는 일 | 코드가 보장하는 것 |
|---|---|---|
| A 상황 판정 | 업종 16 · 요구 유형 7(+애매하면 2순위) · 전략 7 · 결말 8 중 고르기, 공간 · 요구 구 추출 | enum 스키마, 고객이 정한 업종 고정 |
| B 파트 추천 | 뺄 파트(≤2) · 빌릴 파트(≤2, 2·3순위 시나리오에서) 결정, 파트 이름 · 항목 다시 쓰기 | 뼈대 = 상황 순위 1위(요구 유형 3 · 전략 2 · 결말 1 · 업종 1 · BM25 4 · 프런티어 덱 +1, 85개 leave-one-out으로 맞춘 가중치), 요청 분량("10장")과 먼 덱 감점, 뼈대 순서 유지 · 표지 앞 · 마무리 뒤 |
| C 레이아웃 | (출처 없는 파트만) 모듈 4개 중 선택 | 폐기 → 사진 버전, 다른 업종 변형 → 이 업종 변형, 고르지 않은 솔루션 전용 장 → 고른 솔루션의 같은 역할, 제품 그리드 → 제품 수만큼(같은 제품을 되풀이하는 둘째 그리드 제거), 고르지 않은 제품 장 제거, 덱 내 중복 → 뒤 장이 쓸 레이아웃은 피해서 가장 가까운 미사용 장 |
| D 문구 | 파트 단위로 원문(ref)을 이 고객 내용으로 옮겨 쓰기 | 칸 길이 상한, 다른 고객 이름 · 근거 없는 수치 · 레이아웃 견본의 작성 안내문("…사진으로 교체", "자리표시") 검사 → 1회 수정 요청 → 그래도 남으면 이름은 고객명, 수치는 [00], 안내문은 삭제 |
| E 사진 | 칸마다 후보 5개 중 선택(빈 칸 없이) | 칸 종류(제품 컷 · 장면 · 화면 · 구성도) 필터, 다른 업종 장소 · 다른 업종에서 찍은 사진 제외, '고객 자기 공간' 칸은 그 업종 사진만, 타사 간판 · 로고 · 외관은 사례 파트에서만(고객 자신의 것은 허용), 표지 · 마무리는 다른 회사 현장 사진 금지, 제품 칸은 그 제품만, 덱 내 중복 회피(제품 컷만 재사용 허용) |

## 실험 결과 (2026-11-11, Gemini 3.1 flash-lite 구성 · 3.1 Pro 블라인드 심사)

정답 샘플 버티컬 시나리오를 숨기고(자기 자신은 모든 단계에서 제외) 그 고객 입력으로 다시 만든 뒤 정답과 비교. 현재 앱 Layout Agent도
같은 조건(앱 KB의 샘플 버티컬 시나리오 목록에서 정답 덱을 숨김 — `eval/baseline.py --holdout`)으로 돌렸다.

- r1: 사진 브랜드 필터 · 중복 연쇄 수정. Gemini가 후보 5개 중 뼈대를 고르게 했더니 같은 업종 템플릿(버티컬)을 9/13번 골라 상황(교체 · 경쟁 등)이 다른 흐름이 됨.
- r2: 상황 우선 가중치(85개 leave-one-out로 추정) · 후보 3개 · '1순위 기본' 지시 → 교체(renew) 덱 유사도 0.31 → 0.73~0.83. 그래도 같은 업종 쏠림이 남음.
- r3: 뼈대를 상황 1순위로 고정(Gemini는 빼기 · 빌리기 · 문구 · 사진만), 요청 분량 반영, 빈 사진 칸 없앰, 표지 · 마무리 중립 사진, 견본 안내문 차단.
- 남은 차이(심사 사유): 고객 고유 요구(TCO 비교, 구독/설치 비교, 확산 물량, 분량)를 다루는 장이 없음 · 업종이 다른 뼈대의 장 내용 잔재 · 세부 업종이 다른 사진(마트에 백화점, 사이니지 제안에 에어컨) · 사진 설명의 타사 이름 · 근거 없는 수치를 [00]으로 비워 둠(정답 덱은 가상의 수치를 씀).
- 덱 1개 ≈ Gemini 호출 25회, 입력 약 6만 · 출력 약 1.8만 토큰(flash-lite), 약 2분.

## 데이터 (library.json)

`python -m composer.library` — 앱 KB(`app/data/runtime/kb`)와 샘플 버티컬 시나리오 내보내기(`scripts/export_library.mjs`)로 만든다.

- 시나리오 85개(bs01–22 · 버티컬 40 · 표준 20 · 어카운트 3) → 파트 모듈 624개 → 장 1,356개(채운 문구 · 사진 그대로)
  - 위 수치와 실험 결과는 2026-11-11 기준. 2026-11-12부터 앱 시나리오는 107개(bs01–20 · 버티컬 40 · 업종별 표준 44 `bs_std_<버티컬>` · 어카운트 3) — bs21 · bs22 · 예전 표준 20종은 삭제됨. `library.json`은 지금 KB로 다시 만들고, `run.sh` · `eval/report.py`의 평가 묶음은 삭제된 덱을 빼고 예전 표준 5개를 같은 업종의 새 표준 덱으로 바꿈.
- 레이아웃 838개: 칸(data-tb 역할 · 원문 · 글자 크기, data-img 종류 · 힌트 · 크기 · fit · 샘플 사진), 업종 변형 패밀리, 고정 문구
- 사진 3,702장: 도입사례 · 솔루션 미디어(설명 · 종류), 사진 레이아웃 · 채움 묶음 · 제품 갤러리 · 제품 라이브러리.
  업종은 출처(사례 업종 · 파일 접두사 · 시나리오)로, 보이는 장소는 캡션의 장소 단어로(출처명 제거 후) 따로 기록한다.

## 실행

```bash
cd poc/test/scenario_composer
python -m composer.library                       # 라이브러리 (KB가 바뀌면 다시)
bash scripts/run.sh smoke                        # 12개 덱 (키: poc/.env 의 GEMINI_API_KEY — 출력하지 않음)
bash scripts/run.sh composer r4 rank base        # Layout Agent 와 같은 40개 덱 재구성 (all = 85개)
bash scripts/run.sh baseline                     # 현재 Layout Agent, 정답 덱 숨김 (runs/base-ho)
bash scripts/run.sh judge r4 base-ho             # 1:1 블라인드 심사 (상대 생략 시 정답 대비) — Pro 호출이 비싸니 덱 수를 줄여서
bash scripts/run.sh report gold,base-ho,r4       # 같은 덱 기준 비교표 (지표는 저장된 덱으로 다시 계산 — 호출 없음)
python -m eval.render runs/r4/bs01.json          # 장표 HTML (팩 이미지 해석) · --gold 로 정답 덱
```

앱에서는 `kind: compose` 작업(`app/api/poc/adapters/compose.py`)으로 쓴다 — `step: parts`(파트 추천) → 사람이 고침 → `step: layouts`(장표 완성).
빈 Storyboard의 '자동 구성'은 파트 추천을, 파트가 있으면 '장표 자동 완성 · 파트 N개' 버튼이 장표 완성을 부른다.
라이브러리는 `app/data/runtime/composer`에 만들어진다(poc/ 아래에는 쓰지 않음). `WM_COMPOSER_BASE=llm` 이면 뼈대를 Gemini가 상위 3개 중에서 고른다.
